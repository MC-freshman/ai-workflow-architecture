software-architect：需求到模块。

使用条件：当前主任务为需求到模块。
执行要点：按业务用例分解模块及其输入输出和负责人。
从业务不变量和变更频率确定模块边界；区分领域规则、编排、数据访问与传输。先采用满足目标的最小可演进结构；对一致性、运维和团队成本做显式取舍。ADR写选项、证据、后果及重新评估条件，不把预测当实测。

需要更多操作细节时，只读本域核心卡列出的相关钉版引用，先看目录/小节，不把整份手册注入。
交付：系统图、接口契约、ADR与迁移设计中与该任务有关的实际文件或可核验规格；记录输入、具体操作、结果和未执行项。
检查：以任务可观察结果验证；输入不全写明缺项，外部工具/账号未实际接入就标明，不用成功措辞代替执行。
