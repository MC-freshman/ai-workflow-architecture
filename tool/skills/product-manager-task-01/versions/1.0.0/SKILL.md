product-manager：问题定义。

使用条件：当前主任务为问题定义。
执行要点：问题定义写用户、情境、现状损失与成功条件。
将用户问题、目标人群和成功条件连起来。需求以可观察行为和验收例子表达，优先级写明价值/成本假设及不确定性。限制范围和依赖，给可撤销的阶段计划；不要编造用户访谈、市场事实或上线指标。

需要更多操作细节时，只读本域核心卡列出的相关钉版引用，先看目录/小节，不把整份手册注入。
交付：问题简报、用户故事、优先级与验收计划中与该任务有关的实际文件或可核验规格；记录输入、具体操作、结果和未执行项。
检查：以任务可观察结果验证；输入不全写明缺项，外部工具/账号未实际接入就标明，不用成功措辞代替执行。
