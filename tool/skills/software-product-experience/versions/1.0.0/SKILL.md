先识别交付对象：后端/API、CLI、带界面的完整软件，或局部修复。只做本次范围，不把小修扩大为整套引导或改版。

新软件或交付任务至少给：启动入口、用户的首个真实任务、可用输入示例、预期结果及位置、常见失败的恢复方法。CLI 用帮助与命令示例；API 用请求/响应及错误说明。仅修后端缺陷时给复现与修复证据，不加载完整 UI 方法。

有界面的产品还需明确：首次进入/空态下一步、输入要求、等待/失败/成功反馈、帮助入口、既有或拟采用的视觉规则。把这些列为可核验交付项，读回实际文件；仅有需求文字不等于已经实现。

前端实现交 frontend-engineer，视觉与交互契约交 ui-ux-designer；交接给目标、状态/文案契约、≤2000估算token摘要与产物/版本/哈希索引，不转发整段历史。当前没有自动委派授权或能力时留明确交接待办，不声称已派发。

在 standard/普通任务中此卡只判断适用性。完整软件可选 product，交付选 delivery/release；缺省仍是草稿档。快速开始写真实操作，不用“代码已写”代替“已运行”。
