# Phase 1 Stage Bindings

The 1.6.0 candidate accepts a configured numerical modeling project, with
conventional result paths and explicit metric tolerances. The acceptance sample
is a six-point linear regression. This is not evidence of correctness for an
arbitrary competition model. Model authors must supply independent validation.

All stages run in a new Codex run's `work/project`. Inputs are copied from the
immutable lock; `data/raw` is mounted read-only. No stage writes back to the
original project. Script nonzero exit, missing evidence, or a required failed
gate prevents submission. Prompt stages require actual session-authored work.

| Stage | Action and actual entry | Required evidence before advance |
| --- | --- | --- |
| INIT | script: init_project | new project manifest and stage state agree, READY |
| AUDIT | script: audit_data | nonempty data audit JSON and Markdown |
| SPEC | prompt, stage acceptance tool | CONFIRMED model spec, confirmation author/basis, objective, units, finite expected metrics and nonnegative tolerance |
| BASELINE | prompt, configured baselineEntry | source and results/baseline.json; configured baselineMetric, default mse, finite |
| SOLVE | prompt, configured solverEntry, register_result | results/solution.json matches every expected metric; registered source/data/spec hashes |
| EXPERIMENT | script: run_experiments | configs/experiment.json, actual successful runs with source/input hashes |
| VALIDATE | prompt, validationEntry (default src/validate.py), run_validations | configs/validation.json, nonempty passing validation checks, independent-validation.json with at least three passing checks, validation summary |
| FIGURES | prompt, render tool, actual visual review, check_figures | eight mandatory gates below |
| FREEZE | script: advance then freeze_artifacts | all preceding checks, final JSON SHA256 manifest with exact complete output coverage |

For stages after INIT, check the prior state, generate target artifacts, check
their domain requirements, and only then call stage_machine advance. FREEZE
advances before generating the final manifest so both final domain state files
are covered. output.json declares exactly the sealed artifacts other than itself.

Figure gates: figure_contract, source_preflight, render_preview, layout_bbox_qa,
composition_efficiency, panel_alignment, pdf_collision, visual_review. Both
FIGURES and FREEZE require all eight. Preview, PDF, PNG, SVG and QA evidence hashes
must still match; visual observations are never generated by the wrapper.

phase1.json requires projectId, dataFile, baselineEntry, solverEntry, figureSource,
figureContract, qaDirectory and visualReview. Optional validationEntry,
baselineMetric and resultRegistration customize the numerical workflow.
resultRegistration accepts metric, problemId, experimentId, claim, unit and
method. Defaults use model_spec objective/units and conventional P1/EXP-001 ids.
The independent validation program must check problem-specific assumptions,
constraints and units; generic metric comparison does not prove those properties.

Timeouts are bounded; uncertain outcomes block automatic replay. No repair loop,
parallel execution, Agent delegation or generic Phase 2 gate engine is enabled.
