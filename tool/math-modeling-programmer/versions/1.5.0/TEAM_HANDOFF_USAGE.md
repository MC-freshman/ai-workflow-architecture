# 建模手与论文手协作说明

本说明面向建模手和论文手。编程手负责把已确认的方案转成可运行任务、数据表格、图表和
验证结果；建模手负责确认题意、假设和结论；论文手只使用已审核或已冻结的结果。

## 1. 团队数据流

```text
建模手提出任务
    -> 任务清单和任务卡
    -> 编程手执行、验证和登记
    -> 建模手审核任务结果
    -> 关键数字进入结果登记表
    -> 论文手引用表格、图表和数字
    -> 全队冻结交付包
```

不要把聊天记录、终端截图或手工抄写的数字作为正式数据源。

## 2. 建模手：如何提出任务

一个任务可以是 EDA、清洗规则比较、模型计算、敏感性分析、仿真、优化或绘图。请尽量
提供以下内容：

```text
任务编号：EDA-Q1-014
所属问题：Q1
任务标题：比较不同区域的订单量差异
要回答的问题：判断区域变量是否需要进入模型
使用的数据：data/raw/orders.xlsx / Sheet1
期望输出：分组统计表、差异图、显著性或效应量
依赖任务：EDA-Q1-006
验收条件：单位一致、样本量已报告、缺失值已说明
优先级：P1
是否可能用于论文：是
```

如果只有模糊想法，也可以先写成待整理需求，但不要只写“分析一下数据”。至少需要说明
希望支持哪一个模型假设、结论或决策。

### 建模手提交任务时的规则

- 目标函数方向、变量含义、参数单位和约束必须明确；
- 未确认的内容标记为 `UNCONFIRMED`，不要要求编程手自行猜测；
- 说明任务是探索性分析，还是需要进入论文的证据；
- 指定结果应保留的精度、单位和统计口径；
- 如果任务依赖前一个结果，填写任务编号而不是只描述文件名。

## 3. 建模手：如何审核结果

编程手完成后会在 `tasks/task_registry.csv` 登记任务状态。建模手重点检查：

| 检查项 | 要确认的内容 |
|---|---|
| 题意 | 计算对象和题目要求一致 |
| 变量 | 变量方向、单位、取值域正确 |
| 假设 | 结果没有超出模型假设适用范围 |
| 数据 | 缺失、异常和样本筛选有记录 |
| 算法 | 基线、主模型和参数设置符合方案 |
| 结果 | 数值、表格和图表彼此一致 |
| 稳健性 | 至少有敏感性、基线或独立复算证据 |
| 论文价值 | 结论可以支撑正文中的一句话判断 |

审核结论只能使用以下三种：

- `ACCEPTED`：结果可用于正式分析或论文；
- `REWORK`：指出需要修改的计算、图表或说明；
- `BLOCKED`：缺少数据、模型规格或关键假设，暂时不能判断。

审核意见应具体到任务编号和修改动作，例如：

```text
EDA-Q1-014：REWORK
请将均值比较改为中位数和四分位距，并报告每组样本量；当前结果不能支持“区域差异显著”的表述。
```

## 4. 论文手：可引用哪些结果

论文手只使用以下来源：

1. `tasks/task_registry.csv` 中审核为 `ACCEPTED` 的任务；
2. `results/result_registry.csv` 中状态为 `CHECKED` 或 `FROZEN` 的数字；
3. 已登记来源结果 ID 的图表；
4. 验证报告中明确标为 `PASS` 的检查。

每个正文数字都应能回答：

```text
这个数字来自哪个任务或实验？
使用了哪份数据和参数？
单位、保留位数和不确定性是什么？
能否在程序中重新生成？
```

不要直接使用：

- 聊天消息中的临时数字；
- 终端输出截图；
- 未标记实验编号的 Excel 手工结果；
- 只有图片、没有来源结果 ID 的图表；
- 编程手口头说“应该是最终值”的数字。

## 5. 论文手：表格和图表的使用规则

### 表格

- 表头写清变量、单位和统计口径；
- 保留位数与测量精度或模型误差一致；
- 均值、标准差、标准误、置信区间不能混写；
- 表格中的关键数字回填到 `result_registry.csv`；
- Excel 只是排版和交换格式，CSV/JSON 登记表才是追溯依据。

### 图表

- 图题说明“展示了什么”，正文说明“说明了什么”；
- 坐标轴、单位、图例、样本量和误差定义完整；
- 同一方法在不同图中使用一致的颜色和线型；
- 图表由当前代码生成，不手工修改数字或坐标；
- 每张图在登记表中填写一句话结论和来源结果 ID。

如果图表需要修改，应提出新的任务，例如：

```text
FIG-Q1-003：保持数据和模型不变，将纵轴改为百分比，补充 95% 置信区间，并保证论文栏宽下文字可读。
```

不要在 Word、Excel 或图片编辑器中直接改程序生成的数字。

## 6. 三类标准交接消息

### 建模手 -> 编程手

```text
[TASK] EDA-Q1-014
目标：判断区域变量是否应进入 Q1 模型
输入：data/raw/orders.xlsx / Sheet1
输出：分组统计表、差异图、效应量
验收：报告每组样本量和缺失值；单位为件；结果需支持模型假设讨论
优先级：P1；论文候选：是
```

### 编程手 -> 建模手

```text
[REVIEW] EDA-Q1-014
状态：PASS，等待审核
结果：见 results/eda/EDA-Q1-014/summary.json
图表：见 figures/eda/EDA-Q1-014_group_compare.png
验证：缺失值检查 PASS，单位检查 PASS，基线比较 NOT_RUN
请确认：是否可以将“区域差异”作为模型分组依据
```

### 编程手 -> 论文手

```text
[HANDOFF] Q1
可用结果：result_id=EXP-014-Q1，状态=FROZEN
关键数字：见 results/result_registry.csv
图表：见 figures/fig_q1_*.pdf
验证：见 reports/validation_report.md
限制：结论仅适用于当前样本范围；不确定性见登记表
复现：见 results/reproduce.md
```

## 7. 冲突处理

出现数字或结论不一致时，按以下顺序处理：

1. 题目原文和竞赛规则；
2. 建模手已确认的模型规格；
3. 实际运行并通过验证的结果；
4. 案例经验或临时估计。

冲突、假设变更和结果取舍记录到 `reports/decision_log.md`。模型变更后必须创建新实验编号，
不能覆盖已冻结结果。

## 8. 最终交付前共同确认

- 建模手确认每道题的变量、假设、约束和结论；
- 论文手使用的数字全部来自登记表；
- 每张图均有来源结果 ID；
- `ACCEPTED` 任务没有未处理的 `REWORK`；
- 关键验证没有被标记为 `NOT_RUN`；
- 结果、图表、论文和代码来自同一个冻结版本；
- 交付包中包含复现命令、环境记录和哈希清单。
