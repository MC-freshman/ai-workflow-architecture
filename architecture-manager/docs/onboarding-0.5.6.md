# 0.5.6 接入修复使用说明

双击 `Architecture-Manager-0.5.6-portable-x64.exe`，工作区选择 `E:\ai`。不需要开控制台，也不需要 AI 手改平台配置。

## 已有平台继续接入

1. 打开“平台与接入”，在接入向导第 1 步选择平台。
2. 页面出现“平台安装的组件需要更新”时，点击“预览更新已安装组件”，核对文件和哈希后确认执行。打开新版 EXE 不等于平台安装副本已更新；旧文件会保存在审计恢复点。
3. 在“准备环境”核对软件位置。向导读取平台实际使用的网关文件；旧文件中的绑定、解释器别名、MCP 和凭据引用保留。同名绑定发生冲突会点名拒绝，不会偷偷选择或清空。
4. 独立更新组件/绑定后，点击“核对当前更改后续接”，确认差异及需要重验的步骤。管理台保留原日志带日期副本，并重验受影响能力。不要手改 automatic.json 的哈希，也不要换一份日志冒充成功。
5. 顶部“本次暂缓”可勾选暂不需要的环境、软件、客户端、认证或 Git。依赖步骤随之暂缓。结果显示“配置已保存 · 接入未完成”，取消勾选后再继续补齐。

## 表单与解释器

普通扫描刷新不覆盖正在编辑的 Python、软件位置和 WSL 选择；未编辑的字段会回填当前生效配置。旧计划里的 inputs 不再覆盖现行配置。“重新读取当前配置（放弃未保存编辑）”是明确丢弃草稿的入口。

有 hostEnvironmentManifest 的平台更换解释器时，预览会列出新解释器的实际宿主清单和配置指针。原清单保留；新的清单只覆盖 runner 的标准库及已导入依赖包，隔离脚本环境仍使用自己的完整清单。在途 run 不换锁，不通过时不激活。

## 软件导入后继续绑定

“导入本体”中先执行安置，再点“读取实际安置结果”。安置只是验证复制、备份和真实恢复。

- 已有软件配方：点击“绑定到现行配方（不发布新版本）”，仅更新所属平台的本体路径。配方和默认版本不变，具体兼容性/MCP/功能仍须各自实测。
- 新软件：完成第 2 步“只读询问并预览配方与绑定”。这个入口原本就会发布配方并绑定，本轮没有把它说成新增功能。
- 安装包须先安装，再选择实际安装本体；不能把安装包直接当已接入软件。

## 如何读接入结果

peer 接入探针验证真实 prepare → 领取任务 → 确认 stop，不提交或编造作者正文。拒绝、领取失败或停止失败都不能通过。业务执行缺正文时显示 awaiting-input；协议可调用不等于业务完成。

第 6 步“查看接入记录与恢复点”提供正式回读：当前配置和证据、组件哈希、本次配置提交是否排除运行产物，以及历史 runtime 入库件的数量和清单。历史违规不能因为是文本就视为合规。本轮没有删除旧历史，也没有替各平台改写旧证据。

此版本交付管理台修复，不代替各平台自己的生产复验。zcode 应先更新安装副本再续接；dsh 原来“claimReached=true、子任务缺正文”的记录不能用来证明业务已经完成。
