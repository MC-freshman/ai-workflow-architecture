# P10 共同导入、恢复与撤销

共同事务使用 body-import 计划。来源摘要、目标 ID/版本、生成文本、原文映射和指针/登记/所属平台绑定都在同一计划中。来源必须未改变，目标版本不能覆盖；仓内仅文本/源码，软件本体由独立安置计划归所属平台 runtime。

暂存放在 `<平台>/runtime/tmp/manager-imports/`，journal 在 `<平台>/runtime/maintenance/manager-imports/`。完整契约、依赖闭包与双向封条通过后原子发布新版本；随后按基线哈希写指针和登记，不能改其它资源或其它平台。替换既有登记前要有 Git HEAD 中相同的原字节；没有回滚提交会提示先在仓库页处理，不静默覆盖。

中断后保留现场。已经发布的版本只读保留，继续时核对自己的 SOURCE/封条，跳过已完成安置和发布，只补登记。首次执行、重复确认和同 ID 新版本分别处理；同版重复不重装或重发，不初始化已有业务 run。

“导入本体”下方的“导入记录与恢复”只读所选平台的记录，可恢复原计划或预览撤销。撤销仅在当前内容仍是本次输出时恢复旧指针/登记；外部新改动不覆盖。冻结版本、原件、本体和备份保留；这不是卸载软件。软件独立安置已有完整副本与真实恢复演练，普通复制不冒充功能验证。

八条专项检查通过，涵盖实际 Git 回滚锚点、发布后中断续接、复制取消、原件/旧版本保真、外部改动保护、目录越界、重复确认、软件安置/备份恢复只执行一次，以及共同 IPC apply/verify/记录/撤销。路径同一但斜杠写法不同按 realpath 比较，避免 Windows 假不一致。

可回读样例在 Codex 私有 P10-example 独立工作区，含 journal/checkpoint/恢复结果与逐项 SHA。软件样例只检验测试字节的复制和恢复，未执行程序或业务工作流；真实软件功能在 P14/P17。P11–P15 的各类表单与转换尚在继续。
