# 0.5.7 软件配置与接入操作说明

双击 `Architecture-Manager-0.5.7-portable-x64.exe`，选择自己的架构工作区；本机是 `E:\ai`。打开“平台与接入”，向导第 1 步选择要操作的平台。

## 遇到两份软件配置

当前配置中的 `softwareGatewayConfig` 指针决定哪份软件配置生效。其它旧文件不再自动合并，也不会因旧 `.py` 路径不同阻断当前配置。

向导显示“软件配置来源核对”，列出当前文件、其它文件、缺少项与差异项。这是对比信息，差异不等于当前配置损坏：

1. 当前绑定齐全时直接继续，不需要删除旧文件。
2. 确实需要恢复旧文件中遗漏的绑定时，点击“预览迁入缺少项（保留当前差异项）”。默认保留当前解释器、软件位置和权限配置。
3. 只有明确要采用另一份配置的差异值时，点击“预览迁入并采用此文件差异项”。先核对计划，再“确认并执行”。这可能修改解释器、端点、权限或 provider 命令，不能只看文件名决定。
4. 没有唯一指针且两份配置冲突时，界面仍能打开，但普通保存会要求先完成上述明确选择。

来源原件保留。计划固定目标和来源哈希，执行前变化会拒绝；写入有审计、恢复点和中断回滚。迁移只是配置操作，不代表软件功能已实测通过。

## 保存和解除软件绑定

进入第 3 步“准备环境”，展开“绑定软件本体与平台 provider”。填写或选择实际程序位置，点击“保存软件位置与 provider”，核对后执行。

清空某一程序路径并保存，会明确解除这一个绑定；清空 PPython 会解除该解释器别名。不会删除软件程序文件，也不会从旧配置悄悄恢复。未绑定的软件会如实列入待补项。

## 重读、续跑与暂缓

- 普通重扫保留正在编辑的内容。“重新读取当前配置（放弃未保存编辑）”明确放弃 Python、软件位置、隔离后端等全部配置草稿，并清除旧环境检测和能力回执。
- 独立保存绑定或组件后，点击“核对当前更改后续接”。确认差异后，受影响结果失效并重新验证；环境变化时旧安装计划留历史，不再用旧解释器/后端计划堵住续跑。不要手改 automatic.json 的哈希。
- 顶部“本次暂缓”可勾选暂不需要的模块。暂缓项不会算通过，状态保持“配置已保存 · 接入未完成”。首次完整接入的真实地板、矩阵、治理与入库判据仍须满足。
- 普通 GUI 本体不能作为 JSON CLI 入口。使用“安装标准 CLI 客户端入口”，或按已存在的 MCP/厂商接口接入；许可、登录、UAC、系统重启仍在系统界面处理。

文件选择与慢请求返回后会核对当前操作对象，不能把旧平台/旧软件的结果填进新对象。平台私有配置路径按所选工作区解析，跨平台、工作区外和目录联接越界会拒绝。

本轮交付管理台修复；没有替生产平台篡改配置或旧日志，也没有重新宣布它们的认证结果。历史 runtime 入库问题 D-112 仍单独登记；一个 WSL 子进程取消用例在不具备该测试环境时保持跳过。
