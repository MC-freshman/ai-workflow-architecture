# 0.7.1 审计和测试

在“审计”页点击“刷新并核对”，按工作区、状态或计划/操作 ID 筛选。每次确认执行有一个独立 operationId；同一计划重试会产生新的操作 ID，嵌套操作保留父 ID。AI 的平台 tool/agent 选版使用同一审计边界，GUI 和 AI 都不改在途 run-lock。

新事件自动写时间与 SHA-256。查看审计时核对事件结构、封条，以及当前显示窗口内 checkpoint 的字节；默认显示最近 100 条，接口最多 500 条。旧记录不补造时间或哈希，明确显示历史未封条。操作只有开始没有最终记录时，显示尚待核对；可能仍在运行或异常中断，不能当作成功或零写入。封条仅用于发现不一致，不能抵抗有权限者改写整个日志。

日志位置：`%LOCALAPPDATA%\ArchitectureManager\audit\events.jsonl`；恢复点：同目录 `checkpoints\*.before`。错误信息中的已知本次凭据值和常见凭据模式在写入前脱敏。读取旧记录时仅对展示脱敏，不改写历史文件。审计记录不保存凭据；checkpoint 是配置恢复材料，仍须按本地私有数据管理。

损坏 JSON/非事件不会进入界面列表；哈希或恢复点不符时保留原件，核对实际文件后再决定恢复。`AUDIT_FINALIZATION_FAILED` 表示操作已经返回、最终日志保存失败，可能已写入，应先回读实际状态和恢复点，不能盲目重复执行。审计开始记录失败时不会派发操作。

开发者在源码目录执行：

```powershell
npm run conform -- --workspace E:\ai --out E:\ai\codex\runtime\maintenance\audit-report
```

一条命令执行 lint、preload 合约检查、完整实现测试和可选三仓只读审计，输出 `conform.json`、各步 stdout/stderr 和 `workspace-audit.json`。不带 `--workspace` 时只验证管理台实现。有效测试必须有完整 TAP 汇总、至少一项实际通过、零失败和零取消，全部跳过或零测试不会通过。报告绑定 `src/`、`scripts/`、`test/`、package/lock 和 lint 配置的 SHA-256，并检测验证过程中的源码变化。

三仓审计复用现有冻结发布校验器，检查 registry/current、启用的现行版本及其精确依赖、双向文件封条、schema 和锁；停用资源的释放版不记成“已验证”。同一版本依赖在一次审计中只校验一次。报告有静态 digest，不改指针、平台配置或已发布字节，不运行软件、原生 AI 或平台全矩阵；它不能证明平台已接入或软件功能可用。发现共享历史问题时报告失败，不靠改冻结字节或声明刷绿。

本轮管理证据在工作区 `codex/runtime/maintenance/20261008-audit-tests/`。测试用临时夹具验证失败、取消、恢复点损坏和重复执行，不接触生产项目。0.7.1 保留 0.7.0/0.6.0 发行件；更换 EXE 后重开管理台即可使用审计页增强，已安装到平台的 AI 入口需通过既有组件更新流程采纳，管理台不会顺手改别的平台安装副本。
