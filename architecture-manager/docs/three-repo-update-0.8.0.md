# 三仓接入一键更新（0.8.0）

打开管理台，选择自己的架构工作区，到 **平台与接入 → 一键更新所有平台**。自动纳入已有接入配置的平台，生成一份完整更新预览；核对后点击“确认并执行”，只确认一次，按平台依次执行。

预览固定本次三仓现行版本、配对引擎/契约/检查器、专家依赖和需要准备的环境。盘上更高的未采纳候选不会自动成为更新目标。若现行调用判据与引擎接口不配套，可使用工作区 `versions/anchor.json` 已明确采用的兼容判据，来源和摘要一并固定；无合法配对时停止预览。

在“必要补填与保留个人固定版本”展开项中，可以填写有效上下文窗口、来源和适用的 Python。缺失的窗口不会假设为无限；Python 不兼容、依赖冲突或封条损坏都列明原因。个人固定资源填 `agent:资源ID,tool:资源ID`；未保留的顶层覆盖跟进共享默认，专家内部精确锁按原版执行。

资源操作环境按 BP-1 §1.6③归目标平台 `runtime/manager-resources/`，与 runner 密封环境分开。只准备选中现行资源闭包声明的精确依赖；新环境在 `inbox/backup/<平台>/manager-resources/` 留重建配方、轮子、文件摘要和真实恢复记录。新环境恢复失败时不激活新配置。旧目录和证据保留，管理台不自动删除。

程序使用既有认证选择器：内容和来源未变时沿用证据，只重测受影响格；沿用既有首次接入及引擎/契约大版本规则。资源环境文件即使路径没变，内容变化也使相关证据失效。软件配方、连接器版本核对与软件本体真实功能分别验证，缺本体或接口仍显示待补。

执行中可点统一进度中的“停止本次操作”；停止当前可取消步骤后保存记录。再次进入该面板可点“继续本次更新”，沿同一固定计划继续，已完成的环境准备保留。共享目标或外部配置被改动时拒绝旧计划，重新预览；修改补填值也会生成新计划。

“恢复本次旧接入配置”生成恢复预览，确认后恢复仍由本次操作拥有的配置并提交到本地 Git。已有外部新修改的文件保持原样，并显示需核对。恢复不删除新环境、运行证据或备份，也不自动推送恢复提交；需要远端同步时用 Git 页面正常推送。恢复后重新点击全局更新按钮生成新计划。

结果分别显示“无变化”“更新并验证通过”“待补”“已验证，待推送”“已停止”“失败，已恢复”和“外部变化需核对”。一个平台待补时其他独立平台继续。缺账号、许可、UAC 或厂商接口会列原因；无模型直接探针可用的已登记客户端自动重新验证，有模型调用或需登录的客户端需在原接入入口补齐。

勾选“本次同时正常推送已配置的 Git 远端”后，执行器只正常推送，不强推；不混入无关暂存、凭据、本体或运行产物。没有推送授权或远端失败时保持“已验证，待推送”。最终完成同时要求真实检查、原生证明和四项 Git 读回：HEAD、治理白名单为空、远端一致、回滚提交早于配置激活。

本次开发的自动更新和恢复验证使用隔离工作区；真实资源环境恢复另有独立证据。fixture 不证明厂商客户端或模型业务成功，0.8.0 功能发布也不表示所有生产平台已经完成采纳。
