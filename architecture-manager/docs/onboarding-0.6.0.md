# 0.6.0 自动准备、原生接入与资源版本

## 平台连接三仓

1. 打开 0.6.0 管理台，选择自己的架构工作区。
2. “平台与接入”→“平台接入向导”，选择已有平台，或先用“导入本体”安装新平台的实际程序。
3. 选择厂商本体，或留空让管理台识别所选平台目录中的已有程序。点击“预览一键接入／继续”。现有兼容 Python、WSL 发行版与客机 Python 会真实探测；没有兼容设施时如实等待安装，不要求 AI 改 JSON。
4. 核对计划并确认。原生配置通过厂商支持的 writer 注册；无关设置保留，可能含凭据的原配置只留 Windows 当前用户 DPAPI 加密备份，真实恢复到独立文件比较成功。
5. 分别查看“服务通道验证”“厂商原生三仓验证”“完整认证”。服务回环通过不代表厂商客户端接入成功。

当前已适配原生接口：

| 本体接口 | 自动配置 | 不经过模型的真实调用 | 状态口径 |
|---|---|---|---|
| Codex 自带 app-server | 原生 config/batchWrite 注册 MCP，保留其他设置 | ephemeral 协议会话中调用 architecture_probe、architecture_list、architecture_get_release；从三仓各读一个 SHA256SUMS 校验的冻结版本 | 有原生当前证据才通过；没有模型回合，没有业务阶段 |
| WorkBuddy 自带 CLI | 厂商 CLI 注册独立项目 `.mcp.json` | 无模型直接调用接口仍待确认；可明确选择一次原生 AI 只读验证 | 必须有效登录；只认真实工具使用/工具结果，模型文字不算证明；未验证不能标完整接入。GUI 还须加载该项目 |
| 未提供已适配外部 MCP 接口的程序（含当前豆包本体） | 登记本体与具体缺口，不改厂商二进制 | 不用自建 CLI 冒充厂商 | 等待厂商开放接口／适配器；平台能力准备仍可保存 |

Codex 的配置与验证接口来自官方 MCP、app-server 文档；WorkBuddy 项目配置来自其官方 MCP 说明及本体 CLI 帮助。仅存在 mcp_helper.dll 或 MCP Apps 页面不是外部服务注册接口。

原生“三仓读取”验证的是客户端确实能访问共享资源及冻结字节；软件具体功能仍按配方/连接器和权限执行，读取清单不表示已扫描网络或操作数据库。完整平台接入还需能力地板、首次矩阵和配置入库，分别记录，不互相替代。

本体或配置改动后旧原生证据失效。暂缓客户端验证则保留待补状态。原生配置备份在 `inbox/backup/<platform>/manager-native/`，标记可能含凭据，不入库；跨 Windows 用户/电脑不能直接解密，需重新登录或配置。

WorkBuddy 在“客户端入口”点“允许一次原生 AI 只读验证”，确认一次额度使用。管理台在同一个原生进程内先执行官方认证；需要用户登录时直接打开官方浏览器页面，界面显示等待登录，此时尚未发送模型请求。只提供一个读取三仓冻结文本的工具、显式拒绝内置写入/执行工具；调用次数守卫跨服务重启保留；不自动重试。只认匹配的 tool_use/tool_result 及随机挑战，不认模型回复文字。配置过程始终不依赖 AI。

2026-10-07 本机仍未通过 WorkBuddy 原生三仓验证：账号缓存预检可读、官方 authenticate 返回成功，但随后实际工具请求仍返回 Authentication required，没有有效工具回执。最早两个拒绝记录 num_turns=0；认证与请求合并后厂商记 num_turns=2、费用=0，仍未通过。管理台如实保留失败记录，不把认证成功、计数或费用当作能力证明。这是原生认证通道待适配，不能保证用户重复登录就能解决。

## 本体进入三仓

“导入本体”选择 agent、skill 或 tool，选择文件/目录/ZIP，确认明确入口，再点“自动生成接入计划”。ID 和名称优先读 manifest／frontmatter，缺失时由文件名或内容指纹生成；新版本按语义化排序递增；全文、附件、SOURCE、SHA256SUMS 和精确依赖由既有发布执行器落盘。

普通 agent 未带主工作流时选择已发布的标准工作流并精确锁版；已有依赖与权限保留。缺失依赖、多个正文入口或超出标准模板的运行语义明确要求补充，不能由管理台猜出后宣称业务已验证。工作流脚本导入只生成定义，不启动业务脚本。

软件进入 software 的仍是文本配方，程序归所属平台 runtime。读取可确定的名称、版本号与 Windows PE GUI／CLI 类型；实际软件版本、动作映射、MCP 地址与权限按实测/声明处理。只有程序但没有可调用接口的 GUI 可管理会话，不能据此声称 GUI 内全部功能已经自动化。

## tool／agent 切版与回退

进入“三仓资源”，找到资源；“正在使用”来自 current.json。下拉框默认选中现行版；选择目标版→“预览切换／回滚”→核对 SHA 与依赖→确认执行。切换回旧版走同一路径。依赖冲突或未冻结版本会拒绝；进行中任务的锁不改变。资源页也可打开 tool／agent 正文并发布独立更新版本。

## 本轮诚实的未完成部分

尚不能保证任意厂商 EXE 都能全自动接入：WorkBuddy 无模型直接调用通道和豆包外部工具入口仍待适配。任意软件动作、凭据、复杂权限也不能从二进制名字推断。本轮提供自动准备与支持接口的自动配置、严格原生证明及明确待补项，不把缺口刷绿。

本机 WorkBuddy 自带 CLI 为 2.156.0；它没有较新 SDK 的 --request-timeout-ms 参数，因此管理台不传该参数。账号元数据与原生认证 token 分别判定；协议回执的 token 仅转入本次子进程内存。当前本体的认证/工具结果仍未闭合，不要求用户反复登录，不宣称本轮全部平台已接入。
