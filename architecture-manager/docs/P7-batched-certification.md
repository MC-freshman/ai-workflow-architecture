# P7 批处理认证与计时

2026-10-03。新发布配对 `wf-runner 0.12.2 / repo-lint 0.6.5`，矩阵判据包 `architecture-ops 1.5.2`。当前生产配置和共享 current 没有自动切换。

管理台的新平台配置页会推荐已冻结、校验通过的性能配对。点“填入推荐版本”只填表，仍需预览配置计划并确认执行；候选或冻结失败的版本不推荐，检查器与 runner 声明不配对时拒绝。已接入平台的更新也由同一个配置计划执行。

每个工作流/智能体认证格使用一个 runner 进程，内部沿用原 prepare→next→stop 的权限、契约、锁、版本和修订校验，不执行业务阶段。旧 runner 保留原三次 CLI 方式。进度显示初始化、准备、领取、收口与启动/传输耗时；剩余时间按已完成格估算，不作为保证。

真实两代表格，各三次：expert-task@1.1.0 中位 4140→2375 ms；game-builder@1.10.0 中位 6454→4765 ms；进程启动 3→1，两格均达到 ≤80%。未知版本、非法参数、协议版本及检查器版本冲突的错误分类/重试属性与普通入口一致。取消真实创建后的维护 run，进程退出 125，清理通过普通 stop 收口为 stopped，保留 run-lock/事件流 SHA。

性能结论针对上述两格及本机配置；沿用旧证据的 52 格不称为新测。首次接入和大版本升级的矩阵仍由 P6 选格规则决定。其它平台需各自采用配置并独立认证。

单条回读：`npm run conform -- --out <私有证据目录> --release-proof <P7-release-proof.json>`。该文件将原基线、最终三次矩阵、错误对照、取消证据和新旧释放版 SHA 绑定到同一 digest；不额外跑全矩阵。
