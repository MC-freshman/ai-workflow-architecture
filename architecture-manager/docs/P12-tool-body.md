# P12 工具与工作流

「导入本体」选工具／工作流，可导入说明文字、普通目录／ZIP、JSON/YAML 定义或源码脚本。没有架构 JSON/current 的来源也能接入：填写 ID、版本、显示名称及阶段，管理台生成规范 manifest、工作流定义、正文锚点、输入输出 schema、封条和登记。

提示词阶段填写正文；脚本阶段选择实际源码并逐行填写参数和超时。预览、发布与最小调用都不会执行脚本。EXE／DLL／安装包归软件，不能以工具名绕过第三仓。脚本业务执行仍受所选平台隔离环境、权限和确认约束，不以领取成功冒充业务成功。

资源页「查看／编辑工作流」可读取完整原定义及阶段正文。未勾选修改阶段时保留原图、门禁、schema、脚本等支持文本；升级同时修改 manifest 与定义的身份，旧目录不变。发布向导还提供合法的从零模板：已有工作流可只发布或发布并采用，新 ID 自动建立首次 current/registry。专家新模板锁定一条主工作流。

所有新发布走 P10 的共同 journal、checkpoint、CAS 和恢复；旧 release-publish 执行器只作旧计划兼容入口。合法非空阶段、成对提示词锚点、精确依赖、双向封条和身份都需通过公共校验。原 R10/R15 的空模板、错误 schema 和升级身份不同步已闭合。

实际 Codex 私有样例对导入工作流、身份升级、从零模板分别 prepare→next→stop，三格通过；回执证实原始说明进入提示词。已有默认 1.0.1 在仅发布 1.0.2 后保持不变。首次错误锚点候选与失败读数保留，新版本重出证，未改写它。GUI 全链路验证按 P17 执行，当前开发新增功能不在已发行 0.4.2 中。
