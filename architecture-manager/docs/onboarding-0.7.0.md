# 0.7.0：自动接入与平台独立版本

这是可使用的阶段发行，不能据此宣布六个平台原生全自动接入完成。软件程序、Node/Python 运行本体、凭据和证据均归所属平台；三仓仅发布文本、定义和配方。

## 选路径后接入三仓

“导入本体”选择类型、所属平台和文件／目录／ZIP，点“识别并预览来源”。agent 的 manifest.prompt、tool 的 manifest.entry、唯一 prompt.md／workflow.yaml／SKILL.md 会自动选入口；无法唯一确定时，一次选择明确入口。

tool、agent、skill 点“自动生成接入计划”。管理台推断身份、新版本和标准定义，保留完整正文，钉依赖并生成 SHA256SUMS；核对计划后点“确认并执行”。有歧义、缺依赖或已发布版本冲突会停止。任意脚本项目不能仅凭目录推断全部业务语义；缺少定义的流程使用明确标注的标准模板，业务执行需另行发起。

software 点“自动匹配配方并接入／标准 GUI 会话”。匹配到唯一现行配方时，安置本体、真实恢复备份、写本平台绑定并检查已声明条件；不会重写现行配方。未知 GUI 自动生成标准 start/status/close 会话配方，不自动启动窗口，不声称能操作 GUI 内部功能。未知 CLI 的动作或专用 MCP 尚无声明时仍待配置，使用原有“功能动作／现成 MCP”表单补齐。匹配多份配方时集中提示歧义。绑定成功、版本查询和具体功能调用是三个不同结论。

## 只修改某个平台的版本

1. 打开“资源”，在上方“平台独立版本”选择平台。
2. 找到 tool／agent，查看“共享默认”“平台选择”“当前生效”。
3. 选择已有冻结版本，点“预览本平台切换／回退”，核对目标平台后执行。
4. 回到该行读“当前生效”；“恢复跟随共享默认”删除本平台选择。

修改仅影响未来任务；共享 current、其他平台、正在运行的锁及 agent 精确 tool-lock 不变。引擎、扫描器等存在配对约束的资源仍用平台对齐计划，不能单独半切。旧选择指向已不存在版本时必须明确选可用版本或恢复跟随，不静默替代。

## 跟 AI 说同样的事情

在已加载架构 MCP 的原生客户端中说：“把本平台的 agent `<id>` 切到 `<version>`”“本平台 tool `<id>` 恢复跟随共享默认”。AI 使用 `architecture_get_platform_versions` 和 `architecture_set_platform_default`；后者需要 kind、resourceId、version 和 confirm=true。version=null 恢复共享默认。Codex 原有 `ai_set_platform_default` 同样转交此执行器；已打开的旧 MCP 进程需要重新连接或开新会话以加载新代码。

管理台安装标准服务时会把统一选版执行器与 Node 本体安装到各平台。Node 本体在 runtime/manager-node，文本执行器在 bridge/manager-client。备份在 inbox/backup 的本平台目录，安装时实际恢复并核对哈希。未经厂商调用验证的客户端不能仅因安装了这个标准服务而称原生已接入。

## 平台客户端的当前边界

| 平台 | 自动配置 | 本轮真实原生验证 |
|---|---|---|
| Codex | 原生 app-server 写 MCP，保留其他设置 | 三仓冻结读取、平台版本读取已过；历史 visualization-engineer 1.6.0 选择缺冻结目录，保留并登记 |
| WorkBuddy | 厂商 CLI 写项目 .mcp.json | 一次授权实测认证完成、MCP connected；未收到工具回执，待补，模型是否实际开始未知 |
| Qoder | 原生工作区 mcp.json 的 mcpServers | 已注册，须加载生成项目；真实厂商调用待补 |
| ZCode | 原生工作区 .zcode/config.json 的 mcp.servers | 已注册，须加载生成项目；真实厂商调用待补 |
| DSH | 可识别实际 GUI 本体、安装标准服务 | 尚无已适配原生配置和调用链，待补 |
| 豆包 | 可安装标准服务 | 未确认自建 MCP 外部入口，待补 |

“平台与接入”选择原生本体、安装标准服务后预览原生注册；没有可用厂商接口时显示待补。Qoder／ZCode 生成的项目位于各自 workspaces/architecture-native，不修改厂商程序字节。厂商登录与许可需要使用者操作。暂缓可保存配置并继续其他独立步骤，不能将暂缓当完整接入。

## 审计、恢复与验证

GUI 与 AI 的平台选版使用同一原子执行器、checkpoint 和审计。基线或冻结依赖变化会拒绝；重复已完成计划不重复写；死进程留下的锁归档后可恢复，活进程锁仍阻断。新的原生失败／待验证状态会使旧成功标志失效，旧证据仍保留可回读。

本轮不重复平台全矩阵。单命令 `npm run conform -- --out <目录>` 汇总源码检查和受影响回归；发行包另逐 SHA 回读并用真实便携 EXE 验证界面。软件版本询问、三仓文件读取和业务运行分别记录。
