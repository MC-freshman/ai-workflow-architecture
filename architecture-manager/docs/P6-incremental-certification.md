# P6 增量认证

平台按钮、接入向导和兼容流水线都使用同一范围判定。确认框先列出本次实测格、沿用格与原因；确认后绑定变化会要求重新预览。首次完整认证前不把单格或空行报告变成完成。有效首检后按正文/精确依赖、相关配置、Profile、provider、环境与验证规则选格；仅改注册表显示名称等缓存信息不重复调用。

`domains/certification/` 分为 binding、content-cache、fingerprints、selection、evidence、legacy。旧 core 入口只是兼容出口。冻结目录先查完整文件集合与链接，再复算封条；未变内容按文件大小、mtime、ctime 和文件标识增量复用 SHA，修改同大小文件并恢复 mtime 仍会重新哈希。

coverage 每行保留原报告路径、SHA、实际行与当时指纹。合并结果明确区分 actualRows/reusedRows；零次新调用只有在全量原证据有效时才能沿用完成，不冒充刚实测。中断保留实际完成行，继续时补其余；失败的增量轮保留本轮已经通过的格。能力地板失败不会抹掉之前的恢复点。所有证据只能来自所选平台。

旧首检迁移先复核 matrix/conform SHA、正向 prepare/claim/stop 或软件快照/本体读数、配置绑定。注册表/available 缓存改变时，可以用原入库 commit 机械重构旧共享摘要，与当前平台私有文件摘要相配；冻结依赖再与当时 Git 封条逐件相配，程序文件在旧检查后变化的格不迁移。无法证明等价的格列为待测。其它平台的 runtime 不参与重构。

验证：132 项，131 PASS / 1 SKIP / 0 FAIL。真 Codex conform 的能力读数为 33/0/0；调用面沿用原 52 格，实际矩阵启动 0，总执行约 12.7 秒，不含预览时间。正式批处理和两格三次性能比较仍按 P7 完成，实际 EXE 按 P8。
