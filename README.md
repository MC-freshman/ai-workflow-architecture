# 架构管理台 0.5.2 使用手册

每个人使用自己的架构工作区、平台配置、软件和 Git 仓库。管理台在本机工作，不需要中心服务器。0.5.2 增加暂缓接入、明确差异续接和带 SHA 的历史记录；保留外部本体导入、更新、恢复和增量认证。逐步操作见 [接入续接与暂缓](docs/onboarding-resume-0.5.2.md)。

## 1. 打开和选择工作区

1. 双击 `Architecture-Manager-0.5.2-portable-x64.exe`，或运行同版 `setup-x64.exe` 安装。便携包、安装包和 `SHA256SUMS-0.5.2.txt` 位于 `architecture-manager/release/`；旧包不覆盖，GitHub Releases 保留既有历史版本供回退。
2. 点击右上角“选择工作区”，选自己的架构根目录。本机是 `E:\ai`；不要选择某一个 tool、agent 或平台的子目录。最近目录会记忆，切换工作区会清空旧计划和待提交凭据。
3. 全新用户可在首次页面克隆自己的架构副本。GitHub 登录在系统自己的界面完成；提交姓名和邮箱只用于 Git 提交身份。
4. 等“扫描完成”后操作。默认扫描只读，生成计划也不写入。核对目标后点击“确认并执行”，才开始安置、发布、绑定或调用。

运行 EXE 不要求安装开发 Node/npm。平台运行工作流或脚本需要自己的解释器、隔离环境及所需软件；管理台会检测和列出待准备项。程序许可、登录、UAC、系统组件安装和重启由用户在对应系统界面处理。

## 2. 从本体添加到架构

打开“导入本体”，按同一条路线操作：**选择类型 → 选择所属平台 → 选文件、文件夹或 ZIP → 识别 → 确认入口 → 填表 → 预览 → 执行 → 回读**。

目录或 ZIP 有多个候选入口时，必须在“确认正文／程序入口”中选一个。识别到文件不等于接入成功。原件保留；导入包中的说明只是内容，不会成为管理台自动执行的命令。

| 要添加什么 | 准备的本体 | 管理台填写和处理 |
|---|---|---|
| 智能体（agent） | 提示词 Markdown/文本，或含明确入口的目录/ZIP | 名称、ID、角色、工作流与精确依赖；生成 manifest、锁、来源、封条并发布 |
| 技能（skill） | SKILL.md 或含它的目录/ZIP | ID、名称、依赖；保留正文及附属文本/源码，生成 catalog 和版本 |
| 工具／工作流（tool） | 工作流说明、定义或脚本项目 | 用阶段表单确认流程、参数和依赖；生成合法定义/schema，新 ID 可直接创建 |
| 平台客户端 | 客户端程序、完整目录或明确的 CLI 配置 | 平台 ID、解释器、接口模式；安置本体、配置服务/原生描述、登记治理并测试真实入口 |
| 软件／现成 MCP | 完整安装目录、可运行程序/脚本或 MCP 配置 | 先安置和真实恢复，再声明 CLI 功能、GUI 会话或 MCP 工具并绑定所属平台 |

ID 使用小写英文、数字和连字符；中文写显示名称。更新沿用同一 ID，版本自动递增或选择新的语义化版本。已发布版本不可覆盖。共享仓仅存文本/源码/配方；本体、依赖环境、凭据、缓存和证据归所属平台 runtime，备份归 inbox/backup 的对应平台。

### 智能体、技能和工作流

“正文预览”便于检查入口；完整正文会保留，不受屏幕截断影响。“资源”提供查看全部内容、编辑并发布新版本、切换默认版、停用/移除登记。依赖从版本列表选择并精确钉版；资源现行版以 current.json 为准。

导入工作流后可执行最小调用检查，它验证 prepare→next→stop 的可调用链，不替你运行正文业务或生成模型答案。现行启用资源的真实依赖会阻止停用；历史版本中的字面提及不应当作现行依赖。冻结旧目录仍保留。

### 平台客户端

1. 选择客户端本体。新平台填 ID、显示名称并勾选允许创建该一级目录；已有平台从列表选择。
2. 选择准备架构服务的 Python。接口不明确的 GUI 使用“GUI／接口未明确”模式；确实实现架构 JSON stdin/stdout 协议的 CLI 才选对应模式。
3. 预览并执行本体接入，随后点击“测试已接入的真实客户端”。普通程序的 `--version` 成功不能代替客户端随机挑战回执。
4. 到“平台与接入”选择这个平台，完成环境、软件位置、客户端/provider 和 Git 身份表单，预览“一键接入／继续”。管理台执行配置、准备独立环境、恢复验证、探针、认证、治理登记和显式 Git 提交，不要求 AI 会话手改配置。

暂不需要的部分在顶部“本次暂缓”勾选，依赖步骤自动暂缓；结果显示“配置已保存 · 接入未完成”及待补软件。独立安装入口或保存软件位置后，点“核对当前更改后续接”，确认完整旧/新哈希和受影响步骤；不必手改钉子。换引擎/契约/检查器时明确“预览重建接入记录”，旧日志留日期副本。后续取消暂缓并继续即可补齐；单格成功、暂缓和配置提交均不代替首次完整认证。

界面分别显示本体已安置、架构服务回环、所选客户端已验证、厂商原生接线及能力地板。只有能力并集 0 declaredAbsent 且本平台证据有效才称“接入完成”。无 CLI/MCP/插件接口的程序可登记和启动，原生接线保持待适配；管理台不能凭 EXE 创造厂商工具接口。

## 3. 接入和使用软件

### 普通 CLI 或脚本

1. 选择实际程序或完整安装目录。依赖同目录 DLL/资源的 EXE 必须连完整目录一起选；安装包仅安置，安装完成后重新选实际本体。
2. 填软件 ID、名称、本体版本，点击“1. 预览安置／继续与恢复”并执行。这里会生成备份，再用备份真实恢复得到最终本体；共两份完整落盘数据，界面显示空间与进度。
3. CLI 填版本查询参数；脚本选择明确的解释器。添加需要的“功能动作”、固定参数和类型/标记/顺序。只读探测需明确勾选；有副作用的动作保留待验证。
4. 点击“2. 只读询问并预览配方与绑定”并确认。真实查到的版本和已测功能才进入冻结快照。版本查询通过不代表所有功能通过。
5. 在“软件”先选所属平台，再点对应软件的“功能参数与会话”，按表单填写参数并预览调用。操作结果和版本询问分开记录。

通用 CLI 不需要为每个软件单独写 MCP。只有程序缺可用接口、特殊认证、特殊传输或参数结构尚未支持时，才需要适配器或专用连接器。

### GUI 程序

软件形式选 GUI，填写必要启动参数，安置后发布会话配方。通过“预览启动本次会话”“预览检查会话存活”“预览关闭本次会话”管理真实进程。关闭只针对管理台本次登记的会话。

窗口启动成功不等于 GUI 内部功能已自动化；无 API/MCP 的界面功能由你操作。“打开位置”显示并打开所属平台绑定的实际目录，入口模板与解析后的真实路径分列。状态不明时不会盲目启动第二份。

### 已有 MCP 配置

1. 选择 MCP 配置所在目录，在入口列表选择实际 JSON。配置支持 mcpServers、servers 或单个明确的服务配置。
2. 选择配置中的服务，必要时选 Node/Python 等实际运行程序。自动下载型 npx/npm/uvx 入口不偷偷安装，显示待准备项。
3. 安置后点击“实际连接并读取工具”。这是真握手及工具清单读取，不运行工具功能。
4. 只勾选需要发布的工具，逐项确认影响、文件范围和网络范围，预览发布并绑定。未选工具不发布；本平台采用支持原生 MCP 的连接器，其他平台配置不改。
5. 到软件功能表单按真实 schema 填参数，再预览实际调用。定义已发现与功能已执行分列；调用断连后可能已经执行的结果会提示“不确定”，不会冒充调用前已拒绝。

支持 stdio、旧 SSE 和 Streamable HTTP；支持协议版本 2024-11-05、2025-03-26、2025-06-18、2025-11-25。未支持的协议（包括 2026-07-28）、OAuth、特殊证书和专用传输明确待适配。程序字节或工具 schema 漂移会拒绝旧快照调用，需重新发现并发布新版本。

需要凭据时展开“准备、保存或恢复本平台引用”。先准备 provider，填写 `reference:名称` 和凭据值，预览保存。值只在本地内存和 Windows 凭据库/DPAPI 加密备份中处理，不进入计划、审计、配方、证据或 Git。备份含凭据且只适用于当前 Windows 用户；换电脑或用户需要重新登录或录入。

## 4. 更新、停止、继续和撤销

- **更新**：选新来源，沿用 ID，发布新版本；先看正文/差异及默认版选择。仅发布不采用时旧 current 保持；确认采用才切默认和所选平台绑定。在途 run 继续使用原锁。
- **停止**：进度栏点击“停止本次操作”。等待任务完成中止记录后再操作；已安全完成的原子提交如实记完成，不伪装撤销。不会杀掉用户原本打开的软件。
- **继续**：回到同一工作区/平台，导入记录中选择“继续原计划”，或重读实际安置结果。继续校验原来源、已复制前缀和摘要；发生外部新改时暂停，不强行覆盖。
- **撤销登记**：导入记录中“预览撤销登记”，确认后恢复本轮旧指针、登记及平台绑定。冻结新旧版本、本体和备份保留，撤销不是物理卸载或永久删除。
- **停用/排除**：资源停用受现行依赖保护；平台“排除视图”只隐藏列表，不删目录、不改平台能力。要解除接线，应预览对应配置变更。

生成下一项计划前须保存前一项治理配置的 Git 基线。出现“基线已改变”时先回读目标/差异，处理自己的修改后重新预览；不要靠重复点击覆盖外部内容。

## 5. 认证为什么更快，什么时候仍需等待

“接入认证（自动选格）”重新 conform，并按内容、版本、环境/provider 和判据摘要选变化/未完成格。未变格校验旧证据和来源 SHA 后沿用，界面明确区分“本次实测”和“沿用”。最新缓存不是刚刚执行。

首次接入或引擎/契约大版本升级仍完整矩阵；之后新增复用已有 Profile 的资源只补对应格。停止或失败后补未完成格，不把通过格全部重跑。软件本体复制、环境安装和首次矩阵仍取决于文件量、磁盘和资源数。

“完整配置”可明确选择 wf-runner 0.12.2 / repo-lint 0.6.5 / architecture-ops 1.5.2 的已发布提速配对，再预览保存配置；不会自动切共享默认或其他平台。普通调用格进程启动从 3 次降至 1 次；两代表格同机三次中位耗时为旧路径的 57.4% 和 73.8%。第一次采用新判据文件时 SHA 改变仍会重检受影响格，不能承诺任何操作都只用几秒。

## 6. 计划、文档、Git 和备份

“治理”中的计划中心按原文表头读取 P 表和状态，有筛选/分页；点文档进入全文维护。不会根据目录存在推测完成。“文档”查看编辑顶层要求、计划、说明和日志，写入前核对基线和目标。

“仓库”点击“刷新并扫敏感文件”，再选择提交、分支、标签、推送、历史备份、HEAD 快照或回滚。表单选择本次路径、填写说明并生成计划；不需要 console 或旧式弹出 prompt。已有无关暂存会拒绝混入，不会替你清空它。推送仅使用真实配置远端，拒绝强推；GitHub 登录需你完成。

历史备份包括 Git 历史及需要的工作树/暂存并做真实恢复验证；HEAD 快照只是一份文件导出，不等于历史备份。回滚显示提交和影响路径，以 revert 保留可追踪历史。软件/环境备份归 inbox/backup 的对应平台；没有恢复演练记录的备份不算已验证。

审计及 checkpoint 在本机 ArchitectureManager 用户数据目录；认证和导入 journal 在所选平台 runtime。它们可用于诊断和续接，不随 Git 上传。把架构交给其他人时让对方使用自己的副本、环境和凭据，不复制你的运行数据冒充对方接入证据。

## 7. 已知边界与验证口径

0.5.0 实际 EXE 验证覆盖 agent、skill、tool 更新、平台 JSON CLI 挑战、CLI/MCP 真实调用、GUI 真实窗口/存活/关闭，以及取消续接和元数据撤销。样例在独立测试工作区，不据此替任何生产平台申报接入完成。

本轮原生 Windows 自动化接口不可用，系统文件选择/确认弹窗的人工点击未完成自动验证；EXE 自身 DOM→IPC→Worker→文件/进程/Git 链真实运行，测试驱动只在内存中回答它自身的确认弹窗。没有假装厂商登录、UAC、GUI 内部业务或未配置 WSL 已测通过。

后续维护项已单独登记：历史资源元数据、依赖审计、首次新规则指纹开销、展示性引用路径及 Git 确认文案的目标格式。当前 Git 计划详情中的真实工作区与文件列表可核对；确认弹窗的旧目标模板可能显示 undefined，不用它判断影响文件。它不改变计划派发或文件选择。

## 8. 开发与复算

开发使用 Node >=24、Electron/React/Node IPC、已锁定依赖及现有 Python/provider。普通用户无需执行这些命令：

```text
npm ci
npm run conform -- --out <本平台证据目录>
npm run build:ui
npm start
npm run package:win
```

conform 集中静态未定义变量、操作声明/preload、模块边界、领域事务、真实进程/恢复及相关回归，输出 pass/fail digest。发布辅助 Python 脚本保留在 app.asar.unpacked；外部软件的 ASAR 被当作真实文件复制，不展开其内部虚拟目录。已发布三仓字节只读。
