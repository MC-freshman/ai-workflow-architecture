# 0.5.2 接入续接与暂缓操作

打开 `Architecture-Manager-0.5.2-portable-x64.exe`，选择自己的架构根目录（本机是 `E:\ai`），等“扫描完成”，进入“平台与接入”。无需 AI 会话改 JSON，也不需要手改日志里的哈希。

## 现有平台继续接入

1. 在“操作对象”选择自己的平台，例如 `dsh`。
2. 顶部“本次暂缓”可多选：运行环境与能力实测、软件本体绑定、客户端验证、接入认证／首次矩阵、Git 提交。配置、安全校验与治理登记不能跳。运行环境暂缓会连带暂缓 provider、能力、客户端和认证；软件或客户端暂缓会连带暂缓完整认证。
3. 没有独立修改过配置时，点击“预览一键接入／继续”。独立安装标准客户端、保存软件位置或修改配置后，点击“核对当前更改后续接”。它会读取当前生效配置，列出变更文件的完整旧/新 SHA 与要重新验证的步骤。
4. 核对后点击“确认并执行”。旧接入身份保留，受影响结果作废重验，未变化的安全安装步骤沿用。预览后又有变化会被拒绝，需要重新核对。
5. 暂缓时结果为“本轮配置已保存 · 接入未完成”，逐项列出待补模块和未绑定软件。已选择的安全步骤仍可完成，Git 可提交当前配置；该提交不代表完整认证通过。
6. 后续补齐后取消相应暂缓勾选，重新预览并继续。首次完整接入仍需能力地板、客户端真实回执、首次矩阵和 Git 全部达标；缺口/未测不能刷成通过。数量来自当时启用资源，不能把单格 PASS 当整套认证。

## 换版本或明确重新开始

引擎、契约、检查器版本不同，不能沿用旧认证。先核对“完整配置”中的版本，再点“预览重建接入记录”。确认后创建新的接入身份，旧记录保存为带日期的历史文件，附完整 SHA256SUMS。旧失败不会被删掉。

历史位于自己平台的 `runtime/maintenance/manager-onboarding/history/`。严格拒绝未确认变化时不改原日志；重建和核对续接在写新记录前留原始字节副本。

## dsh 当前这次怎么走

当前记录的客户端哈希已与现文件相同；不能据此证明是谁改了钉子。既有同一计划日志和失败记录保留，没有第二份新日志。软件本体登记仍为空，先前单格成功不等于完整认证。

暂时不用六件软件时，勾选“暂缓软件本体绑定”，点击“核对当前更改后续接”，核对并执行。管理台会完成其它已选安全步骤并保存待补状态。需要的软件可以先在本平台的软件中心选择实际本体并绑定；不要直接借用别的平台 runtime、凭据或环境。补齐以后取消暂缓并继续。

标准 CLI 入口是实现架构 JSON stdin/stdout 回执的入口。普通 Electron GUI 不能填成该 CLI；厂商原生接口注册与架构服务回环分别显示，标准客户端验证不冒充厂商原生客户端验证。

## 本版还修复了什么

- 旧 false 不再反过来堵住能力探针自身；候选声明只供真探针使用，生产声明只有真实证据通过才改变。
- 已有 prepare/stop、隔离、委派、软件或当前客户端证据通过时，只清对应的旧名缺口；未知或未通过项保留。
- 客户端步骤会真正取回随机挑战回执；完整认证可复用同配置、同版本、同文件 SHA 的该回执。
- Windows 备份恢复明确选系统 tar，避免 Git Bash PATH 导致盘符被误认为远端。
- 缺陷簿新增号段仍检查连续性，非法 ID 给结构化错误。

0.5.2 新增双包，不覆盖旧发行。便携包已走真实 EXE/DOM/IPC/Worker、文件与 Git 链路；安装包校验内嵌同一应用载荷，未声称执行过系统安装界面。WSL 专项未在本轮重跑，生产 dsh 的完整认证也未代跑。
