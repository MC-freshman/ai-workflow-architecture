# 架构与版本说明

## 三个共享仓

| 仓 | 保存的内容 | 主要结构 |
|---|---|---|
| tool | 工作流、技能、能力包、引擎与治理工具 | registry、current、versions、SHA256SUMS |
| agent | 专家角色、提示词、策略和精确依赖锁 | registry、current、versions、tool-lock、SHA256SUMS |
| software | 软件配方、能力快照、接口 schema 与网关定义 | registry、current、versions、SOURCE、SHA256SUMS |

软件配方描述怎样取得和调用软件，仓内不提供第三方软件本体。三个仓保持各自职责和版本形态；单个 GitHub 仓库只是它们的公开托管载体。

## 三层版本

**管理台版本**：本发行是 0.8.1，描述 Windows 应用功能和安装包。

**共享资源版本**：每个专家、流程、技能或配方独立发布。current.json 指向共享默认，内部依赖按锁解析。当前快照的治理组件版本列于 [RELEASE.json](../RELEASE.json)，不要用应用的 0.8.1 替代资源版本。

**平台采纳版本**：由用户自己的平台配置选择，允许合法的个人固定版本；必须满足对应资源的配对与依赖关系。公开源码不携带作者的生产采纳状态。

## 运行与隔离

客户端通过自己的 bridge 读取三仓。运行开始固定资源、技能与依赖版本，锁和事件写入所属平台 runtime。配置、软件本体、环境、缓存、日志和凭据各归所属平台。

跨客户端续跑以带 SHA256 的交接载体和版本一致性校验承接。正在进行的单个 run 不热迁移。不同客户端同时写同一项目副本的冲突，不能当作架构已经提供跨平台互斥来处理。

## 新用户的工作区

本快照的治理入口是通用说明，平台清单为空。新增平台、环境和凭据由使用者在自己的副本中准备。各平台能力须独立验证，不能复制别人的日志或结果作为自己的接入证明。

专家与工作流未写档位时按草稿范围执行；“过图”与“交稿”遵循对应流程。资源可调用、配置已保存和业务完成具有不同判据。

## 历史资源与完整性

共享仓的现有版本目录保留原公开字节；原始第三方许可、SOURCE 和封条一起保留。整仓文件使用 [REPOSITORY-SHA256SUMS](../REPOSITORY-SHA256SUMS) 核对。

较早公开快照曾对少量历史软件配方文本脱敏，本发行不覆盖那些已公开的版本。相关来源差异列于 [历史资源来源](reference/frozen-source-provenance.json)。整仓校验通过证明下载与本次快照一致，不替代使用者平台的真实能力或软件本体认证。
