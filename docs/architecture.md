# 架构与执行语义

本架构是多 AI 客户端共用资源和执行记录的工作区，不是一个新模型或云托管服务。管理台维护资源和接入，当前客户端中的 AI 执行获准模型任务，执行器负责依赖解析、阶段状态和检查。

tool 共享工作流/skill/pack、执行器和治理文本；agent 共享专家与精确主流程/依赖锁；software 共享软件配方、能力快照及接口定义。三仓均保留 registry、current、语义化 versions、SHA256SUMS 与依赖。三共享目录与私有/公开两个 Git 仓是不同概念。

prepare 解析本次选择、校验冻结资源和环境、保存 run-lock；next 返回待完成动作，客户端完成并 submit；检查后继续，终态依据实际结果。专家内部依赖不被平台默认覆盖；共享默认切换不改变进行中 run。旧发布只读，新版采用创建新目录和明确切指针。

平台配置、凭据、环境、本体、缓存、日志与 run 一手证据在所属平台。环境需求只按专家依赖、skill 声明或平台 runtime 配方归属。跨平台项目状态使用带 SHA-256 的交接载体，校验续跑版本；不直读另一个平台 runtime，不对进行中单 run 热迁移。平台内锁不提供跨客户端互斥，使用者需避免并发写同一项目副本。

能读三仓是内容可达；prepare→领取→stop 是所测入口可调用；真实客户端工具回执是原生通道接通；业务 succeeded 只证明那次业务。完整接入另要求本平台兑现共享能力并集、消除缺项和未验证、完成规定认证与治理。它们不能互相替代。
