### 采用的设计

1. **默认严格续接，漂移有可操作差异**。预览同时固定日志 SHA、变更路径旧/新 SHA 和影响步骤。增加“核对更改后继续”和“从当前配置重建”两条明确路径。核对后继续保留原计划身份，但丢弃受影响步骤结论；不是把哈希改对就把旧认证当通过。变更在预览后再漂移一律拒绝；引擎/契约/检查器钉版变化必须明确重建，不能静默换代。
2. **可暂缓维护模块**。环境/能力实测、软件绑定、客户端验证、认证、Git 可明确暂缓；配置与安全校验不可跳。自动展示依赖暂缓。未选/未绑定软件留真实 pending 清单，未达到能力地板时不启动完整矩阵；其它已选安全步骤仍继续。返回“本轮配置已保存·接入未完成”，不调用完整接入的完成标记。补齐时能沿用未变化的已完成安全步骤；首次完整认证仍按共享侧实际目录数量跑一次，数量动态读取。
3. **保留历史和诚实账面**。自动日志在每次尝试/重建前保存带日期/逐字节 SHA 的历史副本；可回读对比，旧失败不替换。真实证明通过时仅清理对应旧 unverified/declaredAbsent 别名，不清无证据项。补 D-98/D-99 和附带问题登记，号段上界从实际合法 ID 派生。
4. **可复现验收与发包**。Windows ZIP 恢复明确使用系统 tar，避免 PATH 上 Git Bash tar 把盘符当远端；检测不到真实系统工具则明确失败。基线失败单独留档，不改断言刷绿。使用本机同版 Electron 构建到 Codex 私有候选目录，逐文件核对执行体，再新增 0.5.2 双包/哈希/说明并正常提交推送。
