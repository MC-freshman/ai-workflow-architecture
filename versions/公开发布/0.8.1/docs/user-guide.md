# 架构管理台操作手册 · 0.8.1

## 操作顺序

每次先选择自己的工作区，再选择所属平台。涉及写入的操作遵循 **填写 → 预览计划 → 核对目标与差异 → 确认执行 → 回读结果**。一个计划执行或安全停止后，再开始下一项操作。

## 查看和管理资源

“资源”展示 tool、agent、software 的登记、现行版和历史版。打开条目可查看定义、正文、来源与依赖。专家调用的内部工作流服从其精确锁；平台个人选版与共享默认分开显示。

更新资源会创建新版本目录，旧发布目录保留。“预览共享默认切换／回滚”改变共享 current；“资源 → 平台独立版本”只改变所选平台的个人选择。已有 run 的版本锁不会因默认指针变化而换版。

## 导入专家、技能和工作流

在“导入本体”选择类型、所属平台和文件/目录/ZIP。识别出多个入口时明确选一个；检查正文，确认 ID、显示名称、阶段和依赖后预览发布。

| 类型 | 推荐来源 | 需要确认 |
|---|---|---|
| 专家 agent | 提示词文本或有明确入口的目录 | 角色、正文、允许调用的流程及精确依赖 |
| 技能 skill | SKILL.md 及其附属文本/源码 | 身份、完整正文、软件需求和依赖版本 |
| 工作流 tool | 合法定义或有清晰说明的脚本项目 | 真实阶段、输入输出、入口和权限 |

中文名称填显示字段；ID 使用小写英文、数字和连字符。自动识别只填可确定的信息，不能代替你确认业务语义。程序依赖、缓存和执行产物归所属平台，不进入共享发布目录。

## 接入自己的平台

1. 在“平台与接入”选择已有平台，或为自己的客户端新增平台 ID。新增一级目录须明确确认。
2. 准备客户端入口、Python/其他解释器、接口模式和所需软件。配置中的路径使用本机真实路径。
3. 核对完整配置、模型/有效上下文窗口及来源；信息不明时补填或保留待补，不猜厂商容量。
4. 预览“一键接入／继续”，确认后执行环境准备、配置和检查。
5. 查看分别显示的配置、能力地板、客户端回环和厂商原生工具结果。保存配置不等于完整接入；接入检查不等于业务已经执行。

暂不准备的组件可勾选“本次暂缓”，结果保留待补清单。准备完成后使用“核对当前更改后续接”，确认旧/新摘要及受影响步骤。无需重新覆盖已有项目。

## 一键更新所有平台

按钮位于平台页，面向已有有效配置的平台。先预览本次会涉及的平台、依赖和版本配对，再确认执行。

0.8.1 会先核对上下文窗口与来源；合法旧 bridge 副本按配置引用确定权威位置并纳入配对备份。环境恢复证明须属于该平台，且摘要、通过字段和实际安装版本相符才复用。

各平台分别显示完成、待补、停止和恢复结果。取消或检查异常后的配置会按本次归属保存为待补；不能入库时恢复本次拥有的字节，外部新改保留并提示核对。厂商原生模型挑战仍在原客户端入口逐次确认。

## 软件和 MCP

先选择所属平台，再选择真实软件本体或现有 MCP 配置。

- **CLI/脚本**：完整目录一起安置，选择实际入口与解释器；确认版本查询参数、功能动作和参数结构，再做只读发现与绑定。
- **GUI**：登记实际程序，按本次会话启动、查看存活并关闭。窗口存活不证明 GUI 内部业务已自动完成。
- **已有 MCP**：选择服务配置及运行程序，实际握手并读取工具；只发布选中的工具，确认影响范围后按真实 schema 调用。

安装器只负责安装或安置，不能当作已安装程序调用。缺接口、OAuth、专用证书或不支持的协议按待适配显示。凭据使用本平台本地引用；值不应写入资源正文、配方或 Git。

## 停止、继续和恢复

点击进度栏“停止本次操作”，等待停止记录完成。已经完成的原子步骤如实保留；不会杀掉用户原本打开的软件。

继续时回到同一工作区与平台，从原计划或导入记录恢复。来源、已完成前缀和摘要发生外部变化时需核对后再预览。撤销登记恢复本轮旧指针与配置；它不是物理卸载或删除冻结版本。

## 文档、Git 与备份

“文档”维护工作区要求和说明；“治理”的计划中心读取自己的 P 表与状态。“仓库”按所选路径预览提交、标签、推送、备份或回滚。未归属的暂存内容不应混入本次提交。

软件与环境备份归所属平台的 backup 登记。Git 历史备份和 HEAD 文件快照是不同载体；经过真实恢复核对才算可用备份。首次接入或引擎/契约大版本变化按完整判据检查，之后复用有效证据并只补变化项。

数据范围与反馈方式见 [数据与许可](data-and-license.md)。
