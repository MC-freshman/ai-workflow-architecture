## 产品约定

- 平台标准入口为 `<platform>/bridge.json`。历史 `<platform>/bridge/bridge.json` 只作为读取兼容；迁移逐个平台预览、确认、回读，不删除旧文件，不静默切换客户端的引用。管理台对两个位置只展示一个 bridge 状态；若两份内容不一致，显示冲突并禁止自动迁移。
- 管理台支持已登记的六个平台目录。无代码向导负责目录发现、配置预览、确认写入和逐平台验证；“已配置”“可调用”“接入完成”分别判定。新客户端缺适配器时显示“待适配”，绝不凭文件存在亮绿。
- tool 与 agent 保持现有三仓结构。新资源初次登记建议最新稳定发布版；新版本发布后不静默改变 `current.json`。用户可在管理台选择已发布版本，预览、确认、验证指针切换；进行中的 run 保持原锁。
- software 仓只存配方文本。下载的软件本体由向导安置在所属平台 `runtime/software/`，依 BP-7 登记备份并真实恢复演练；调用优先经连接器／MCP。未知协议或无法验证的能力显示“待适配／待验证”，不伪称接入完成。
- 所有工作区写入采用 plan → confirm → apply → verify；失败不得留下半截写入。每个下列子块结束均保留可回读的代码、测试或台账状态，可安全停手。
