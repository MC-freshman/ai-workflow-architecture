## 1. 这一代改了什么

管理台从"五面板计划式工具"扩为**全面管理框架软件**：管理对象覆盖三仓资源（发布/升级/标记）、六平台接入（含新平台一键接入）、runs/run-lock、缺陷状态簿、inbox 三区、审计历史、Git 执行器、软件连接器启动、计划中心、文档站构建、工作区从 0 克隆搭建。全部写路径走既有事务内核（plan→confirm→apply→verify：乐观锁/checkpoint/原子写/回读/幂等/审计）。

## 3. 定稿偏差与移交项（不构成完成的部分，如实登记）

1. **P11 i18n**：文案层抽取未实施，界面仍 zh-CN 单语——P11 判据"核心流程双语冒烟"不满足，本轮**带偏差收口**（先例：2.0.0 带偏差定稿）；移交维护期。
2. **干净机首启回归**：安装包双击启动属用户动作，管理台会话无法代点；包哈希可复算，首次启动回归移交用户/维护期。
3. **renderer store 全量重写、扫描缓存、dsh 半程实盘**：P9/P8 内如实偏离登记（收益/风险比不成立或需真实平台会话），移交维护期。
4. 维护期缺陷登记：本轮 0 红行（`P0/defects-register.json` 空簿维持；执行期发现的均为本轮新增代码自身问题并当场修正）。

## 4. 不变边界（与 3.4.0 一致的八条全部继承）

三仓仍是 tool/agent/software 且同构形态不动；管理台不是平台、不产生运行时能力；runs/inbox 面板只读；凭据零经手；已发布字节零改写（发布 ≠ 采纳）；自证语义不变（BP-2）；接入完成的判据仍是矩阵 FAIL 0 + 0 declaredAbsent，不由管理台 UI 声明。
