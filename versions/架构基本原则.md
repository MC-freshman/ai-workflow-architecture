# 用户工作区架构原则

本公开工作区保留以下基本约束：

1. **三仓骨架**：tool、agent、software 职责独立，保留 current、语义化版本、SHA256SUMS 和精确锁；只收文本/源码/配方，软件本体不进共享仓。
2. **平台对等**：使用者平台各自声明并验证能力；待补如实列出，不按作者身份产生特权或永久分层。
3. **最小增量验收**：以内容和哈希选变化项，检查能发现真实失败；首次接入与引擎/契约大版本变化才跑完整矩阵。
4. **续跑语义**：跨客户端使用带哈希的交接载体与版本一致性校验；不静默换版，不宣称已经具备跨客户端互斥。
5. **有序实施**：执行前给 P 表，每块安全停手，按预定判据完成；非阻断问题登记后另立方案。
6. **入库与回滚**：破坏前有可回滚提交；按明确路径提交，推送前扫描，不强推，不混入别人的未收口内容。
7. **隔离与备份**：配置、凭据、软件本体、环境和私有运行数据归所属平台，按平台备份并经一次真实恢复才称可用。

解释器、库或外部程序的需求归专家依赖、技能声明或所属平台 runtime 配方之一，写明归属。已发布版本只读；档位、平台隔离和诚实报告不因增量检查而削减。
