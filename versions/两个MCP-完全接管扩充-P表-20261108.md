## 1. 「完全接管」的定义与不可达边界（先钉死，防止误判）

**可达定义**：在不启动 GUI、不引入仓外源码到共享仓、不绕过授权的前提下，把两个软件**所有可 headless 调用的能力**纳入 MCP 工具面；读默认开放，写/破坏性动作走一次性确认；能力缺失时结构化降级并给补齐路径，不谎报。

**明确不可达（红线，不是待办）**：

| 类别 | 为什么不做 |
|---|---|
| 驱动 GUI / Electron 窗口 | 两个 MCP 都是 stdio 无界面进程；小说平台 IPC 只在渲染↔主进程之间 |
| 云模型调用（AI 生成/对话） | 需外发项目上下文与凭据；`novel.config.api` 已被脱敏层屏蔽，不回显也不转发 |
| `git push` / 发包 / GitHub release | 外部动作，BP-6 要求用户终端与当次授权；MCP 不得成为绕过通道 |
| 改共享 `current` / 抬引擎默认 | 红线 5；显式版本请求不读平台默认 |
| 删除类动作、跨项目副本并发写 | 不可恢复；小说平台服务层事务队列不跨进程互斥 |
| 把仓外源码（`architecture-manager/src`、`E:\小说\创作平台`）复制进共享仓 | BP-1 可冻结 / BP-2 平台对等；只能**运行时可选注入** |

6. BP-2：其他平台无 `E:\小说\创作平台` 与管理台源码 ⇒ injected 层在其上降级；`gapPlan` 需写明补齐路径与成本。
