# 解封 dsh 那一格：操作序、输入清单、失败分支

- 文档性质：**操作指引（前置条件未满足，尚不可执行）**。本文不构成对任何平台配置、共享仓字节或 `current.json` 指针的写入授权。
- 事实基线：`versions/版本配对失配-根因与解决方案-20261006.md`（同日，sha256 `9296fd6d…`）。
- 读完本文你能自己做三件事：① 在管理台里找到"该点哪几个按钮"；② 知道成功与失败各长什么样；③ 知道**今天先动手会撞哪面墙**。

## 一、今天真正卡住的不是矩阵，是三个不同性质的问题（别把它们混成一件事）

| # | 问题 | 性质 | 现在能不能靠点按钮解决 |
|---|---|---|---|
| ① | 接入记录里 `certification` 步挂着 `deferred`，原因写"依赖暂缓的 软件绑定，未执行"，而软件本体其实已绑定 | **陈标记**（记录里的事实过期） | ✅ 能。取消勾选暂缓后重跑即可 |
| ② | 唯一失败格 `workflow:repo-lint@0.6.3` → `VERSION_CONFLICT` | **判据把共享 current 当成了平台该用的版本** | ❌ 不能。纯点按钮无解，见第三节 |
| ③ | `firstCertification` 为空 ⇒ `verify-onboarding.mjs` 出不了 digest；根仓两笔未推 | ② 的下游 | ❌ 随 ② 一起解 |

**为什么 ② 点按钮解不了**：`certification` 步失败后，管理台落的是 `pendingMatrixRecovery`，其 `only` 就是失败那一格的 `kind:id`；下次续跑仍由 `platform-check.mjs:152` 起拼参数，**依然不传 `--targets`**，于是那一格又按共享 `current` 选版，再撞同一条闸门。不换判据/不换钉版，重跑一百次都是同一格同一错。

## 二、管理台里你实际会看到什么（逐字取自 0.5.2 源码）

面板：**平台接入向导**（`architecture-manager/src/renderer/panels/onboard.jsx`）。

**三个按钮**（`:68`）：

| 按钮文字 | 参数 | 行为 |
|---|---|---|
| `预览一键接入／继续` | `resumeMode='strict'` | 有配置变更即拒（`ONBOARDING_RESUME_DRIFT`） |
| `核对当前更改后续接` | `resumeMode='reconcile'` | 逐文件核对差异后继续；**版本变更即拒**（`onboarding-resume.mjs:60`） |
| `预览重建接入记录` | `resumeMode='restart'` | 重开一份记录（旧记录留日期副本） |

**暂缓勾选**（`:68` 的 fieldset，legend「本次暂缓（可多选）」）：`暂缓运行环境与能力实测` / `暂缓软件本体绑定` / `暂缓客户端验证` / `暂缓接入认证／首次矩阵` / `暂缓 Git 提交`。

**版本选择**（`:82`）：三个下拉——运行引擎 `wf-runner`、运行契约 `runtime-contracts`、资源检查器 `repo-lint`；每项第一行是「使用共享默认 X」，其余是该资源共享仓里**全部可用版本平铺**。

**提速配对按钮**（`:81`）：「选择这套提速版本」→ 写入 `snapshot.performanceRecommendation` 的四个值（引擎／检查器／契约／调用判据）。

## 三、操作序（前置条件：`VERSION_PAIR_MISMATCH` 已按裁定降为具名警告）

> 裁定原文见根因文档 §9.5：**降为具名警告，写进接入记录与治理登记，不阻断接入**。该裁定**未实施**前，本节的 A1 会失败（见第四节）。

| 步 | 动作 | 期望读数 | 失败分支 |
|---|---|---|---|
| A0 | 先取回滚点：确认根仓 HEAD 与工作区干净（B-6 读数在案） | `git rev-parse HEAD` = `32de49c2`；无已跟踪文件改动 | 有改动 ⇒ 先提交或登记，别在脏树上抬配置 |
| A1 | 换用新管理台包后打开向导，对象选 `dsh · 修复或升级接入` | 目标：检视 `runner 0.12.2 / contracts 1.5.2 / scanner 0.6.5` 三项"当前使用"与预期一致 | 若报 `VERSION_PAIR_MISMATCH` ⇒ 判据改动未生效，**停手**，回第三节前置条件 |
| A2 | **不勾任何暂缓**（尤其"软件本体绑定"与"接入认证"），点「核对当前更改后续接」 | 预览列出本轮要改的文件；**不再出现 `certification` 重新 marked `deferred`** | 若预览报 `ONBOARDING_RESUME_DRIFT` ⇒ 先看 `resumePreview.changes` 逐项核对，不要直接转 `restart` |
| A3 | 确认执行（第二次确认弹窗） | `configuration / backend / environment / providers / client / capabilities` 六步沿用旧记录（`passed` 重用，不重跑）；进入 `certification` | 任一步 `ONBOARDING_STEP_FAILED:<name>` ⇒ 记下步名与 `result.status`，停手 |
| A4 | `certification` 走 `mode='quick'`、`only='workflow:repo-lint'`（由 `pendingMatrixRecovery.only` 决定），只补跑那一格 | 该行由 `FAIL` 转 **`PASS`**；`counts.fail = 0`、`needsInput = 0` | 若那一行仍 `FAIL`：读 `matrix.json` 里该行的 `errorCode`／`errorMessage`；若是 `VERSION_CONFLICT` 且报文里的版本仍是 `0.6.3` ⇒ 说明这次仍按共享 current 选版，判据改动没生效 |
| A5 | 固化首次认证 + 统一回读 | `state.json` 的 `firstCertification` 非空；`scripts/verify-onboarding.mjs` 八项全 true 并出 `digest` | 八项里有 false ⇒ 按该项名定位（`firstMatrix` / `capabilityFloor` / `configurationCommitted` …），别只贴 ok=false |
| A6 | BP-6 四读数补齐并推送 | HEAD sha、白名单内 `git status` 为空、`origin/main..HEAD` = 0/0、入库时间早于任何破坏性动作 | 无推送通道 ⇒ 只登记"远端未同步"，**不要**声明完成 |

**守恒约束（每一步都适用）**：本序列**不写共享三仓**、**不改其它五个平台**、**不翻任何 `current.json`**。dsh 的 `scannerRelease 0.6.5` 与 `bridge.json` 默认 0.6.5 保持原样 —— 它们是本案里唯一自洽的一套，动它们才是真倒退。

## 四、如果预检仍保持硬拦（备用序，代价明写）

裁定未实施时，让 dsh 自洽且过闸门的组合只有一种：

| 步 | 动作 | 代价 |
|---|---|---|
| B1 | 向导里把「运行引擎」改为 `wf-runner 0.12.0` | dsh 退回与 codex/zcode/qoder 同代的引擎 |
| B2 | 把「运行契约」改为 `runtime-contracts 1.5.0` | 契约退两代（1.5.2 → 1.5.0） |
| B3 | 把「资源检查器」改为 `repo-lint 0.6.3`（= 共享 current，也 = 0.12.0 声明所要求的**不是** 0.5.1，故 B1 必须与 B3 同批） | 检查器退两代 |
| B4 | 调用判据 `invocationMatrixRelease` 同步退到与 0.12.0 兼容的代 | 判据代后退 |

**为什么不推荐**：这条把 dsh 从"唯一横竖自洽的平台"降成"和另外三家一样落后"，而且**下次共享指针一抬又要重来一遍**。它只证明了一件事：**闸门语义不改，所有平台都会被同一把尺子反复拧**。

## 五、这次操作顺带能验到的东西（顺手取证，零额外成本）

1. **矩阵行是否记录了它按哪一层选版** —— 若判据改动生效并在行内写了 `resolvedFrom`，那一格应显示 `platform-default`（而不是 `shared-current`）。这是"判据尊重平台声明"的可回读证据。
2. **`only` 是否真的只跑一格** —— `pendingMatrixRecovery.only` 是 `workflow:repo-lint`，故 `--only` 只该产生 1 行；若出现 0 行或 >1 行，是 D-32 那一族（零行假绿）复发的信号。
3. **五平台是否被动到** —— 操作前后对 `codex/zcode/qoder/workbuddy/doubao` 各取一次四键读数（根因文档 §9.1 的 V8–V10），应逐字不变。
