## 1. 三条先钉住的口径（任何一步不得违反）

1. **不靠削弱 schema 消灭测试失败**。旧 fixture 与旧声明一律**迁移到新语义**，不是把必填改成可选。
2. **历史坏版本不回改**。已发布 `versions/` 目录字节只读；坏封条的 `_connector 1.0.4`（D-91）原样留存，显式点名它时**仍应报历史错误**——修的是"别家会不会被它坑"，不是"把红行抹掉"。
3. **配置对齐 ≠ 能力完成**。本方案任何一步的"完成"都要有真 run、事件流与产物哈希，不接受"config 里写了这个键"。

## 5. 3.0/3.1 遗留批的并入口径

- **盘上确实已有两份缺口登记**（本轮实测，修正本方案初稿的说法）：`qoder/runtime/maintenance/3.0-A/GAP-3.0.md` 表格 **53 行**、`3.1-A/GAP-3.1.md` 表格 **231 行**，都带 `路径:行号` 与整数分钟成本。**但它们是"按位置编的缺口地址簿"，不是"按缺陷号编的状态表"**——3.0 那份只交叉引用到 `D-25/31/32/34/35` 五个号，3.1 那份只引用到 `D-66/D-69`。因此 `D-36…D-52`、`D-53…D-64`、`D-70…D-82` 至今**没有逐条状态**，治理文本里多以区间出现。
- **顺带记一处治理文本与盘面的不符**：`AGENTS.md` 里写 `3.0-A/GAP-3.0.md`"39 行"，实测表格行为 **53 行**（文件 106 行）。要么当年数的是登记条目数、要么是后续追加未同步——按 BP-6 该在下一轮文本更正里改掉。
- **取证方式的一条自纠**：本条第一次核数时用了 `A && B && wc` 的链式命令，A 失败导致 `wc` 根本没跑，我一度据此判"GAP 文件不在原路径"——**文件一直在**。教训与 D-94 同类：判据命令的退出码链会把"没跑成"伪装成"没有"。
- 因此**不在本方案里逐条宣布它们的状态**——那会是用推测填表。做法：R-P1 先把状态簿建起来（**可以直接把上面两份地址簿作为输入**，成本因此低于初稿估计），再由 R-P2…R-P5 认领其中属于契约／扫描器／判据／会话四组的条目；其余（平台铺开、凭据类、观察窗口）留在各平台自证与维护期。
