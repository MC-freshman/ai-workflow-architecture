# 管理台三仓接入一键更新实施表（已批准，P1–P6 已执行）

2026-10-09。用户要求：“增加一键更新按钮，就是让已经接入的平台可以一键更新三仓的接入”。本表给出可执行范围与完成判据；批准后按 P1–P6 执行。候选发行号 `0.8.0`，不得覆盖既有发行包或三仓释放版。

## 1. 用户看到的功能

在“平台与接入”中，只增加一个全局 **“一键更新所有平台”** 按钮。自动发现已有有效接入配置的平台，点击后展示所有目标的一份完整更新预览；确认一次，连续完成目标版本固定、依赖准备、配置切换、软件接线核对、受影响检查、治理记录与 Git 入库。不要求逐个平台点击、不要求在多个页面逐项选引擎、逐个切专家或手改 JSON。

所有符合条件的平台自动纳入，按平台顺序执行、分别保存结果；尚未接入者明确列为跳过并给原接入向导入口。某平台缺账号/本体/权限或检查失败，只将该平台记为待补/失败；其他独立平台可以继续。共享资源或工作区基线被外部改变时暂停批次，重新预览，不覆盖他人改动。

进度提供停止、继续及恢复旧接入配置。状态明确区分：无变化、更新中、更新并验证通过、已保存但待补、已停止、失败已恢复、外部变化需核对。只有目标版本、真实检查与入库读回满足本表条件，才显示更新完成。登录、UAC、许可和系统重启仍需要使用者操作；没有可用接口时列出具体待补项。

## 2. 更新范围与规则

1. **三仓目标固定一次。** 从工作区三仓 registry、current 和不可变 manifest/依赖锁读取本次目标，记录各文件/释放版摘要。跟进工作区已明确采用的共享 current；不因盘上存在更高版本就自动采用未切默认的候选。引擎、契约、检查器及调用判据按依赖与接口配对固定。不在执行中重新解析 current 换版。
2. **tool / agent 选版。** 将该平台需要更新的顶层选择列入预览，保留或更新哪些显式覆盖项由同一预览明确显示；默认跟进共享现行版，可勾选保留个人固定版本。新专家自然可发现，不批量复制专家内容到平台。专家内部精确 tool-lock、旧释放版和在途 run-lock 不改写；旧任务续跑仍按原锁。
3. **software 接入。** 更新需要变化的连接器/网关引用，核对本平台既有绑定与目标配方。配方文本的更新与软件本体匹配、功能真实调用分别报告。已有程序不因配方变新就盲目下载安装最新版；仅按冻结配方的明确版本/获取方法准备依赖，缺本体或接口保留待补。
4. **依赖环境补齐。** 同时解析现行 `runtime.environmentLock` 与选中专家/工作流/技能依赖闭包中的 `x-runtimeRequirements`，只取实际选用的精确依赖，不将整个历史技能池灌入环境。检查版本冲突、解释器兼容和 profile。环境归属统一选 BP-1 §1.6③：目标 platform/runtime；资源只声明文本。保持 runner 密封脚本环境与资源操作环境的边界，不将新专家工具库强塞进原密封环境。新增/变化环境按 BP-7 留重建配方、逐文件摘要和一次真实恢复；未变且证据有效的环境复用。
5. **上下文配置。** 增加有效上下文窗口及来源的表单/读回，接入 `contextWindowTokens` 和该平台自己的 `resourceEnvironmentManifest`。能从已声明平台设置确定的值自动回填；缺失时在同一预览提示补填，不用虚构大窗口放行预算。运行固定提示预算继续服从共享契约，外层历史与工具返回另计。
6. **增量验证。** 复用现有认证选择器、哈希缓存、conform 与调用检查；未变化且来源/摘要有效的证据沿用，变化/未完成项重测。补齐新依赖环境和上下文政策的影响指纹，不能仅凭文件路径相同复用旧结果。首次接入或明确引擎/契约大版本升级才全矩阵；普通更新不作为重新接入。规则变化可能影响很多格，预览如实列数量与原因，不承诺固定秒数。
7. **回滚与恢复。** 变化前保存可回滚 Git 基线和带哈希 checkpoint；先准备与校验新环境，再整批激活配对配置。取消发生在安全子步骤之间，重复继续不重复安装/恢复/派发。失败恢复本次仍由操作拥有的旧配置，不覆盖外部新改；准备过的新目录、证据保留可读，不自动删除。多个配置文件使用既有事务及恢复记录，不宣称整个磁盘原子写入。
8. **Git 入库。** 自动提交仅包含预览列明的治理文本与目标平台配置，凭据、运行产物、环境和本体排除。不混入无关暂存。推送默认沿用用户此前明确启用的仓库策略；没有推送授权/远端/登录时显示待入库，不绕过也不称最终完成。正常推送、拒绝强推；读回本次 HEAD、治理白名单状态、远端一致和回滚提交早于激活时间。

按钮面向更新既有接入；尚无有效接入配置的平台仍走原接入向导。产品由用户管理层选择目标平台执行，每个平台有自己的配置、环境和一手证据；Codex 本轮开发不直接替其他生产平台采纳，也不互抄结论。

## 4. 冻结完成判据

- **正常更新**：在隔离测试工作区中，旧配对栈/旧专家覆盖更新到本次固定目标；三仓接入、需要变化的资源环境与上下文设置可回读；未列入目标的平台、共享 current、不可变释放版及在途锁逐字节不变。
- **失败边界**：有意义的依赖冲突、解释器不兼容、缺本体/原生接口、外部改动、坏封条和超预算输入不得刷绿。系统登录/权限缺失列为待补。环境安装/恢复失败不能激活半配对配置；配置切换中断可恢复旧配置。
- **继续与批次**：停止后可从同一固定计划继续；已完成子步不重复副作用；有外部变化拒绝旧计划。两个隔离平台使用各自环境和证据，一方待补不冒充另一方成功，也不妨碍独立步骤完成。
- **增量**：同内容再次更新得到无变化结果；修改一个资源只检查真实受影响闭包，坏旧证据重测。资源环境文件同路径但内容改变会使受影响证据失效。未达到首次/大版本条件时不强制全矩阵。
- **界面与发行**：新按钮通过 GUI→IPC→统一执行器实际运行；新便携 EXE 在隔离工作区真实核对配置、产物及哈希。厂商客户端调用与模型业务不以测试 fixture/自建服务冒充。新发行号不覆盖旧包，文档写清操作、恢复和待补状态。
- **收口**：必要回归与单条管理台 conform 无新增未解释失败；源码和治理记录分别入对应 Git 仓，红线扫描通过，四项 Git 读数可回读。功能完成不等于所有生产平台已由本轮完成采纳。

批准时冻结以上判据；执行期非阻断新发现只登记，收口后另案，不在本轮顺手修复。

## 5. 有序 P 表

估算 6 段、合计 12 小时；每 P 约 2 小时，内部 3 个子块。时长是安排估算，不是要求连续工作或额外等待；每子块末均保存完整产物、停止探针并可安全停手。

| P | 子块（各自安全停点） | 产物与完成判据 |
|---|---|---|
| P1 固定更新契约与回滚基线 | ①核对两个源码仓/版本占用与现存改动；②固定三仓目标、平台资格、覆盖策略和状态；③保存实施表/测试范围/Git 基线 | 计划可预览、目标与依赖哈希固定；默认不执行、不改生产平台；回滚锚可读 |
| P2 补齐资源环境与窗口配置 | ①统一依赖闭包与冲突/解释器判断；②资源环境准备及真实恢复；③配置表单/读回与影响指纹 | 新旧依赖格式均可用；平台隔离；未变复用；环境/窗口内容变更不会假复用证据 |
| P3 串联一键更新执行器 | ①配对栈/顶层选版/软件绑定差异；②一次确认的连续事务、停止/继续；③失败恢复、平台独立批次、Git 收口 | 正常更新完整走通；失败/待补不称成功；无重复副作用/半配对，外部改动受保护 |
| P4 增加管理台入口与结果 | ①一个全局按钮/自动纳入已接入平台；②更新预览、个人固定项及必要补填；③统一进度、继续/恢复与结果明细 | 用户通过单一入口完成所有已接入平台更新；状态和作用域清楚；未接入者指向原向导；无需手改 JSON |
| P5 必要回归与真实界面验证 | ①正常/冲突/中断/恢复用例；②两个隔离平台、内容增量与旧锁验证；③单条 conform 及新便携 EXE | §4 判据证据可读；复用既有无改动证据；不重跑生产平台全矩阵，不冒充外部厂商成功 |
