## 4. 能力语义（本轮新增，全部有机器判据）

1. **F-1 上下文注入**：注入集 = 本次 run 的工作流声明的 `dependencies.skills`（场景点名时以场景为准，未点名回落工作流声明），由 prepare 算成 `execution.contextSkills` 钉进锁；读不到/摘要不符 ⇒ `CONTEXT_UNRESOLVED` / `INTEGRITY_MISMATCH`，且发生在锁提交之前。
2. **pack 是集合不是文档**：`dependencies.packs` 贡献的是该 pack `skillVersions` 里本次已钉住的**成员技能**，不贡献文本（八个 pack 释放本来没有正文；把它当文本读会打死第一个 prompt 阶段）。
3. **F-2 场景**：`scenarios[<id>].{summary, add, replace, remove, order, gates, skills, defaults}` + 顶层 `requiredStages` / `defaultScenario`（v3 必填）。三条硬界（C-1）：不得引入枚举外动作、不得移除 `requiredStages`、只能增删门禁实例。展开结果以 `expandedGraphSha256` 入锁，**计入 promptRef 目标与门禁名**（T-P1 的 190 对结构 diff 定下的：只算阶段 id 会让两条内容不同的流程撞同一个哈希）；续跑时 `plan()` 重算并比对，不符即 `VERSION_CONFLICT`（这是 BP-4 1.3 的 4.3① 第一次有可比对的确定量）。
4. **档位可见（D-62）**：`execution.rigorSource` 区分"显式写了"与"没写＝缺省草稿"；claim 带 `rigor/rigorSource/gated/frozen/tierNotice`。**没有为可见性改动任何流程的提示词字节**。
5. **执行面六格**：派发必须有被复验的封套摘要（D-53）、环境根拼错＝派发前的入参拒绝（D-56）、被拒的调用记 `not-dispatched` 可干净重放（D-51）、宿主进程死后 `next` 说"结果未知"而不是"还在跑"（D-64，只读探针、不回收不重放）、严格 JSON 报错带位置（D-34）、档位可见（D-62）。
