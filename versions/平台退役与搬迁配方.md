# 平台退役与搬迁配方（v1）

> 2026-10-29 订立，配合「平台 runtime 瘦身与退役配方」P 表（P2 治理文本）。
> 适用范围：codex / dsh / workbuddy / zcode / doubao / qoder / qoder-cn 七个运行平台。
> 注（2026-10-30）：本文 runtime 读数是 2026-10-29 基线；平台 runtime 未因 Wave 1 改变。

## 1. 目的

runtime 目录是各平台最大的空间占用来源（2026-10-29 实测七平台合计约 20.9 GB，占平台目录 60%–86%）。
本配方回答两个问题：**哪些能删、删了怎么重建**，以及**平台目录要搬走/退役时如何操作**。

## 2. runtime 内容分级

| 级别 | 内容 | 可否删除 | 依据 |
| --- | --- | --- | --- |
| **A 缓存类（可重建）** | `manager-environments/<uuid>/host`、`sealed`、`manager-resources/<uuid>/active`、`py-env`、`script-env`、`wsl-py-env`、`manager-node`、`nodejs-cache`、`nodejs-global` | 可删，按 §3 重建 | BP-7：可重建件交「重建配方 + 逐文件 sha256 + 一条重建命令」 |
| **B 演练副产物** | 非 `registered-` 前缀的 `*restore-drill*` 目录 | **可删**（本轮已执行） | 见 §4 判定规则 |
| **C 备份登记类** | `registered-restore-drill-*/{host,sealed}`、`inbox/backup/<platform>/**`（含 REBUILD.json / RESTORE-VERIFIED.json / wheels / zips） | **保留** | BP-7：没演练过的按未备份处理；已登记者即为备份本体 |
| **D 运行证据类** | `runs/<run-id>/`（run-lock.json、事件流、产物哈希）、`maintenance/`、`software/` | **保留** | 红线：哈希可回读、run 必钉版 |

## 3. 一条重建命令（A 类）

环境类对象由架构管理台的 onboarding 铺设，重建时不手工拷贝：

```bash
# 在用户终端执行（会话内 spawnSync 对 .exe 存在 EBUSY 限制）
node architecture-manager/src/cli.mjs onboarding prepare --platform <platformId>
node architecture-manager/src/cli.mjs onboarding seed    --platform <platformId>
```

重建依据：`<platform>/runtime/../inbox/backup/<platform>/**/REBUILD.json`（含 `requirements` 钉版清单 + 逐 wheel sha256 + `wheels/` 目录），
按 D-172 机制走 venv/wheel 复用续装，无需重新下载。

## 4. 演练副产物（B 类）判定规则

1. 目录名含 `restore-drill` **且不以 `registered-` 开头** → 判为演练副产物；
2. 前置条件：该环境 UUID 在 `inbox/backup/<platform>/` 下必须同时具备
   `REBUILD.json`（重建配方）、`RESTORE-VERIFIED.json`（演练已验证）、`wheels/`（依赖字节）；
   三者缺一 → **不删**，按 BP-7 视为未备份；
3. 删除粒度：目录级分批（单命令不超过 4 个目录），不使用通配批量删除；
4. 已知残留：WSL（LX）创建的 `bin/python*` 符号链接在 Windows 侧拒绝删除
   （`fsutil` 报错误 5、PowerShell/.NET 报错、Git Bash `rm` 报 Permission denied），
   目录内其余内容已清除，残留链接体积可忽略，登记为待清理项，需 WSL 内或管理员权限处理。

## 5. 平台搬迁 / 退役顺序

1. 证据归档：`runs/` 已完结 run 压缩（zst）后原件逐包 sha256 复算一致再删，指针改指归档包；
2. A 类缓存删除（§3 可随时重建）；
3. B 类演练副产物按 §4 删除；
4. 剩余为 bridge 配置 + C/D 类文本与证据，整个平台目录可整体移动或删除；
5. **迁移约定**：平台 config 内一律使用相对路径，迁移语义为「整根 `E:\ai` 一起搬」；
   架构语义上平台目录不脱离根单独存在，单平台搬走会破坏共享仓相对引用。

## 6. 本轮执行记录（2026-10-29）

- 按 §4 判定后删除 27 个演练副产物目录，释放约 **6.4 GB**；
  runtime 合计 27.4 GB → 20.9 GB，venv 数 92 → 63（剩余均为 host/sealed/registered/active/py-env/script-env/wsl-py-env）。
- **偏差登记**：BP-6 要求「入库先行（commit 早于破坏性动作）」，本轮删除先于本文件入库执行，
  已如实记录，后续同类操作必须先落盘治理文本并 commit 再删除。

## 7. 本轮新登记缺陷（非阻断，另立方案修复）

  但 codex / dsh / qoder 为 `10EC6F3C6D744767`、zcode / doubao 为 `A2904662A8630BAF`，即 **5/7 平台副本落后于真身**。
  `cli_client.py`、`mcp_service.py`、`platform_provider.py` 三文件 7/7 一致，无漂移。
- **D-175 备份区膨胀**：`inbox/backup/` 实测 3,988 MB / 95,092 文件，其中含 venv 完整副本（含 `restore-drill` 内文件）。
- **D-176 LX 符号链接残留**：见 §4.4，需 WSL 内或管理员权限清理。
