## 使用方式

用户选择自己的架构工作区，在“平台与接入”中选择已有平台修复或填写新 ID，选择 Python、已就绪的 WSL 隔离环境和软件本体位置，核对计划并确认。管理台连续处理配置、独立环境、备份恢复、provider、能力实测、标准 CLI/MCP 入口、认证、治理文本与 Git 提交；失败停在具体步骤并保留恢复点。

接入维护不需要 AI 会话、手写 JSON 或控制台。系统登录、许可、提权、系统组件安装后的重启由用户在对应界面处理，接入确认不授权后续业务的外网扫描或永久提权。

支持的通用入口是标准 JSON CLI 和 MCP stdio。客户端工具回环必须匹配随机 challenge、平台、配置和版本摘要。六个厂商原生客户端的注册状态分别列示，标准入口通过不代表它们全部注册成功；业务模型输出另行执行。

## 实现与边界

- 延续 Electron/React/Node IPC 与计划事务内核；所有配置写入保留基线、checkpoint、审计和回读。
- 平台发现使用统一登记规则；新 ID 受格式、平台身份、工作区归属、链接边界与版本锁检查约束。
- 环境选择 BP-1 第三条归属路，落在所属平台 runtime；备份落 inbox/backup/所属平台，并实际按登记命令恢复和复算。
- 三仓形态和已发布版本只读规则保留。runtime-contracts 1.5.2 在三处 schema 用规范 ID 取代六平台枚举；引擎继续校验请求身份等于可信配置，不能借此访问其他平台。
- 软件继续由 _connector 和平台 provider 派发，架构 platformId 与配方操作系统 platform 分开记录。软件版本基线不等于所有业务操作已经验证。
- 首次接入保留完整矩阵；后续按内容摘要及受影响单格复验。缓存显示原检查时间，不冒充刚执行。
- 打包外部 Python 辅助脚本位于 app.asar.unpacked，解决检查程序无法读取 ASAR 内脚本造成的全体 check-failed。

本轮不扩展到手动 Git 页旧输入框兼容修复、VeraCrypt 卷操作冻结、六厂商全部原生注册或原有国际化缺口。发现项按执行记录登记，后续另立 P 表；它们不能被本轮标准通路结果刷成已完成。
