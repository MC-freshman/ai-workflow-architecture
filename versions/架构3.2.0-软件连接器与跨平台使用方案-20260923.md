# 架构 3.2.0：软件连接器与跨平台使用方案

> 版本：**3.2.0（方案稿，未实施）**  
> 日期：**2026-09-23**  
> 前置基线：`versions/架构3.0.0.md`、`versions/架构3.1.0.md`、`versions/架构基本原则.md` 1.3  
> 本文性质：**目标方案 + 执行边界 + 交接约束**，不是实施授权。进入执行前须按配套 P 表逐步批准。

## 1. 这次要解决的问题

3.0.0 已有 `software-call`、软件配方、能力快照和参考 `_gateway`，但软件仍主要停留在“配方可解析、平台可登记”的阶段。3.1.0 已将真正的连接器/MCP 方向留给后续版本，当前还存在三类断点：

1. 工作流能够识别软件，但没有一套稳定的跨平台调用入口。
2. 各软件的 CLI、MCP 服务、HTTP 服务和 GUI 会话形态不同，不能用一个假定的 `--tools` 接口统一它们。
3. 用户需要正常打开软件、使用命令行或 GUI；自动化调用不能变成使用软件的唯一入口。

3.2.0 的目标是让同一份软件配方在各平台通过统一连接器调用，同时保留用户的原生使用方式。

## 2. 执行平台与额度转移

本方案按 **Codex → Qoder** 交接编写：

- **源平台：Codex**。只负责生成方案、基线摘要、交接包和 SHA-256 清单；不在本轮直接改 Qoder 配置，不读取 Qoder runtime。
- **目标平台：Qoder**。负责实施软件连接器、安装/核验平台本体、运行真实调用和出具平台自己的证据。选择 Qoder 的原因是它已有 `softwareRoot`、`softwareRuntimeRoot`、`softwareGateway`、平台内锁表和六件软件的本体登记，迁移成本最低。
- **交接载体：`handoff-bundle/v1`**。建议落在 `E:\ai\qoder\runtime\maintenance\20260923-3.2.0\handoff-bundle\`，包含 `manifest.json`、版本锁摘要、方案哈希、待执行 P 表和逐文件 `SHA256SUMS`。Qoder 只读交接包，不能直读 Codex 的 `runtime/`。
- **版本一致性**：Qoder 在开始 P2 前重新解析三仓 `current.json`、方案哈希和交接包哈希；不一致即 `HANDOFF_VERSION_MISMATCH`，停止写入，不静默换版。

如果 Qoder 会话暂时不可用，交接包可以交给其他已接入平台，但目标平台必须自己完成配置、自测和证据，不能复用 Qoder 的“已通过”结论。

## 3. 目标架构

```text
共享 software 仓
  registry / current / versions / manifest / recipe / schema / selftest
              │只读解析
              ▼
平台 software-connector
  MCP-stdio / MCP-HTTP / CLI adapter / desktop-session adapter
              │平台本地调用
              ▼
平台 runtime/software
  本体、解释器、凭据引用、锁、日志、请求响应、产物证据
              │
              ├─ 工作流调用：software.call
              └─ 用户直用：PowerShell、开始菜单、原生 GUI
```

### 3.1 共享层：`software` 仓

共享仓继续只保存可冻结、可跨平台共享的文本：

- `registry.json`、每个软件的 `current.json`；
- `manifest.json`、recipe、输入输出 schema、selftest、说明书；
- `capabilities.snapshot.json` 及其哈希；
- 连接器元数据和逻辑操作名；
- 版本依赖与 `SHA256SUMS`。

软件本体、凭据、平台绝对路径、运行日志和大缓存继续按 BP-1/BP-7 留在平台 runtime。

每个软件的 manifest 增加或统一以下语义：

```json
{
  "transports": ["cli-wrapper"],
  "userModes": ["direct-cli", "mediated-call"],
  "operations": {
    "scan": {"inputSchema": "schemas/scan.input.json", "outputSchema": "schemas/scan.output.json"}
  },
  "connector": {
    "adapter": "generic-cli",
    "sessionModel": "per-run",
    "requiresConsent": false,
    "exclusiveResources": []
  }
}
```

`connector.adapter` 是逻辑名称，不能写平台绝对路径。具体路径由平台配置和本体登记解析。

### 3.2 平台层：一个连接器，多种适配器

首版以现有 `software/_gateway/versions/1.0.0/gateway.py` 为兼容基线，使用 Qoder 已登记的 Python 3.9 解释器和平台内 `software-gateway.json`。3.2.0 新增的共享程序件建议命名为 `software/_connector`，仍采用版本目录、`SOURCE.json`、双向 `SHA256SUMS` 和 `current.json`；它是共享程序件，不进软件 registry。

连接器提供统一的 MCP/JSON-RPC 入口，底层按 manifest 选择适配器：

| 软件形态 | 连接方式 | 适配器做什么 |
|---|---|---|
| CLI 工具 | `cli-wrapper` | 从 recipe 解析命令、参数、工作目录和输出 schema，调用平台本体 |
| 原生 MCP 服务 | `mcp-stdio` / `mcp-http` | 转发标准 MCP 请求，保留原始工具名和结构化结果 |
| HTTP 服务 | `mcp-http` 或受控 HTTP adapter | 连接平台内端点，检查 host、端口和授权 |
| GUI 或长生命周期程序 | `desktop-session` | 打开、查询、关闭会话；需要人工时返回 `INTERACTIVE_REQUIRED` 或 `SESSION_READY` |

连接器不为第三方软件虚构能力。软件没有 `--tools` 就不询问 `--tools`；能力通过 MCP `tools/list`、recipe 声明和冻结快照分别验证。

### 3.3 统一调用接口

3.2.0 沿用 `ai-software-call/v1`，将平台连接器固定为以下接口：

```text
software.list
software.describe
software.health
software.call
software.session.open
software.session.status
software.session.close
software.artifact.get
software.evidence.get
```

`software.call` 的最小入参为：`softwareId`、释放版本、`operation`、结构化 `arguments`、`profile`、项目根、`consentToken`（需要时）和 `idempotencyKey`。

统一返回状态：`accepted`、`running`、`succeeded`、`failed`、`replayed`。沿用 3.0 的拒绝码：`CAPABILITY_UNAVAILABLE`、`SOFTWARE_NOT_INSTALLED`、`SOFTWARE_DRIFT`、`CONSENT_REQUIRED`、`SOFTWARE_BUSY`，并补充 `INTERACTIVE_REQUIRED`、`CONNECTOR_UNAVAILABLE`、`INVALID_ARGUMENTS`。

### 3.4 用户直用与自动化调用共存

用户可以继续：

- 在 PowerShell 或终端直接使用 CLI；
- 从开始菜单、桌面或原生命令直接打开 GUI；
- 在平台中请求“用某软件处理某目录”，由连接器完成自动化调用；
- 对 GUI 软件先打开会话，再由用户在软件界面完成交互。

用户直用不伪装成工作流 run。若要把外部操作导入项目，只建立“外部会话附着”记录，记录软件版本和产物哈希，不伪造工作流血缘。

### 3.5 权限、锁与证据

每次中介调用固定记录：

- 软件释放版、manifest 哈希、能力快照哈希；
- profile、目标根、网络范围和凭据引用；
- 授权摘要、幂等键、连接器版本；
- `request.json`、`response.json`、`software-called` 事件和产物哈希。

profile 首批固定为 `readonly`、`workspace-write`、`external-access`、`administrator`。提权、外网、凭据和挂载操作必须逐次授权，不能用常驻管理员授权替代。

锁仍是平台内锁：`per-run`、`pooled`、`singleton`、`exclusiveResources`。BP-4 1.3 不要求跨平台互斥；跨平台只通过带哈希的交接包传递项目状态。

## 4. “每个软件是否都要单独写 MCP？”

**不需要每个软件单独写一套 MCP 服务。** 推荐形态是：

1. **一个共享连接器运行时**：负责 MCP/JSON-RPC、版本解析、权限、幂等、锁、证据和错误码。
2. **每个软件一份 adapter 描述**：声明 transport、operation、参数 schema、会话模型、side effects 和授权要求。
3. **只有底层协议确实不同的软件才写薄适配器**：
   - CLI 软件复用通用 `generic-cli`，通常只写 manifest 和参数映射；
   - 原生 MCP 软件复用 `mcp-proxy`，不重复实现工具逻辑；
   - GUI/长会话软件复用 `desktop-session`，只实现启动、状态、关闭和人工交互边界。

因此，六个软件不等于六个 MCP 服务。理想结果是“一个连接器 + 六份声明 + 少量特殊适配器”。只有软件本身拥有独立 MCP 服务、独立认证或独立会话协议时，才为它保留一个独立进程；那仍然由统一连接器托管，不能绕过共享契约。

## 5. 首批软件范围

按风险和自动化程度分三层：

1. **第一批**：`dirsearch`、`mysql-cli`、`wireshark-cli`。先做只读或工作区限定调用，最适合验证通用 CLI adapter。
2. **第二批**：`nmap`。加入目标范围、网络访问和外部副作用授权。
3. **第三批**：`burp-suite`、`veracrypt`。优先做 MCP/HTTP 或桌面会话，不强行改造成 CLI。

能力快照没有冻结、连接器健康检查未通过或本体未登记时，统一返回 `CAPABILITY_UNAVAILABLE` / `SOFTWARE_NOT_INSTALLED`，不以配方存在代替可调用性。

## 6. 交接后的实际操作方式

Codex 完成 P1 后，向 Qoder 交付：

```text
handoff-bundle/v1/
  manifest.json
  source-current.json
  target-requirements.json
  architecture-3.2.0-plan.sha256
  P-TABLE.sha256
  SHA256SUMS
```

Qoder 的第一条命令是“读取并校验交接包”，不是直接改配置。校验通过后按 P2…P8 执行；每一步的产物先落在 `qoder/runtime/maintenance/20260923-3.2.0/`，完成平台自证后再提交治理文本和配置面。

## 7. 3.2.0 完成判定

本轮完成必须同时满足：

1. `software-call/v1`、连接器 adapter schema 和版本锁可被 repo-lint 校验；
2. Qoder 真实跑通第一批三个 CLI 软件，各自产生 request/response/evidence 和哈希；
3. 至少一个原生 MCP 或 GUI 会话路径经过真实拒绝/成功边界测试；
4. 用户仍可从终端或 GUI 直接使用同一批软件；
5. Qoder 的软件能力地板、配置、版本和证据由 Qoder 自己出具；
6. 交接包可回读，版本不一致会拒绝，未向 Codex runtime 建立直读依赖；
7. 治理文本、共享程序件和平台配置在根仓提交，收口报告包含 HEAD、白名单 `git status`、远端一致性和入库时间。

未完成的特殊软件适配器、其他平台接入和观察期问题进入维护台账，不能被写成“所有软件已经可调用”。

## 8. 关键风险与取舍

- 软件本体继续不可入 Git；必须按平台放在 `runtime/software/`，并在 `inbox/backup/<platform>/` 留重建配方或副本登记。
- 共享 registry 的新增操作会改变能力并集；每次发布后只做一次并集复算，单个软件变更只跑 `conform --only <softwareId>`。
- 连接器故障与软件本体故障分开报错，不能把 `CONNECTOR_UNAVAILABLE` 伪装成 `SOFTWARE_DRIFT`。
- 用户直用与自动化调用的权限边界不同；自动化调用必须可审计，直用不强行套工作流锁。
- 版本发布、平台采纳和用户日常使用是三件事；发布新版本不自动改变任何平台配置。
