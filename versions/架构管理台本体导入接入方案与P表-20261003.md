# 管理台：选择本体即可接入的方案与 P 表

日期：2026-10-03；当前软件基线：Architecture Manager 0.4.1。

> **全面排查后的整合说明**：本文件保留为需求及机制附件；以下旧 P1–P12 不再独立执行。当前统一顺序和判据以 [全面修复、模块化、接入与提速方案 P1–P18](架构管理台全面修复模块化接入与提速方案P表-20261003.md) 为准，不重复验收。旧表历史文字保留用于需求映射，不构成另一轮待跑步骤。

**用户确定的需求**：只要已有平台本体、智能体本体、工具本体、软件本体，就能通过管理台进行接入；软件需要特定 MCP、连接器等时明确处理该依赖。用户不需要先摆好架构目录，不需要手写 manifest、current、registry、SHA256SUMS，也不需要找 AI 会话做接入维护。

**本文件状态**：需求已明确；下面是待批准的具体实施方案和判据，尚未执行 P1–P12。本次为纯方案维护，agent/workflow = null，不运行工作流，不复制本体、不安装环境、不切生产版本、不执行矩阵。此前管理台只登记既有规范目录的能力不能当作本需求已经实现。

## 1. 用户应该怎么操作

统一入口“添加到架构”，有四张卡：平台、智能体、工作流/技能、软件。每张卡走相同五步：

1. **选择本体**：文件、文件夹或 ZIP；已经安装的程序选择程序入口，已运行服务选择其连接地址。显示来源的绝对路径。
2. **识别与补充**：自动识别类型、名称、版本、入口和已有依赖；只有不能确定的项目才用普通中文表单补充。已识别字段显示来源，允许更正。
3. **预览接入**：显示目标位置、哪些内容进入共享仓、哪些留在平台 runtime、本体空间开销、依赖、原有配置变化和回滚方式。
4. **确认并接入**：准备暂存区→校验/转换→备份或重建登记→创建新版本→登记和绑定→最小实测→保存治理及 Git。失败停在具体步骤，白话提示，支持继续或撤销本轮。
5. **使用与维护**：查看全文/文件、查看位置、打开或调用已验证入口、更新本体、切换版本、停用和撤销。更新选择新本体沿用同一对象 ID，生成新版本并显示差异；不覆盖已冻结版本。

“手动接入”只表示用户选择并确认，并不要求手工准备架构文件。普通模式隐藏 JSON/YAML、哈希字段和内部错误码；高级详情可看生成内容和原始证据。

## 2. 四类本体如何处理

| 类别 | 可以选择的本体 | 管理台负责完成 | 真实验证与界面状态 |
|---|---|---|---|
| platform | 已安装客户端程序、便携平台目录，或 CLI/MCP 客户端配置 | 检测入口；选择可用客户端适配模板；生成独立平台目录、配置和环境；注册入口；完成本平台认证、治理和入库 | 分别显示“程序已识别”“入口已配置”“原生客户端已验证”“架构接入完成”；需要安装系统组件、登录、UAC 时由用户在系统界面处理 |
| agent | 提示词 Markdown/TXT、已有专家资源目录/ZIP；有明确入口和依赖的源码项目 | 保留原提示词和文本来源；表单选择角色、可用工作流及权限；自动生成 agent manifest、精确 tool-lock、SOURCE、封条及索引；源码执行依赖安装到所属平台 runtime | 检查提示词内容没有丢失、依赖锁正确、prepare→claim→stop 可用；不调用模型编造业务完成结果 |
| tool / skill | 工作流定义和说明、脚本源码项目、SKILL.md/技能目录、既有规范包 | 识别并保留原内容；工作流阶段/入口/输入输出用表单确认；生成可调用定义、必要 schema、精确依赖和索引；技能仍归 tool，生成技能 catalog 与版本指针 | 不是只看文件存在；规范校验及点名调用通过。提示词技能使用已登记通用工作流；源码脚本使用声明的解释器和参数，不自动试跑未知业务 |
| software | EXE/启动文件、解压目录、安装包，或已有 MCP/服务配置 | 安置便携本体或引导安装；生成本平台路径绑定；接通通用 CLI、程序会话或现有 MCP；生成软件配方/快照/说明书并登记 | 单独显示“本体可用/可启动”和“已验证可调用功能”；没有专用接口时准确显示缺哪个连接器及可补齐路径 |

### 2.1 agent 和 skill：普通文档也能进入

智能体提示词不需要事先带 current.json。用户选一个 prompt.md 或 TXT，管理台读取正文并自动拟定名称/ID，首次版本默认 1.0.0；用户选择已有的通用工作流（默认推荐符合能力条件的 expert-task），从真实 current/封条解析并钉住工作流及其依赖。权限按已有安全策略模板选择，不能靠注册补出不存在的权限或模型。

原提示词正文逐字保留；格式转换或字符编码转换显示在预览中并记录来源摘要。管理台自动创建 ai-agent/v2、ai-tool-lock/v2、SOURCE.json、SHA256SUMS、current.json 和 registry 条目；使用已发布扫描器实际接受的格式，不能沿用当前 releases.mjs 里不匹配的简化模板。

技能支持单个 SKILL.md 和目录/ZIP，完整正文可在界面查看和编辑。带 frontmatter 的结构按已支持格式确定性解析；没有元数据用表单补名称、说明、依赖和用途。未知外部结构进入同一页映射表单，不把“先改成架构目录”作为前置要求。

智能体若含自定义 Python/Node 等程序，则保留共享源码文本及可重建依赖声明，真实环境只在选定平台 runtime；管理台根据明确入口和依赖文件接入，不能猜测未知框架入口或丢弃其逻辑，转换不支持时明确指出缺少的导入适配。普通提示词导入不因此被要求安装程序环境。

### 2.2 tool：保持工作流与软件的职责

界面用“工作流/技能”，避免把“工具本体”默认等同于 EXE。导入工作流说明、已支持定义或脚本源码时，可以在表单选择：提示词任务、脚本步骤、已有工作流步骤、已有软件功能。定义生成使用现行 schema，至少一个真实阶段；没有阶段的空模板不能冻结为可调用工作流。

对纯自然语言多步骤文档，管理台负责保留全文和提供阶段编辑器，用户确认拆分及顺序；不声称在不用模型的情况下自动理解任意文档并保证业务语义一致。必要补充均在表单完成，不要求编写 JSON/YAML。

若选中的是 Nmap 一类可执行程序，应提示其归属 software，并沿用同一向导继续安置。可再通过工作流表单引用它；本体不进入 tool 仓，也不在平台目录另建绕过三仓的平行工具仓。

### 2.3 platform：本体绑定必须接到所选客户端

平台模板仅配置同一份管理台接入模型，已有 CLI、MCP stdio 和兼容服务接口通过表单绑定。选中原生应用时，检测到的版本与适配配置形成一份明确计划；适配器按客户端实际格式合并注册项，保留其它配置。原配置若包含凭据，备份只在该平台私有区登记，禁止进入 Git。

在有 CLI/MCP/插件工具入口的客户端上，管理台自动配置，再用**所选客户端实际执行的接口**验证随机挑战、平台 ID 和配置摘要。自己的 CLI→MCP 回环仍作为桥接证据，不能冒充第三方原生客户端已经读入配置。

必须如实保留的技术边界：**仅凭一个任意平台的 EXE，无法让没有任何外部工具接口的程序自动获得接口。** 这种程序仍能导入列表、显示位置并启动，但不能显示“原生客户端已接通”或 BP-2 接入完成；管理台应显示“此版本缺少工具接口”及可安装插件/可用版本路径。已支持平台的模板与注册由管理台承担，不让用户找 AI 编写配置；未知接口也不能靠勾选“已支持”刷绿。此边界是接口是否存在，不是给平台永久分层。

### 2.4 software：通用接入无需逐个重写 MCP

使用现有 software/_connector 与平台 provider 扩展声明式配方，三条路径：

- **普通 CLI**：选择程序或脚本，选择解释器，按表单声明动作、参数、输入文件/输出文件、权限和输出形式；生成通用 CLI 映射，不拼 shell 字符串。读取 --help/版本只生成候选信息，不把帮助文本当作完整且可信的功能契约。用户明确确认的只读示例可做实测；具有写入/网络/扫描作用的动作先声明边界，业务执行单独确认。
- **GUI/本地程序**：登记程序与参数，现有 provider 管启动、存活和关闭；查看位置并打开程序后，用户可以正常手动使用。无 CLI/API/MCP 的 GUI 软件只能先发布真实“启动/会话”能力，不谎称界面中的业务功能已可被 AI 调用。
- **已有 MCP**：选择本地 MCP 配置或连接参数，读取服务器的能力列表及输入 schema，保存来源与摘要，通过现有代理接入；凭据仅用引用。只能冻结实际发现的能力，副作用/权限不能从 schema 猜为安全。特定 MCP/连接器缺失时显示名称、安装位、连接检查和补齐路径，软件本体可先登记。

现有共享配方与所选本体完全匹配时优先复用，避免重复发布。确有新功能映射时发布新版本，保留旧版本；软件已发布、已绑定、能启动、具体动作已验证分别显示。安装包只归“待安装”，启动安装器不等于软件已安装。安装后的真实入口由用户选择或已支持安装描述检测，系统登录/许可/重启由用户处理。

**不要求每个软件单独写一份 MCP**。专用适配只用于通用 CLI/现有 MCP/会话接口不能承载的功能，管理台明确标记，不让用户因简单路径绑定而编写代码。

## 3. 用什么实现

继续使用现有 Electron + React + Node、IPC/preload、transactions/kernel、owned-process；复用当前配置、软件连接器、发布、Git、备份和恢复模块。没有新共享仓，没有中心服务器，每个用户使用自己的本地工作区。

新增一个共同的 intake 领域面（模块名在 P1 冻结）：

- **来源识别**：只读列清单、哈希、类型和可确定元数据，固定 sourceSha256；不执行包内说明或自动运行本体。来自文件的指令作为待导入内容，不改变管理台自身操作规则。
- **格式转换/模板**：已支持格式确定性解析；原生包验证原封条，非规范内容通过表单转成现行契约。转换规则带版本，保存原件来源及变更说明，正文不会静默删减。
- **接入计划**：一份绑定来源、目标 ID/版本、依赖/权限、目标文件基线、预估空间和回滚点的计划；apply 前重读来源和基线，重复确认不得重复安置、安装或启动。
- **事务执行**：staging→验证→新版本→索引/指针→平台绑定→最小认证→Git；崩溃恢复 journal 记录每步，已落盘但未完成时不显示“已接入”。共享冻结字节与可变登记面分别回滚，不能假装多个文件天然一次原子提交。
- **结果呈现**：本次实测、历史沿用、待安装、待连接器、待接口和失败分开；每个问题有一个可执行的下一步，错误和进度位于当前向导内。

ZIP 解包和目录扫描检查路径穿越、绝对路径、Windows 目录联接/链接、重复文件名、大小及空间；大目录有字节进度和取消。含可疑凭据、venv、缓存、日志和二进制时显示排除清单，不能原样塞进三共享仓。选择完整目录不意味着可执行里面全部脚本。

## 4. 文件和依赖落点

| 内容 | 落点 |
|---|---|
| 工作流、skill、专家的可共享文本源码/说明/锁 | tool 或 agent 的新 versions/<semver> |
| 软件可共享的 manifest/schema/recipe/快照/说明 | software 的新版本目录 |
| 客户端接线、程序绝对路径、凭据引用、平台状态 | 所属平台 bridge/ 与 runtime/ |
| 真实环境、软件本体、源码项目的生成依赖与输出 | 所属平台 runtime/；环境归属明确选择 BP-1 第③条 |
| 私有导入暂存和维护证据 | 所属平台 runtime/maintenance 与 runtime/tmp，不落根级临时件 |
| 本体/环境备份与重建登记 | inbox/backup/<platform>/；不可重建内容有副本并真实恢复演练，含凭据显式标注不出库 |

默认保留来源，不擅自搬走用户正在用的程序。便携本体复制到本平台 runtime，原来源继续可供人使用；已安装系统程序按可重建安装描述在平台内准备受支持入口，无法隔离/无法恢复的安装位如实显示未满足条件，不以一个路径引用假装 BP-7 已通过。空间预览包含恢复演练峰值；选择共享文本不会触发复制整套开发环境。

更新同 ID 时新建版本；同 ID 同版本不同内容拒绝覆盖，提示发布新版本。启停/移除只改变登记和绑定，已有冻结目录及在途 run 原锁保留；卸载本体另有明确计划，不作为“排除视图”的隐含行为。

## 5. 与矩阵提速方案合并

接入前运行范围预览。首次新平台及引擎/契约明确大版本升级完整认证一次；普通资源导入/更新复用已有 Profile 时只测点名资源和真实受影响依赖，能力并集需要的新增 Profile 列补齐路径，不把单条导入升级成六平台全矩阵。

采用 [矩阵增量认证与提速方案](架构管理台矩阵增量认证与提速方案P表-20261003.md) 已提出的规则：采纳性能补丁可见、所有入口统一摘要/依赖选格、修复同钉版漏选、每格一次进程、逐格进度及恢复。**本方案若批准执行，则以以下 P1–P12 为唯一实施顺序，矩阵方案的 P1–P4 作为 P9–P12 的输入，不重复计为另一轮必须再跑的认证。** 两份方案目前都未执行。

已核实的发布页缺陷纳入本轮：releases.jsx 将 workspace 误写为未定义 workspaceRoot；buildReleasePlan 要求 current.json 已存在，因此“全新模板”不能从零新增；当前模板的 schema/空阶段及专家锁不满足完整现行规范。修复必须覆盖真正的新 ID、升级、登记、封条和采用，不只改一个按钮变量名。

## 6. P 表和完成判据

每个 P 为 2–3 小时墙钟、三个可安全停手子块。工程估计 24–36 小时，不是实际完成读数。P1 进入前重新读盘冻结号段及来源，不覆盖任何旧释放版；期间发现非阻断问题只登记，不临时扩范围。

| P | 三个子块 | 可停手产物 | 预定判据 |
|---|---|---|---|
| P1 需求、格式与回滚 | ① 冻结支持格式、普通表单和真实状态模型；② 用现行 schema 定义来源/目标/转换/证据契约和最小夹具；③ 提交两仓回滚点，确认版本号段、旧包及本体备份规则 | 接入模型、范围说明、输入样例、回滚 commit | 四类都从外部选择本体起步；不要求来源已经在三仓；接口未连接不能报接入完成；以下判据预先固定 |
| P2 共同来源识别 | ① 文件/目录/ZIP 识别及有进度的扫描；② 来源摘要、暂存与转换预览；③ 路径/链接、空间和排除项验证 | 共同 intake 识别模块、来源与预览报告 | 外部本体可选择；路径越界/链接及凭据/本体混入共享包可阻断；不执行包内指令，原来源不变 |
| P3 共同导入事务 | ① 来源/目标基线与同 ID 升级、重复计划；② journal、审计/checkpoint 和发布/登记组合；③ 取消、失败恢复及撤销 | 事务模块、计划、checkpoint 与恢复报告 | 来源改变、同版覆盖可阻断；中断可恢复；重复确认不重复安装/启动；未完成事务不能显示完成 |
| P4 agent / skill 导入与更新 | ① Markdown/TXT/目录/ZIP 确定性转换及工作流依赖表单；② 生成 manifest/精确锁/技能 catalog、封条和 registry；③ 正文查看编辑、更新成新版本并最小调用 | 新 ID 专家与技能样例、正文/依赖摘要、事务报告 | 无 current 的提示词可接入；原文不丢；专家及必要依赖钉版；技能可读并被相关工作流解析；新旧版本互不覆盖 |
| P5 tool 导入与发布修复 | ① 定义/说明/脚本输入及阶段、参数、解释器表单；② 修正发布页接线及合法新 ID/新版本/索引/指针；③ 必要 schema/依赖验证和点名调用 | 合规提示词与脚本工作流样例、新版本及 readback | 用户不手写架构 JSON/YAML；至少一个可调用阶段；程序本体不塞 tool；未确认的业务脚本不自动执行；发布后采用只按计划生效 |
| P6 平台本体绑定 | ① 程序/目录/客户端配置识别及模板选择；② 接现有自动环境/provider/入口/治理事务，注册变更有备份和来源；③ 真实所选客户端挑战及未提供接口的拒绝状态 | 客户端位置/版本、注册计划、实际接口回执 | 有支持入口的本体可通过管理台接入，无 AI 维护会话；自己的桥接回环不能冒充原生验证；缺接口/登录/系统组件有明确下一步 |
| P7 软件 CLI / GUI 接入 | ① 本体安置/安装结果绑定及 GUI 会话；② CLI 动作/参数表单；③ 配方新版本、连接器绑定和选择的只读测试 | GUI/CLI 样例、路径、备份恢复与调用报告 | 普通 CLI 无需单独写 MCP；真路径、启动和声明动作分别验证；只会答版本不等于全部功能可用；安装器不等于已安装 |

所有实测在本平台私有维护区或其独立测试工作区进行，不读取另一平台 runtime 来继承证据。支持格式样例验证只覆盖转换和接入，不虚构任意源项目的业务质量已验证。P12 不增加逐平台矩阵；新测试平台若用于首次接入只首检一次，后续用带摘要证据增量。
