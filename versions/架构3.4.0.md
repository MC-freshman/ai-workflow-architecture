## 1. 基线结论

3.4.0 建成一个每位用户独立使用的 Windows 本地管理台。它不建立中心服务器、不共享用户运行状态、不改写三仓已发布字节，也不自动切换共享 `current`。用户选择自己的架构工作区后，管理台从原始文件读取三仓、平台、软件、文档和 Git 状态。

实现形态为 Electron 30.5.1 + React 18 + Vite 5。渲染层使用受限 preload API，`contextIsolation=true`、`nodeIntegration=false`、`sandbox=true`，不把 Node 文件系统或 shell 权限交给 HTML 页面。

## 2. 已实现能力

- 平台：读取六个平台目录和 bridge，生成可逆的本地显示/排除计划，不删除平台目录。
- 三仓资源：读取 `registry.json`、`current.json` 和可用版本，生成版本切换计划；已发布版本不覆盖。
- 文档：读取方案、P 表、台账和顶层要求，显示 SHA-256；顶层治理文件需要额外确认。
- 软件：读取配方、快照、本体位置和 connector 状态；CLI 使用配方声明的版本询问，GUI/MCP 未就绪时返回 `INTERACTIVE_REQUIRED`。
- Git：显示分支、HEAD、远端、ahead/behind、改动和敏感文件扫描结果；提交、推送、备份、回滚先生成计划，推送不使用强制模式。
- 安全写入：文档和共享 `current.json` 指针统一经过 `plan → apply → verify`，写入前检查基线哈希，写入前保存 checkpoint，完成后回读验证；重复执行返回 `already-applied`。
- 审计：本地应用数据目录 `%LOCALAPPDATA%/ArchitectureManager/audit` 记录操作者、工作区、目标、旧/新哈希、checkpoint 和状态，不记录正文、凭据或软件本体。
- 发行：生成安装版和便携版两个 EXE，均可启动；安装版支持安装与卸载，便携版不需要安装。

## 3. 不变边界

管理台源代码与构建目录位于 `E:\ai\architecture-manager`，可直接使用的便携版和安装版复制在 `E:\ai` 根目录。三仓仍是 `tool`、`agent`、`software`，软件仓仍只存配方，不存软件本体。GitHub 凭据由用户本机 Git Credential Manager 或系统凭据管理器处理，管理台不保存账号、密码或令牌。

Git 远端推送、GUI 软件启动、外网访问、提权和凭据引用都必须由用户在界面确认。Burp Suite、VeraCrypt 等没有可安全自动询问的桌面软件保持 `INTERACTIVE_REQUIRED`，不能把“窗口在位”写成业务调用成功。
