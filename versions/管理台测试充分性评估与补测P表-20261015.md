# 管理台（architecture-manager 0.8.7）测试充分性评估与补测 P 表

- 编制：2026-10-15，依据用户终端权威全量读数 `npm test`（node v24.18.0）+ 源码/测试静态盘点
- 相关缺陷：D-158、D-159、D-160（已登记于 commit `1022eaec`）
- 状态：**待采纳**（BP-5：无 P 表的方案只是议题，不构成实施授权）

---

## §0 结论

**不满足。** 不是数量不够（345 例并不少），而是三项硬缺口：

1. **没有绿基线** —— 套件默认带 6 个真红，门禁形同虚设；且**无 CI、无 git hook**，`npm test` / `npm run conform` 全靠人手跑。
2. **覆盖有空洞** —— 静态可达性显示 172 个 `src/**/*.mjs` 中 **28 个从未被任何测试触达**（该数为上界，见 §1 口径修正）。
3. **测试设计有系统缺陷** —— D-156 与 D-158 是同一个病：测试只覆盖「声明集合内的正常路径」，不覆盖「集合外 / 默认值 / 真实依赖」。这才是缺陷能潜伏的根因，比补多少条用例都重要。

## §3 测试设计缺陷：D-156 与 D-158 是同一病

| 缺陷 | 漏网机制 |
|---|---|
| **D-156** | `test/onboarding-l1.test.mjs` 用**注入的假 check**，真实 `runPlatformCheck` 的 `scope='full'` 默认值从未进测试 ⇒ L1 判据在真实路径上必错，测试全绿 |
| **D-158**（NP1 引入，潜伏 1 天） | `test/entry-skills-onboarding.test.mjs` 只测 workbuddy / doubao / zcode 三个**表内**平台，`entrySkillSlots` 对表外 id 的行为从未进测试 |
| **D-160** | 敏感扫描的**正/负语料**与 `sensitive.mjs:9` 的正则不同源断言 ⇒ D-155 改正则后夹具静默失效（值无引号不再命中） |

**共同模式（必须根治）**：被测函数的**默认值**、**硬编码白名单表的表外分支**、**检测器的语料**——这三类「不在正常路径上」的东西，测试一律没覆盖。

### P1 先把门禁修绿（阻断项，约 1.5 h）

**判据**：`npm test` 与 `npm run conform` 双绿，且 conform 输出 `ok:true` + digest 落盘。**在此之前，任何新测试都无法起到回归护栏作用。**

### P2 补真·零覆盖（约 1.5 h）

- 2.1 `native-client-session.mjs`：补会话建立 / 复用 / 终止 / PID 回收拒绝 / 跨会话隔离 五类用例（对齐既有 `native-client` 测试的口径）

### P3 补测试设计缺陷（约 2 h，最高长期价值）

- 3.1 **真实默认值护栏**：凡被测函数带默认值/全局表的（`runPlatformCheck` 的 `scope`、`entrySkillSlots` 的 `SLOTS` 等），**每条至少一例走真实默认值而非注入桩**。沉淀为可复用断言模式，写进 `test/support/`
- 3.2 **表外分支用例**：凡硬编码白名单表（SLOTS 六平台等），**必配「表外 id」用例**
- 3.3 **检测器语料同源**：`sensitive.mjs` 的正/负语料改表驱动，与正则同文件断言 —— 改正则不改语料即红
- 3.4 **端到端缺口**：D-156 遗留观察项 —— 「绑软件网关的平台走标准路径 L1」的真实 spawn 端到端仍无测试，补一条

**判据**：3.1–3.3 各产出 ≥1 条用例；把 D-156 / D-158 / D-160 的失败机制分别注入回去，**新用例必须转红**（证明护栏真的能抓）。**这是本表最关键的一条判据——补的测试抓不住旧缺陷，等于没补。**

### P4 弱覆盖与结构缺口（约 1.5 h，可延后）

## §5 明写代价

1. **P1 未完成前，本表其余各 P 的产出都不构成有效护栏** —— 红基线上的新用例无法区分「新回归」与「旧红」。
2. **P3 的护栏只能防同类，不能防全部** —— 「真实默认值 / 表外分支 / 语料同源」是 D-156/158/160 三个已知病的解药，不保证覆盖未知病种。
3. **静态可达性数字是上界** —— 后续任何覆盖率结论都须逐条定性，不得直接引用 28 这个数。
4. **`conform` 全串耗时**（69 文件 `--test-concurrency=1`，脚本注释自述「legitimately exceeds ten minutes」）—— 作为 pre-push 门禁的体验成本须用户接受。
