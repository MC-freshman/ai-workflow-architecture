# 架构管理台报错排查与恢复手册（0.7.0）

适用版本与核对日期：管理台 0.7.0，2026-10-08。正常步骤见 [操作手册](架构管理台操作手册-20261008.md)。本页先按症状定位，再给具体修复操作，末尾附当前界面全部已映射错误码索引。

“接入失败”不一定是代码坏了：可能是少本体、缺解释器、旧计划失效、厂商登录未完成或接口尚未适配。**先处理最底层具体原因，再重验受影响步骤**。不要手改成功标志、哈希钉子或已发布版本来消除红色提示。

## 1. 30 秒定位：先选你看到的情况

| 症状/错误关键词 | 先做什么 | 详细处理 |
|---|---|---|
| 空白窗口、按钮找不到、没有反应 | 核对左上角 0.7.0、工作区和扫描/任务状态 | 第 2 节 |
| 文件/ZIP 无法识别、缺入口/依赖 | 检查完整来源、编码、入口与类型 | 第 3 节 |
| `SOFTWARE_BINDING_CONFLICT`、`interpreters:.py` | 查看当前使用的配置及差异，明确迁移来源 | 第 4 节 |
| `ONBOARDING_RESUME_DRIFT`、基线变化 | 使用“核对当前更改后续接”，不改日志哈希 | 第 5 节 |
| 缺 Python/WSL、组件过旧 | 检测兼容环境、更新安装副本，或暂缓 | 第 6 节 |
| `check-failed`、没有报告/有效行 | 展开检查程序具体错误和能力地板报告 | 第 7 节 |
| 客户端没有回执、认证/原生验证待补 | 分清标准 CLI、厂商本体和真实工具回执 | 第 8 节 |
| 软件未绑定、启动失败/状态未知、MCP 失败 | 先选所属平台，再查本体、会话、服务与凭据 | 第 9 节 |
| 版本找不到、不能回退、被引用不能停用 | 核对冻结版本、精确依赖及切换作用域 | 第 10 节 |
| 不能提交/推送、恢复遇到新改动 | 检查基线、显式路径、敏感内容和远端详情 | 第 11 节 |
| 只有英文码，以上没有命中 | 浏览器查找完整错误码及后面的具体详情 | 第 13 节索引 |

每次记下：版本、工作区、平台 ID、操作按钮、是否确认执行、错误码和发生时间。到 **审计** 或接入结果的 **证据与读数** 找本次记录。看 `error` 和 `previousAttempts`；只看 `currentStep` 容易误判根因。

## 2. 空白、灰色按钮和“点了没反应”

### 窗口只剩背景

1. 关闭空白窗口，确认自己打开的是 `Architecture-Manager-0.7.0-portable-x64.exe`，不是清理归档中的 0.1.x/0.5.x 或旧快捷方式。
2. 不要把安装器当便携入口。使用发行目录的完整官方包，核对同版 `SHA256SUMS`；新包启动不自动升级已经安装到平台的组件。
3. 重新打开后选择架构根目录。若当前包也持续空白，记录启动时间及系统/应用错误，交给维护者检查启动和渲染日志。这种情况没有可点击的“修复”按钮，不能声称只改一个配置就能恢复。

### 按钮灰色或执行后没有变化

先看是否未选平台、未选入口/版本、未勾选创建目录授权，或当前仍有任务。灰色按钮表示条件未满足。“识别完成”“计划已生成”没有写盘；滚动/定位到 **计划预览 → 确认并执行**。

取消文件选择是取消操作，原来源保留。无变化提示 `NO_CHANGE` 是目标已经相同，不是执行失败。`TRANSACTION_KIND_UNSUPPORTED` 表示该类计划只读或尚无执行器，不能强行运行。

软件 **查看启动条件** 是只读卡片；真正执行在 **功能参数与会话 → 预览启动/预览调用这个功能**。**打开位置** 只开目录。

## 3. 来源识别、ZIP、正文和资源结构

| 错误 | 原因 | 界面处理与完成确认 |
|---|---|---|
| `INTAKE_SOURCE_MISSING` / `INTAKE_SOURCE_CHANGED` | 选中的来源消失或预览后变了 | 重新选择完整来源，识别、预览；来源指纹应更新后再确认 |
| `INTAKE_SOURCE_EMPTY` | 选错目录，或有效文件被排除 | 查看拟纳入/排除列表，改选正文/实际本体；不要把凭据和缓存强行纳入 |
| `INTAKE_ENTRY_INVALID` / `BODY_TEXT_REQUIRED` | 未选入口或正文为空 | 选择 `prompt.md`、`workflow.yaml`、`SKILL.md` 或合法程序入口，检查完整正文 |
| `INTAKE_TEXT_ENCODING` | 正文不是可确定的 UTF-8 | 用编辑器另存为 UTF-8 后重识别，核对中文；不在旧预览上直接执行 |
| `INTAKE_ZIP64_REQUIRED` / `INTAKE_ZIP_ENCRYPTED` | ZIP64 或加密包 | 本机解压/解密为普通目录，再选文件夹；密码不填入接入计划 |
| `INTAKE_ZIP_INVALID` / `INTAKE_ZIP_CONTENT_MISMATCH` | ZIP 损坏或结构不一致 | 用正常解压软件验证，重新获取完整包；不能跳过校验 |
| `INTAKE_DUPLICATE_PATH` / `INTAKE_UNSAFE_PATH` | 大小写冲突、重复或越界路径 | 在来源副本修正后重打包/重选；不要修改已经冻结的发布目录 |
| `INTAKE_LINK_NOT_ALLOWED` | 来源有符号链接/junction，边界不清 | 改选独立的普通目录或文件，不沿外部链接复制未知内容 |
| `AGENT_MAIN_WORKFLOW_REQUIRED` | agent 没主工作流或没钉精确依赖 | 在 agent 表单选主工作流并勾选精确版本，再预览 |
| `RESOURCE_DEPENDENCY_NOT_PINNED` | 依赖用了 latest/current/范围 | 在依赖版本列表选明确 `x.y.z`，确认依赖目录和封条存在 |
| `RESOURCE_SCHEMA_INVALID` / `RESOURCE_PROMPT_ANCHOR_INVALID` | 定义、阶段或正文锚点不合法 | 看字段详情，用类型/阶段表单补齐候选定义；不编辑已发布旧版 |
| `RESOURCE_IDENTITY_MISMATCH` / `WORKFLOW_IDENTITY_MISMATCH` | ID/版本与目录或定义不一致 | 修正候选 manifest/定义，重新生成计划并核对同一个 ID/新版本 |

安装包相关 `INSTALLER_NOT_INSTALLED` / `PLATFORM_INSTALLATION_REQUIRED`：先在系统中完成安装，再选**安装后的实际程序和完整目录**。管理台安置安装器不等于已经安装软件。

`INTAKE_DISK_SPACE_REQUIRED`：看来源页显示的稳定占用和恢复峰值，释放旧文件或选有足够空间的自己的工作区后继续。软件会留下本体和备份；不要只按原安装包大小估算，也不要删除未验证的备份。

## 4. 两份软件配置冲突，尤其 interpreters:.py

`SOFTWARE_BINDING_CONFLICT` 表示配置中的同一项有不同值，管理台保留原配置，没有擅自覆盖。`interpreters:.py` 是一个解释器条目的差异，**不是软件本体路径或 Python 包损坏的证明**。

1. **平台与接入** 选择报错平台，展开 **软件配置来源核对**。
2. 读“当前使用”的文件路径，再读其他文件的“缺少项/差异项”。运行来源由当前配置指针决定，不能凭文件名新旧选择。
3. 当前解释器确认有效、只需补软件绑定：用 **预览迁入缺少项（保留当前差异项）**。
4. 明确另一份文件的解释器/绑定才是想采用的值：用 **预览迁入并采用此文件差异项**，检查所有差异，不只看 `.py`。
5. 计划中核对旧/新值、目标和属于该平台的路径，确认执行。原来源文件保留。
6. 回 **3. 准备环境 → 绑定软件本体与平台 provider** 看保存后的本体和解释器；然后 **核对当前更改后续接**，重新验证受影响项。

`.py` 平台脚本派发解释器与软件配方的 `PPython` 别名用途不同。dirsearch 等按配方/冻结证据选软件自己的解释器，不为了消掉差异把所有 `.py` 统一改成某一版。

若仍报 `SOFTWARE_BINDING_SELECTION_REQUIRED`，说明唯一生效来源还未确认；重新读取、明确迁移再保存。来源文件无法读取时先保留现场和详情，不删旧配置来消除比较提示。

## 5. 预览失效、配置漂移和续跑

| 错误 | 应怎么做 |
|---|---|
| `ONBOARDING_RESUME_DRIFT` | 单独安装入口、更新组件或保存软件位置后，点“核对当前更改后续接”，核对旧/新 SHA，确认受影响步骤重新验证 |
| `ONBOARDING_RESUME_PREVIEW_CHANGED` | 差异预览以后又改了文件；重新核对差异，不能确认旧计划 |
| `ONBOARDING_RESUME_VERSION_CHANGED` | 引擎/契约/检查器钉版变了；使用“预览重建接入记录”，历史记录保留 |
| `INTEGRATION_BASELINE_MISMATCH` / `POINTER_BASELINE_REQUIRED` / `CATALOG_BASELINE_MISMATCH` | 重新读取目标或扫描，确认当前值后重新预览；处理未保存编辑再重读 |
| `DOCUMENT_BASELINE_MISMATCH` | 保存好自己的文字副本，重新打开文档，比较新旧再编辑；不用旧正文覆盖新修改 |
| `EXTERNAL_CHANGE_DETECTED` / `IMPORT_EXTERNAL_CHANGE` | 其他程序修改了目标；先查看 Git 差异/操作记录，再重读重新生成计划 |
| `PLAN_PAYLOAD_MISMATCH` | 计划内容/版本不再一致；关闭旧计划，重新选择对象并预览 |

“重新预览”不一定开启全新运行。**不要手改 automatic.json、能力 checks、state 或日志 SHA 来通过续跑**。安装副本也不会因源码更新自动变新：需要组件更新/标准服务安装计划确认执行，见下一节。

`STALE_TASK_RESULT` 是旧工作区或旧对象结果被忽略；看当前选择并等待其读数。`TASK_CANCELLED` / `ONBOARDING_CANCELLED` 表示本次停止，已完成安全步骤保留；等任务停止记录出现后再续接，不同时开两轮。

`ONBOARDING_JOURNAL_INVALID`、恢复时发现外部新改动等情况，先保留 journal/checkpoint/备份供维护者核对。不要清空它们后声称原先步骤已经成功。

## 6. 解释器、WSL、安装副本与配对版本

### Python/WSL 缺少或不兼容

`RUNTIME_PYTHON_REQUIRED` / `RUNTIME_COMPATIBLE_PYTHON_REQUIRED`：到 **3. 准备环境 → 检测解释器与 WSL**，选择能真正运行的 Python 3.10+。没有时安装系统设施，完成后重新检测。

`RUNTIME_BACKEND_REQUIRED` / `RUNTIME_SEALED_BACKEND_REQUIRED` / `RUNTIME_COMPATIBLE_BACKEND_REQUIRED`：检测后选择已安装、能运行兼容 Python 的 WSL 环境，预览保存隔离后端，再准备独立运行环境。系统启用、发行环境安装、UAC 或重启需要使用者完成；当前不能补时勾选 **暂缓运行环境与能力实测**，如实保留待补。

`RUNTIME_PREPARATION_FAILED` / `HOST_ENVIRONMENT_SNAPSHOT_FAILED`：看环境步骤具体错误，修复解释器启动、下载连接或系统后端，再重新预览。旧环境未完成切换时保持原位；不要删清单或借其他平台环境。

### 新 EXE 打开了，平台仍用旧脚本

`PROVIDER_UPDATE_REQUIRED`：在向导顶部点 **预览更新已安装组件**，确认后再探针。

`CLIENT_ENTRY_DRIFT` / `MANAGEMENT_SERVICE_UPDATE_REQUIRED` / `NATIVE_SERVICE_UPDATE_REQUIRED`：到 **4. 客户端入口 → 安装标准 CLI 客户端入口**，重新预览并执行，必要时重新连接 MCP。

`MANAGEMENT_NODE_REQUIRED`：需要系统可用 Node 18+ 作为准备来源；安装后管理台建立所选平台自己的管理运行时。这里是架构服务需求，不是运行 EXE 的开发环境要求；开发源码的 Node 要求更高。

`VERSION_PAIR_MISMATCH` / `PLATFORM_VERSION_PAIRING_REQUIRED`：到完整配置或平台对齐入口，核对推荐的引擎/契约/检查器组合；不能只把其中一个指向最新。确认换代时重建接入记录，不混用旧认证。

## 7. check-failed、没有报告、矩阵很慢

### 多条检查错误可能只有一个底层原因

例如同时看到“能力检查命令执行失败”“调用检查命令执行失败”“能力检查未产生可读报告”“调用检查未产生有效行”。这些可能是子进程启动/退出造成的连锁结果，不能据计数认定四个独立缺陷。

1. 在平台行展开 **查看检查程序的具体错误**，先看 stderr、退出码和路径，不先重跑整矩阵。
2. 展开 **查看检查问题与能力缺口**，读具体能力 ID、理由、处置与预计成本。
3. 查看本次 `conform.json` 是否存在且有效。没有时优先检查解释器、检查脚本/安装副本、配置所属平台和输出目录权限。
4. 有报告时读 `declaredAbsent`、`unverified`、`floorReached`。地板未过会停在能力检查，`matrixPath` 为空是没有启动矩阵，不是矩阵成功或失败。
5. 修原因后从对应步骤继续或检查受影响调用。空报告/零有效行不是绿灯，不能手工补 PASS。

### 缺的是软件，不要重装整个平台

如果未验证项是软件，先到软件中心选报错平台，查看“该平台未绑定本体”。到向导软件/provider 区填写**本平台**的真实程序文件及所需解释器，保存、确认、核对更改后续接。

只填写路径还不证明功能可用。检查该程序需要的 DLL/包、服务是否启动、连接器是否现行、配方快照是否冻结。暂时不需要时暂缓软件，完整认证也会待补；这是允许保存配置，不是跳过地板后宣称完成。

### 没有明显错误但仍慢

- 看是否“首次接入”、无有效基线或代际升级。它们需要全矩阵；具体格数来自当前资源和平台声明。
- 有基线时看实际选格、复用行、指纹变化与旧失败。更新一个资源通常只验受影响格；大量配置/验证规则变化会扩大影响范围。
- “上次检查缓存”是读取旧报告，不是提速后的新实测。看本次时间与新产物。
- 环境准备、完整备份恢复、大文件复制不是矩阵步骤，分别看任务阶段进度。
- 在 **2. 完整配置** 有“可选择提速配对”时，可明确选择推荐组合并保存；版本换代需重建记录，不强行改指针来复用旧证。

### 能力探针失败

`ONBOARDING_CAPABILITY_PROBE_FAILED`：在 **5. 检查与接入 → 实测所需能力** 看具体能力和证据。如果是旧组件曾有的 prepare/peer 判据问题，先更新安装组件后实测。协议调用完成与业务正文交付是两个判据；peer 没正文不会因接口通过变成业务完成。

## 8. 标准客户端、厂商原生接口及 WorkBuddy 登录

### 客户端 GUI 被当成 JSON CLI

`CLIENT_CONNECTION_FAILED` / `CLIENT_RECEIPT_MISMATCH`：检查“客户端接口”和“客户端入口程序”。GUI 填厂商程序；JSON CLI 框用管理台 **安装标准 CLI 客户端入口** 生成的程序。再点 **测试真实客户端入口**，应返回当前 challenge、平台和摘要；普通 `--version` 输出不能代替。

`CLIENT_ADAPTER_PENDING` 说明当前入口还没有适配器。安装标准服务可验证服务通道，但不会自动创造厂商原生接口。

### 原生配置注册与真实调用

`NATIVE_SERVICE_REQUIRED`：先安装/更新标准服务，再 **预览注册原生客户端**。

`NATIVE_CLIENT_SELECTION_REQUIRED` / `NATIVE_CLIENT_BODY_REQUIRED`：在厂商程序框选择本平台已安装本体。外部本体先导入安置；`NATIVE_CLIENT_PLATFORM_PATH_REQUIRED` 不允许借用其他平台目录。

`NATIVE_CLIENT_BINDING_CHANGED`：本体、厂商配置或服务变了，重注册并重验，旧成功失效。

`NATIVE_SERVER_NAME_CONFLICT`：厂商配置已有非管理台创建的同名服务。先核对现有配置来源，由使用者处理命名冲突；管理台保留原配置，不能直接覆盖。

Qoder/ZCode 注册成功后，需要厂商客户端加载该平台生成的 `workspaces/architecture-native` 项目。**目前其真实调用证据仍待补**；DSH/豆包缺可验证原生适配接口时，也不能靠改 GUI 路径完成。可用标准服务先保存准备结果，原生待补另记。

### WorkBuddy 登录成功却没通过

1. 先确认是否真的需要本次原生模型验证。按钮 **允许一次原生 AI 只读验证** 会询问同意，可能消耗额度，不自动重试。
2. `NATIVE_WORKBUDDY_LOGIN_REQUIRED`：完成**这次请求打开的最新官方登录页**，保持同一认证进程。桌面账号缓存和旧浏览器页面不代表 CLI 已取得可用认证。
3. `NATIVE_AUTHENTICATION_INCOMPLETE` / `NATIVE_AUTH_CONNECTION_CLOSED`：网页回调未完成 CLI 确认或连接已结束；保存本次记录，不能拿旧页面成功作为工具回执。
4. `NATIVE_WORKBUDDY_TOOL_AUTH_REJECTED` / `NATIVE_CREDENTIAL_RELAY_REQUIRED`：认证交接仍需维护者修适配，不要求用户反复登录或手抄 token。
5. `NATIVE_AI_TOOL_TRACE_REQUIRED` / `NATIVE_AI_ATTEMPT_STOPPED`：没有匹配的工具使用和结果，或超时/停止。记录保持待验证；`MCP connected`、登录成功、文字承诺均不算三仓调用成功。

0.7.0 本轮实测 WorkBuddy 取得认证、连接 MCP，但没有工具回执。这个剩余缺口不能仅用本手册操作保证解决。再次尝试需新的明确同意；不承诺零 token，也不把未知模型启动记成成功。

## 9. 软件、会话、MCP 和凭据

| 错误/情况 | 处理步骤 |
|---|---|
| `SOFTWARE_NOT_DECLARED` / `SOFTWARE_BODY_PATH_NOT_FOUND` | 先选所属平台，核对绑定程序是否存在；在准备环境/provider 区补绑定、保存，再续接 |
| `SOFTWARE_CONNECTOR_NOT_CONFIGURED` / `SOFTWARE_CONNECTOR_ENTRY_MISSING` | 同一平台安装/更新连接器及 provider；不能靠换成其他平台的配置文件解决 |
| `AUTOMATIC_SOFTWARE_MATCH_AMBIGUOUS` | 在软件表单明确选软件 ID/配方，核对唯一来源后接入 |
| `AUTOMATIC_SOFTWARE_DECLARATION_REQUIRED` | 未知 CLI 明确声明动作/参数，或导入现成 MCP；未知 GUI 仅标准会话 |
| `SOFTWARE_RUNTIME_REQUIRED` | 为脚本选它自己的解释器，核对冻结要求和启动依赖 |
| `SOFTWARE_ARGUMENT_INVALID` / `SOFTWARE_ACTION_INVALID` | 按功能 schema 填参数类型/必填值、唯一动作名与参数映射，重新预览 |
| `SOFTWARE_UNSAFE_PROBE` / `SOFTWARE_PROBE_ARGUMENT_REQUIRED` | 只读探针仅允许已声明无写入/网络/凭据的动作；补只读测试值或保留待验证，不把有副作用动作伪装只读 |
| `SOFTWARE_CONNECTOR_FAILED` / `SOFTWARE_CONNECTOR_INVALID` | 到审计看进程退出和输出；输出不可读时执行结果可能未知，先核对进程/会话，不盲目重复 |
| `SOFTWARE_EXECUTION_UNKNOWN` | 先“预览检查存活”并确认；核对是否已起进程后再处理，不能连续启动第二份 |
| `MCP_PROGRAM_REQUIRED` / `MCP_RUNTIME_SETUP_REQUIRED` | 先安装服务运行包，选择真实程序；npx/npm/uvx 需要下载时不自动暗中安装 |
| `MCP_CONNECTION_FAILED` | 确认指定服务/端点、本体、登录和防火墙，再重新发现；stdio 会起指定服务器，网络端点需服务已启动 |
| `MCP_EMPTY_TOOLS` / `MCP_DISCOVERY_CHANGED` | 服务未返回工具或证据变了；重新实际连接读取清单并确认发布，旧发现不能复用 |
| `MCP_PERMISSION_REQUIRED` / `MCP_PERMISSION_ENDPOINT_MISMATCH` | 只选所需工具，逐项确认文件/网络/影响范围，与真实端点一致 |
| `MCP_PROTOCOL_UNSUPPORTED` / `MCP_TRANSPORT_UNSUPPORTED` / `MCP_SCHEMA_UNSUPPORTED` | 当前接口不能验证，需要兼容配置/专用适配；不能关校验来发布 |
| `MCP_AUTH_REQUIRED` / `CREDENTIAL_UNAVAILABLE` | 在本平台 MCP 凭据区域准备提供器、保存/恢复引用，再连接；换 Windows 用户/电脑重新录入 |
| `RAW_SECRET_NOT_ALLOWED` / `CREDENTIAL_REFERENCE_INVALID` | 配置只填 `reference:名称`，名称限英文、数字、点、下划线、连字符；真值填独立密码框 |
| `MCP_SPECIAL_CREDENTIAL_ADAPTER_REQUIRED` | 命令行直接带凭据需要专用适配；可支持的环境变量/请求头采用凭据引用 |

### Burp / MySQL / 扫描类软件的补充判断

- Burp：GUI 内 MCP 扩展装好，还需启用服务、确认实际端点可连接及工具清单可读。项目数据/HTTP 请求的授权提示仍由你处理；未点击授权的等待不能记成调用成功。不为了测试而关闭所有批准要求。
- MySQL：客户端可运行不代表服务器在监听。确认本机目标服务、地址、端口、账号引用和权限；连接器只接受已冻结动作定义。历史 `passwordRef` 与现行凭据引用不要凭记忆混填，按当前配方表单处理。字符集查询返回什么就记录什么，不把 gbk 读数写成 utf8 已验证。
- dirsearch/nmap：版本查询不是扫描。确认软件自己的解释器/依赖、授权目标和白名单；本机没有 Web 服务时先启动授权的本机目标，不改扫外部网站来凑成功。首次真实扫描另行确认。
- VeraCrypt/其他 GUI：启动窗口、进程存活、关闭会话分别验证；UAC/许可需使用者处理。人工打开的窗口没有 PID 绑定时不能推定管理台接管成功。

底层回执若出现 `CAPABILITY_UNAVAILABLE`、`SOFTWARE_DRIFT`、`SOFTWARE_BUSY`、`RESOURCE_BUSY`、`VERSION_CONFLICT` 等：保留完整回执。未冻结/未声明先补正确配方与能力；字节漂移重新发现/发布新冻结版本；繁忙先确认持有者；版本冲突按配对计划处理。不能删锁文件后强启，也不能修改冻结封条纳入变化。

## 10. 版本、封条、依赖和停用

| 错误 | 处理方式 |
|---|---|
| `TARGET_VERSION_UNAVAILABLE` / `RESOURCE_NOT_FOUND` | 确认当前工作区、ID、类型和冻结目录；刷新后选实际存在版本 |
| `TARGET_VERSION_NOT_FROZEN` / `RESOURCE_VERSION_CANDIDATE` | 等候选正式发布，或选择已冻结版本；手写空封条不算发布 |
| `RELEASE_HASH_MISMATCH` / `RELEASE_FILE_SET_MISMATCH` | 封条不符/文件缺失，停止采用；由维护者恢复合法发布件或发新版本，不改旧封条 |
| `RELEASE_VERSION_EXISTS` / `RELEASE_SEMVER_INVALID` | 用未存在的严格 `x.y.z` 新版本；不覆盖已发布目录 |
| `NO_CHANGE` | 目标已是当前默认，不需执行；先确认你看的是平台独立还是共享默认 |
| `PLATFORM_SCOPE_MISMATCH` | 请求不属于所选平台；重新选平台生成计划，AI 不跨平台写选择 |
| `RESOURCE_REFERENCED` | 展开全部引用，先更新现行引用者并发布/采用，再停用；不删冻结历史来解除依赖 |

平台独立选版在 **资源 → 平台独立版本**；下方共享默认影响跟随者。agent 内部精确 tool-lock、在途 run-lock 不随顶层选择改写。

旧选择指向消失版本时，明确选已有冻结版本，或 **恢复跟随共享默认**；不能静默代换。Codex 0.7.0 阶段记录中的历史 visualization-engineer 1.6.0 即属这类旧选择缺口，不意味着所有 agent 都坏了。

`ONBOARDING_NOT_VERIFIED` / `ONBOARDING_CHECK_FAILED` 不是新的成功/失败类别：回到对应检查、客户端、配置入库记录，找到未满足项；不要只把状态改成 complete。

## 11. Git、推送、文档编辑及恢复失败

### 提交被阻止

`GIT_IDENTITY_REQUIRED`：在向导登记页填提交姓名/邮箱，重新预览。

`IMPORT_GIT_BASELINE_REQUIRED`：先到 **仓库 → 提交计划（显式路径）**，提交本操作涉及的现有登记/配置，建立可回滚基线，再重新预览导入。

`COMMIT_PATHS_REQUIRED` / `GIT_ADD_ALL_FORBIDDEN`：明确勾选本次相对路径，不能填写 `.`, `-A`、通配符或绝对路径。`GIT_UNRELATED_STAGED_FILES`：有无关暂存，先在其原任务/自己的 Git 客户端处理；管理台不会混入或清空。

`COMMIT_BLOCKED_SENSITIVE` / `PUSH_BLOCKED_SENSITIVE`：展开具体文件，确认凭据、本体、大文件或运行产物是否误入。仅删工作区文件可能不足以清掉已提交历史中的敏感字节；保留记录交给维护者处理，不关闭扫描、不强推。

### 推送、远端和网络

`INVALID_REMOTE`：推送表单选择已配置的远端名；不能把 URL 或命令选项塞入远端框。

`GIT_COMMAND_FAILED`：看具体 stderr。登录/权限拒绝时完成正确账户认证；网络/代理超时先修实际连接；远端有新提交时先核对分支差异，用自己的 Git 客户端安全合并，不能强推。当前 GUI 不是完整 Git 冲突解决器。

`GIT_EXTERNAL_CHANGE`：HEAD 在预览后变了，重新刷新生成计划。`GIT_REPOSITORY_REQUIRED`：选对已经有 Git 的架构根目录，或用克隆流程准备自己的副本；普通文件夹不凭空成为架构仓库。

### 备份和回滚

`GIT_ROLLBACK_DIRTY`：未提交/暂存内容先提交或安全备份并处理，再生成 revert 计划。

`GIT_BACKUP_ALREADY_EXISTS`：用新的备份名称，不覆盖旧备份。`GIT_BACKUP_ARCHIVE_TOOL_MISSING`：系统 tar.exe 不可用，由使用者恢复系统设施；不改用 Git Bash 中同名工具冒充恢复。

`RECOVERY_EXTERNAL_CHANGE`：恢复时目标已被新修改。保留现场和 checkpoint，比较当前内容、`.before` 与原提交，再决定恢复/合并。**不要手动删软件目录、删 checkpoint 或整包覆盖来做“撤销”**。软件操作从操作历史预览撤销；冻结目录保留。

缺陷簿/文档基线变化时刷新后重读，不能用旧表覆盖。`DEFECT_BOOK_CORRUPT` 等结构异常需维护者恢复合法文本，不新建空簿来制造“没有缺陷”。

## 12. 哪些自己能处理，哪些要交给维护者

| 类别 | 使用者可以做 | 需要维护者/厂商适配 |
|---|---|---|
| 路径、入口、依赖、表单 | 重新选完整本体，补字段，明确选版，刷新预览 | 合法来源仍被错误识别，复现后登记 |
| 环境/软件/账号 | 安装系统设施、启动授权本机服务、登录、保存本平台凭据引用 | 专用隔离/认证/传输适配缺失 |
| 漂移/续接 | 核对变化后续接、明确重建记录、取消暂缓再补齐 | 日志损坏、哈希来源不明或外部写入冲突无法判断 |
| 原生厂商调用 | 加载正确项目、当前请求登录、按需同意一次验证 | 无公开接口、WorkBuddy 无工具回执或认证适配未完成 |
| 冻结版本/敏感 Git 历史 | 停止采用/推送，保留记录，选合法旧版 | 发布件损坏、历史凭据处理、不可自判的恢复 |

交给维护者时提供：版本、平台、按钮、错误码及详情、发生时间、是否确认执行、可重复步骤、报告/日志路径和脱敏摘要。不要发送凭据原值、整份账号配置或原生认证回执。

本手册给的是处理路线，**不宣称这些动作已经替你执行或所有剩余实现缺陷已关闭**。找不到对应错误时保留具体详情，按当前源码和本平台证据继续定位。
