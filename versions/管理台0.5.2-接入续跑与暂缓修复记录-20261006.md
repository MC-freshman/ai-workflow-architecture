## 改动与使用

| 问题 | 修复结果 |
|---|---|
| 旧 false 堵住探针自身 | 临时候选只继承 true，生产表不被候选改写；真实 prepare/stop 成功才登记。peer 的前置失败明确指出 prompt prepare 未过，不再抛一个裸 KeyError |
| 独立安装客户端/软件后永久漂移 | 默认严格拒绝；“核对当前更改后续接”展示完整旧/新 SHA，只在确认后接纳，丢弃受影响结论，保留原计划身份；预览后再次漂移仍拒绝 |
| 输入不变时无法重新开始 | “预览重建接入记录”明确新身份；换引擎/契约/检查器不能走沿用旧认证的路径 |
| 不需要的软件阻断其它步骤 | 环境、软件、客户端、认证、Git 可暂缓，依赖自动暂缓；其它选中安全步骤仍执行。未绑定软件逐项待补，结果为 configured-pending，不记 PASS 或 complete |
| 老 unverified/旧格式缺口残留 | 按对应真实证据清旧名；客户端实际挑战回执先获取，再登记能力，MCP 旧名只在当前配置/版本/适配器摘要匹配时清。软件未测或未知项不清 |
| 历史难追溯 | 尝试/重建前留带日期、完整 SHA256SUMS 的旧日志原始字节副本；严格拒绝未确认差异时不替换旧日志 |
| tar 的 PATH 敏感 | Windows 明确使用系统 tar。GNU tar 前置 PATH 的真实盘符失败已复现；同一备份改走系统 tar 后真实恢复逐哈希成立 |
| 缺陷号段只查到 D-97 | 合法 ID 动态上界；D-98 跳号与非法 ID 负例会给结构化失败。D-98～D-104 对应本轮修复 |
