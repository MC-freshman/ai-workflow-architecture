# 架构管理台问题核查与修复实施表

日期：2026-09-28。范围：`architecture-manager` 独立源码、README、本轮治理与本平台维护证据；不改三仓已发布版本，不替其他平台改配置或自证。以下为本轮进入实施前的 P 表，非阻断的新发现另记缺口。

## 核查与裁定

| 项 | 核查 | 本轮处置 |
|---|---|---|
| A1 | 属实：`requireUnreferenced` 递归扫描所有历史版本，误拦已不被 `current` 指向的引用 | 仅扫描当前启用资源的当前发布版及其实际依赖；展示完整命中清单 |
| A2–A4 | 属实：缓存结论未标时间、矩阵非零退出重复计数、`conform.json` 缺口细节未进界面且 veracrypt 的 remediation 为 null | 明示缓存和检查时间；合并同源错误；展示逐项缺口、处置和分钟成本，缺处置标“未声明” |
| A5–A6 | 属实：行版本来自 registry，版本目录按字符串排序 | **以 `current.json` 为正在使用的版本权威**，registry 版本另标“登记值”；下拉语义化排序并标当前默认 |
| B1–B6 | 属实：禁用态不明显、取消/缺字段静默、反馈分离、错误码少白话映射、软件平台默认 codex、动作卡不区分模式 | 补可见状态/就近反馈/错误详情；选择具备连接器的平台或要求明确选择；动作卡写中文动作及后果 |
| C1 | 属实：`launch` 只有计划，没有执行器 | 未接入安全执行器前不展示可执行“启动”入口；只显示“需 provider/人工启动”。绝不声称已启动。真实 GUI/MCP 启动另立配方/权限适配轮 |
| D1–D3 | 属实：软件两条写入路径没有统一审计/checkpoint；安置峰值三份；向导基线不刷新 | 接入事务审计与可恢复 checkpoint、明确容量/进度、降低不必要复制峰值；执行后刷新目标 |
| E1–E4 | 属实：指针双路径、平台 ID 多份、技能大目录全渲染、入口显示原 token | 收敛公共校验/常量与路径；技能分页；原 token 明示“模板，未解析” |
| F2–F3 | 属实：09-28 自助接入轮无独立维护证据目录，README“旧发行包仍保留”与清理表冲突 | 补事后核查记录（不能伪造当时一手证据）；改 README 为当前发行位置和旧包归档状态 |

## P 表

每个 P 分为 2–4 个可安全停手子块；本轮修复只以预写判据收口，不用历史测试数字冒充新结果。

| P | 子块 | 预定判据 |
|---|---|---|
| P1 资源真实状态 | 当前启用版本引用图；完整引用详情；指针权威与语义化排序 | 历史引用不再误拦，现行引用仍拒绝；列表与详情的当前版本一致 |
| P2 平台检查与反馈 | 缓存时间/命令去重；conform 缺口明细；就近反馈及错误白话 | 缓存不冒充新检查；两条失败只算两条；缺口处置缺失可见 |
| P3 软件操作诚实性 | 平台连接器适配选择；动作卡中文模式；模板路径说明；无执行器启动入口收口 | codex 旧网关不会成为默认配方发布平台；未启动的软件绝不报启动成功 |
| P4 软件写入恢复性 | 安置/发布纳入审计和 checkpoint；容量及进度；成功后刷新向导基线 | 真夹具可回读 events/checkpoints、失败可恢复；无连续计划基线误拒 |
| P5 代码与大目录 | 指针校验收敛；平台常量/本地视图路径统一；技能分页 | 关键规则只保留一处；1049 项技能无需一次渲染全部 DOM |
