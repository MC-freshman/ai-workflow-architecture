## 附录：P1 只读读数（2026-10-29）

### a. D-166 重命名 finalize 卡死 —— 复现与拒绝链

- **git 输出实测**（临时仓库复现，`git mv versions.md versions-2026.md`）：
  - `git diff --cached --name-status` → `R100\told\tnew`（tab 分隔，old 在前）
  - `git diff --cached --name-only` → **只给 new**
  - `git status --porcelain` → `R  old -> new`
- **拒绝链**：`onboarding-finalize.mjs:17` 取 `onboardingGitPaths()`（`onboarding-governance.mjs:30-41`：静态 7 条 + `<id>/bridge/` 递归的 json/md/py/mjs）作为 `gitPlan.target.paths`（:18）；apply 时 `:34` 用 `--name-only` 取 staged（只给 new）、`:35` 要求 staged 每一项都在 `target.paths` 内 ⇒ new 不在 ⇒ 抛 `GIT_UNRELATED_STAGED_FILES`。
- **第二处坑**：`buildGitPlan`（`git.mjs:63-68`）把 paths 经 `validateStagedPaths`（`git.mjs:94-109`，禁 `.` / `-A` / `..` / 通配符 / 绝对路径）后作为 `git add --` 的参数；重命名后 old 已不在工作树，**paths 里若仍留 old 会让 `git add` 失败** ⇒ 修法必须把 old 换成 new，而不是两边都放行。
- **判定规则（P2 采用）**：R 行的 old ∈ `onboardingGitPaths()` 且 new 属治理文本集合（扩展名 `.md/.json/.py/.mjs`、不匹配 `credential|secret|.env`、位于根级治理文档 / `versions/` / `<id>/bridge/`）⇒ 放行并把 new 换进 `target.paths`；否则维持拒绝。
