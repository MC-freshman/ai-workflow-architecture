复发机制三条（已核实）：
1. 平台副本是「铺设时快照」，管理台升级后不会自动重铺；
2. `provider-templates.mjs::providerTemplateStatus` 只产出 `current:false` **状态**，被
   `onboarding-readback.mjs`（`writePerformed:false` 只读报告）与 `onboarding-attestation.mjs` 消费，
   **未进 fail 判据**；`onboarding-auto.mjs:115` 的 `PROVIDER_TEMPLATE_CHANGED` 是防竞态，非漂移判据；
3. `platform_defaults.mjs` **铺而不检**：`onboarding-client.mjs:27` 写它，但 `:87-88` 只比对
   `cli_client.py` / `mcp_service.py`（且仅 `standard` 平台）⇒ 该路连状态都没有。

## 1. 范围（两条，必须补）

- **甲、漂移进 conform 并判 FAIL**：新增 `scripts/check-runtime-drift.mjs`，比对五个铺设文件与 `src/runtime/` 真身，挂入 `conform.mjs` steps。
- **乙、平台钉运行时件版本**：`bridge.json` 写 `runtimeComponentVersion`（= 管理台版本），管理台升级即 FAIL 并输出「N 台待重铺」。

不改：三仓结构、平台目录、共享件位置、BP 条款。

## 2. P 表

**P1 只读盘点与备份（~1h）**
- 1a 七平台五个铺设文件与真身逐一哈希，定「待重铺名单」（预期 5 台）；
- 1b 旧文件副本 + sha256 存 `inbox/backup/<platform>/runtime-components/<日期>/`，构成 BP-6 可回滚点。
- 判据：清单落盘可回读；备份副本 sha256 与现盘一致。停手点：零写入。

**P2 加判据，默认 warn（~1.5h）**
- 2a 新脚本比对 `cli_client.py`、`mcp_service.py`、`platform_defaults.mjs`、`platform_provider.py`、`peer_dispatcher.py`；未铺设的平台 skip；`--warn` 只报不 fail；
- 2b 挂入 `conform.mjs` steps（纯 node，无 .exe spawn，会话内可跑）+ 注入坏哈希的单元测试。
- 判据：`npm run conform` 仍 ok（warn 不阻断）；注入用例能抓 FAIL。停手点：脚本落盘即停。

**P3 逐台重铺（~2h，路径待用户定：GUI 或新增脚本）**
- 3a codex 单台试点：备份就位 → 重铺 → `node scripts/verify-onboarding.mjs <root> <id>` 回读 → 哈希复验；
- 3b 其余四台同法。
- 判据：5 台五文件哈希等于真身；`currentBindings` 仍 true；在途 run 零影响。停手点：每台一停。

**P4 判据转 fail + 钉版（~1.5h）**
- 4a `bridge.json` 写 `runtimeComponentVersion`；脚本同时比对「记录值 vs 当前管理台版本」与五文件 sha256；
- 4b 去掉 `--warn`。
- 判据：改坏一份副本 ⇒ conform FAIL；管理台版本 +1 ⇒ 立即 FAIL 并输出待重铺台数与重铺路径。

**P5 入库收口（~1h）**
- 5a 发布记录 / 更新日志 / 两份 README 补账；
- 5b 四项收口读数：HEAD sha / 白名单内 `git status` 空 / 远端一致 / 入库早于重铺覆盖。

## 3. 风险登记（非阻断，只登记）

1. **D-177 缺脚本化重建入口**：`src/cli.mjs` 只有 `scan`（只读），写入型 onboarding 走 GUI ⇒ 重铺无法无人值守/批量，P3 需先定路径。
2. 重铺会**覆盖**文件，必须先备份（P1b），否则不可回滚。
3. onboarding 可能 spawn python ⇒ 会话内 EBUSY，需在用户终端执行。
4. 治理文本改后必跑 `git diff --numstat` 验 EOL 膨胀（Edit 工具会归一 EOL）。
5. 权威 conform digest 仍需用户终端跑后回填。
