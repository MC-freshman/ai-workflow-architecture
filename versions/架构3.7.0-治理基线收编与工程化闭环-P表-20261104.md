## 2. 问题定义（三个根因）

- **根因 A · SSoT 分裂**：`架构3.6.0.md:4` 自认只覆盖 0.4.x；`发布门禁.md:9` 写「339 例左右」而实盘 456；`export-readme.md` 仍写 0.8.2 / `wf-runner 0.13.0`；`conform.mjs:29` 注释写 69 文件而实盘 95；`GitHub仓库收敛说明-20261009.md:20` 写「最新源码 0.8.1」；多份文档仍写「六个平台」。
- **根因 B · 工程化闭环靠人**：`src/cli.mjs` 只有只读 `scan`（D-177）；门禁全靠人工触发；digest 与四项读数靠会话转述回填；BP-7 备份有登记但**未做真实恢复演练**。
- **根因 C · 跨子项目联动未成文**：P2 要回改的 AGENTS / 系统提示词 / HANDOFF / 平台清单 / 六个 `platform.md` **全在 `docs-manifest.json` 白名单**并带来源锁 SHA-256；改原文必触发 C3/C9/C11。站点多处仍写「架构 3.6.0（最新命名基线）」。只改根仓不改站点，等于把代差复制进第二个发布面。

> **口径**：§2 / §4 列出的代差是只读调研命中项；**完整清单与逐条 `路径:行号` 以 P1 盘点产物为准**，不预设条目总数，不把举例当穷举。

## 3. 目标 / 非目标 / 架构决策

**目标**：消除 A、把 B 的关键环节机制化、把 C 的联动写成硬判据，且不改变任何已发布字节、不扩大能力面。

**非目标**：不新增一级目录、不改三仓、不改 BP、不抬 `current`、不发包、不做平台接入认证、不切执行器默认、不改版或重构 `docs-site`。

| 决策 | 内容 | 理由 |
|---|---|---|
| AD-1 | **增量收编，不重构** | 契约正本（5 个 schema）、三仓同构、`anchor.json` 选版、run-lock 钉版均已标准化可冻结 |

| AD-4 | **发布 ≠ 采纳**：改管理台源码但不 bump、不打包、不签名、不发 release | 手工补签与双包发布成本与本轮目标无关；如需 0.9.0 另立发布轮 |
| AD-5 | **平台自证不代办** | BP-2：七台各自出证、结论不互抄 |
| AD-6 | **文档站是硬联动**：P2 改白名单源文后必须按 §6.0 命令链重跑 build + conform 并重算源锁；两套门禁独立给读数 | `docs-conform` C3/C9/C11 对源文做 SHA-256 源锁与逐行忠实校验；10-30 的 `83c46f0a` 已示范标准动作 |
