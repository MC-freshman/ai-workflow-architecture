## 0. 二轮纠错（P6 撤销，最高优先级）

一轮曾把四个 wfa run 的 `work/project/platform/node_modules` 判为"四份字节相同副本（各 609.9 MB）"，**该结论错误，现撤销**：

| 事实 | 核查结果 |
|---|---|
| 四个 node_modules 的真实类型 | 全部为 **Windows Junction 目录链接**（Attributes=1040=Directory+ReparsePoint） |
| 链接目标 | 统一指向 `\\?\E:\小说\创作平台\node_modules`（小说创作平台项目真实依赖，**在 E:\ai 目录树之外**） |
| 归档登记 | materials.zip MANIFEST 四个 target 的 `retainedLinks` 逐字登记四条链接，recovery=`complete-local-deduplicated-zip; restore-and-hash-before-remove`；归档与 39,176 文件恢复演练均**未遍历链接目标**，目标内容无备份 |
| 四 run 真实本地占用（robocopy /XJ） | c229de6c 0.4 MB/57 f、77d46cdc 3.4 MB/42 f、9051803b 2.8 MB/66 f、c771acd1 0.5 MB/56 f，合计 **7.1 MB** |
| 错误成因 | Python os.walk 默认跟随 junction，把同一物理目录在四个 run 下各计一次；"path+size 100%、哈希零差异"是同一实体的必然表现 |
| 全树链接普查 | 9 个平台树根共 7,192 个 junction **全部为 pnpm 内部链接（目标均在 E:\ai 内）**；跨树链接仅此 4 个。另有 `codex/runtime/maintenance/20261007-onboarding-chain/baseline-source/node_modules → E:\ai\architecture-manager\node_modules`（树内、保护族）与 phase1-implementation-02/environment 的 4 个 venv 相对 symlink（保护族） |

**定案：P6 选 C，四链接原位保留，释放量记 0。**
**永久红线：对 runs/workspaces/maintenance 的任何统计用 robocopy /XJ，任何删除/镜像清空必须先识别 ReparsePoint 并排除；沿 wfa 四链接递归删除会毁掉 `E:\小说\创作平台` 的真实依赖。**
