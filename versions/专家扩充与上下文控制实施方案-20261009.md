### 2.2 本轮预定预算

| 内容 | 预定标准 |
|---|---|
| 专家身份、边界、通用 Skill、常驻政策合计 | 目标 ≤2,500 估算 token |
| 当前任务辅助 Skill 合计 | 目标 ≤4,000；只加载任务确实需要的部分 |
| 当前阶段控制正文与索引 | 目标 ≤1,500 |
| 常规单次固定注入总量 | ≤8,000 |
| 特殊复合场景单次固定注入 | 硬上限 `min(12,000, W×25%÷(prompt阶段数+2))` |
| 运行累计固定注入预算 | 同时保留既有 R17 的 `≤W×25%`，包含重复交付与预留修复 |
| 上游长资料按需读取 | 单批目标 ≤4,000，读具体章节；留下版本、文件哈希、读取范围 |
| 专家间交接摘要 | 目标 ≤2,000 + 文件/版本/哈希索引；不带完整父会话 |

`W` 来自平台声明的实际有效模型窗口，不能为了放行把所有专家标成 1m。预算检查必须覆盖 agent prompt、policies、核心卡、辅助卡、pack 有效成员及实际阶段正文；不能只数 skills。

单次固定注入和整个模型会话是两个范围。外层已有历史、用户长文件和工具返回也会占窗口；平台派发器应使用任务所需的精简消息。若任务沿用已有长会话，报告必须说明外层历史未被该预算清除，不能声称整个窗口已受控。

超预算处置顺序固定：**选择相关卡/章节 → 拆工作阶段并以产物续接 → 仍有稳定的职责分界时拆专家**。不得静默截断关键内容，不靠调低档位取消功能，不把大池放进 pack 常驻。

### 2.3 机器执行

为新发布专家声明版本化的 `contextBudget`/预算政策引用；不改旧释放版。

- `repo-lint` 扩展 R17：以实际集合去重计数，补齐阶段正文、常驻核心与绝对上限检查；输出预算摘要。
- `wf-runner` 在生成交付提示前按同一规则检查和记录预算；超限发生在交付前，并明确告诉调用方需要换已声明场景、分阶段或拆专家。用户任务不能被静默裁切。
- `runtime-contracts` 只做可兼容增量：旧锁合法；新锁可读回预算版本、度量方法、计数范围和各项读数。不得把估算量写成真实模型计数。
- 能力与内容检查收敛进 `conform --only <agentId>`。现行 conform 的能力地板检查不足以证明内容完整性，本轮新增受选专家的内容/预算结果，仍输出统一 pass/fail digest。

## 6. 冻结完成判据

1. **职责**：28 个现行专家，每个有唯一主责、常见任务表、1 张核心 Skill 和 1 条主 workflow；所有场景包含本域核心，辅助选择有真实依据。
2. **内容**：任务表至少六类常见任务，至少五类有完整技能/依赖/交付路径；未覆盖类明确列出。该比例是本轮任务表的结构覆盖，不是未知任务的成功率。
3. **可用性**：每专家执行两种不同正常样例和一个有意义的边界样例，检验真实交付物/拒绝路径。只在指定小输入与本平台证据上得出结论，未执行不得记 PASS。需要真实外部账号的任务不靠模拟冒充连接成功；改为验证本轮承诺的本地实现/接口契约，外部采纳单列。
4. **预算**：每个默认/显式场景符合 §2，上游深度引用可回读，边界案例证明大 payload 不被静默截断。新旧任务档位规则照旧；样例默认草稿，只做点名范围，不对业务结果宣称冻结。
5. **发布**：新目录双向 SHA256SUMS、依赖锁可读回；引用的原释放版沿用本次审查和增量 attestation，不重复全历史认证。旧锁仍解析，不关闭兼容入口。
6. **本平台接线**：Codex 的新引擎/契约/scannerRelease 配对通过，受影响单格无 FAIL、预算结果可从 claim/锁读回；不声称其他平台已具备能力，不借本轮重新认证旧平台全矩阵。
7. **入库**：先有可回滚 commit 再翻指针/生产配置；推送前按既有红线扫描；最终带 HEAD、白名单内 status、远端一致、入库早于破坏四项读数。既有其他会话脏项不能混入本轮提交；无法满足全局白名单为空时必须登记并解决归属/协调，不能谎报收口。

判据在本方案批准时冻结。业务样例分散到对应 P 的子块中完成；P13 只回读汇总，不重复全量运行。执行期非阻断新问题只登记，收口后另案处理。
