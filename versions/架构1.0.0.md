## 2. 框架不变量（本版未触动，任何升级也不得触动）

1. 目录同构：`tool/<id>/{registry.json 条目, current.json, versions/<semver>}`，`agent/<id>/` 同构。
2. 发布即冻结：已发布版本只读，不可覆盖、不可就地修改；新版本必须新建目录，并通过 `current.json` 切换。
3. 完整性：每个发布版本带逐文件 `SHA256SUMS`；引擎在解析与提交时复核。
4. 切换语义：改变默认只改 `current.json`（平台配置另属平台自决）。
5. 锁语义：专家内部调用服从其 `tool-lock.json` 的**精确版本**；锁与共享默认允许不一致（滞后），但需可解释。
6. 平台隔离：一个平台不得修改另一个平台的配置、状态或工作区；运行产物不跨平台。
7. 运行契约：`ai-run-protocol/v1.1`（prepare → next → submit/stop）、运行锁 `ai-run-lock/v1.1`、门禁证据 `ai-gate-evidence/v1` 的字段与状态机不变。

## 4. 平台接入最小接口

**原则：共享侧只定义接口与校验，不假定平台的实现方式；平台能力必须由平台自己声明。** 详见 `invocation-adapters-spec.md` §9。

平台需实现并声明：

| 类别 | 项 | 说明 |
|---|---|---|
| 配置 | `platform` / `platformRoot` / `toolRoot` / `agentRoot` / `runsRoot` | 指向本平台目录；共享仓库只读 |
| 引擎选版 | `runner` | 平台显式选定引擎版本（可与共享指针不同） |
| 契约钉版 | `contracts` | 平台钉定的契约包版本；解析时按此记录契约键 |
| 能力声明 | `capabilities.checks` | 全部为真才允许运行 |
| **profile 声明** | `capabilities.profiles` | 形如 `{"renderer": {"adapters": [...], "requires": ["matplotlib"]}}`；未声明即拒绝该 profile |
| **权限适配器声明** | `capabilities.permissionAdapters` | 逐条列出**已验证的权限策略三元组**；引擎要求精确相等，不放宽、不做子集匹配 |
| 脚本环境 | `scriptEnvironment` / `environmentManifest` | 脚本阶段的隔离根与其逐文件清单 |

引擎侧不再包含任何平台专有常量或具体 release 特例——这是要求 2 的实现基线。

## 5. 调用与格式一致性

- 语法：`/wf <workflow-id> [任务描述]`、`/wfa <agent-id> [任务描述]`。专家的主工作流由该专家 `tool-lock` 决定，**调用方不得指定**。
- 可调用判据（判定即验收）：`prepare(mode, version=current)` 成功 → `next` 返回含 `stageId`/`attempt`/`action`/`inputSha256`/`artifacts`/`allowedTools` 的合法 task → `stop` 成功。见规范 §8。
- 机械执行：`ops/invocation_matrix.py` 逐条资源跑 `prepare → next → stop` 产出矩阵 JSON；**任何迁移/升级/发布批次前必须重跑，出现非预期 FAIL 即阻断**。
- 格式一致性由同一套契约保证：工作流定义 `ai-workflow-definition/v2` + manifest `ai-workflow/v2.1`（专家为 `ai-agent/v2`），产物形状由各阶段 `outputs` schema 与门禁共同约束。

## 7. 一句话切默认（要求 3 的机制）

```
ops/switch_defaults.py plan  --spec <spec.json> --out <checkpoint.json>   # 备份 + 校验（指针==from、目标已发布、清单干净）
ops/switch_defaults.py apply --spec … --checkpoint … --write             # 原子替换 + readback 断言
ops/switch_defaults.py verify --spec …                                   # 逐条复核指针与目标哈希
ops/switch_defaults.py revert --checkpoint … --write                     # 逐字节还原（回滚演练已通过）
```

- 一个 spec 覆盖多资源；**切换只改 `current.json`** 与 `registry.json` 的版本字段，不动任何发布版本。
- 实测记录：S1 33 条、S2 平台钉版、S3-5 引擎选版、上架 6 条、补批 3 条、数模成对 2 条 = **11 次切换 / 9 处注册表字段**；S1 另做过一次 byte-exact 回滚演练（35 文件逐字节一致）。
- 跨资源依赖遵循精确闭包：**工作流的 `requires` 与其专家锁必须一致**，否则报 `version-conflict`/`closure-not-authorized`；跨资源滞后必须成对发版并同批切换（数模 1.7.2 + 1.9.0 即是先例）。

## 8. 隔离与并发（要求 4）

**唯一权威表述见 `invocation-adapters-spec.md` §10**（各平台章只写一行指引，不得各自发明）。要点：

| 场景 | 能否并行 |
|---|---|
| 不同 run 之间（同工作流或不同工作流） | **可以**（每 run 独占目录与独占锁） |
| 同一 run 并发写 | **不可以**（写租约冲突即拒绝） |
| 单 run 内多阶段 | **不可以**（契约硬性：`maxParallel` 恒为 1，单 `activeAttempt`） |
| 父运行与子运行（委派） | 父**等待**子 |
| 同平台共享脚本环境内的脚本阶段 | **建议串行**（有脚本环境的平台各自声明；zcode 2026-09-17 起无脚本环境） |
| 同一用户项目目录上的两次数学 run | **不可以**（项目目录由 INIT 创建并被写） |
| tool 与 tool、agent 与 agent 之间 | **互不影响**（共享仓库只读 + 逐版本哈希；产物各自落本平台运行根） |

实测口径（历史报告曾在 `zcode\runtime\concurrency\20260915-035858\`；该完整 runtime 证据已随 2026-09-17 zcode 重建删除，摘要副本见 `codex/workspaces/github-export-architecture-evidence-1.0.0/`）：**C1 同工作流并发 / C2 不同工作流并发 / C3 同 run 并发 claim 拒绝 / C4 在飞 run 自行钉版（默认切换不可达）—— 4/4 通过**；**C5 同项目目录串行—— NOT_RUN**。zcode 重建后已无脚本沙箱，不得再写“C5 现已具备补测条件”。在补测前不得宣称 C5 已验证。

独立性另一项可测口径：**全系统锁滞后 = 0**（每个专家的锁都与其主工作流/能力包的共享默认一致，改动互不牵连）。
