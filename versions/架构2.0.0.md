## 1. 范围与分层：2.0 相对 1.0 改了什么

1.0.0 把"平台按声明式接口被调用"立为判据（`prepare→next→stop` 可调用、FAIL 0）。2.0 在这一判据之上补四件事：

| 面 | 1.0.0 | 2.0.0 |
|---|---|---|
| 契约 | 契约与扫描器同体（`contracts` 指 `repo-lint` 发布目录，引擎经 `repo_lint.Scanner` 做完整性） | **独立契约包** `runtime-contracts`（自带 `SHA256SUMS` 自校验）；`contracts` 与 `scannerRelease` 分离，旧布局保持可读（双布局） |
| 执行环境 | 平台各自特例、隔离靠平台自律 | **平台声明式后端** `executionBackend`（`wf-runner-execution-backend/v1`）；无后端 → 脚本派发**失败关闭**，不再靠引擎内资源级特例 |
| 能力预检 | 布尔 `checks`，缺口在 prepare 才炸 | **`ai-platform-descriptor/v2` 分面描述符**（prompt / script / peer 各自 `supported + enforcement`，分面**不可相加**）；`plan_capability_gap`(CAP-01) 按分面预检 |
| 写回与并发 | 项目写回无锁 | **`projectWriteRoots` + 归一化项目互斥**（C5/ADR-4）；同项目争用即拒 |
| 委派 | 引擎无 `delegate` 实现 | **父子委派闭环**：`peerDispatcherModule` / `peerContentRoot`，父 agent 的 `peerLock` 精确钉版，子 run 真实存在并留血缘。**形态分两段**：0.7.6 只到"平台驱动脚本 import 引擎、进程内调 `dispatch_delegation`"（qoder/zcode 两侧证据当时均如实标为受限面，wire 上的 `delegate` op 只会得到拒绝）；**协议内可触发的 `delegate` 由 0.7.7 补上**（见 §8 缺陷表与 §9 版本表） |
| 版本解析 | prepare 要求精确 semver，平台默认只在显式 `choose(...,None)` 路径生效 | **`target.version` 可省略或传 `current`**，按「显式 > 本平台覆盖 > 共享 current」解析并**把结果钉进 run-lock**（解析一次即冻结） |

## 2. 框架不变量（2.0 未触动，且不得被 2.0 的升级触动）

> **（2026-09-18 追加，上位关系）** 本节全部不变量从属于 `versions/架构基本原则.md` 的 **BP-1 ~ BP-5**（三仓骨架不可变 / 平台对等与能力地板 / 验收与接入最小量 / 跨平台同一项目语义 / 分步实施与完成判定）。BP 规定目标，本节规定实现时不得越界的边界；二者冲突以 BP 为准并回改本文。下列不变量**没有一条被 BP 放松**，被重新划界的只有不变量 3 的适用范围（见该条括注）。

1. **不可变发布**：已发布版本目录只读，禁止修改/覆盖/重命名/复用；换版必须新建语义化目录并切 `current.json`。
2. **运行必钉版**：任何 run 固定 agent/工作流/技能/能力包版本，并写入所属平台 `runtime/runs/<run-id>/run-lock.json`；**平台默认覆盖不得改变共享 current**，也不得绕过专家 `tool-lock`。（BP-4 ② 把这条延伸到跨平台：续跑时目标平台所钉版本必须与锁内版本一致，不得静默换版——本文 §8 缺陷③ 正是对该要求的违反，属缺陷而非可接受行为。）
3. **产物归平台**：配置、凭据、缓存、日志、运行输出只写所属平台目录；平台间不改对方配置/状态/工作区。**（BP-4 划界）** 本条的适用对象是**运行私有产物**；被声明为**项目状态**的内容（项目可写状态、跨 run/跨平台版本锁、续跑所需的阶段结论与产物摘要、exclusive 资源锁表）写**平台中立项目层**，平台只经交接/仲裁接口访问，且任何平台仍不得直读别平台 `runtime/`。
4. **声明式接口**：平台缺能力时按声明被拒（机器可读错误码），而不是被误认为支持；负面能力登记为 `declaredAbsent`，`checks` 内绝不放 `false`。（BP-2 追加口径：`declaredAbsent` 是**待补项**而非永久分层，接入完成的判据是对其覆盖到 0。）
5. **未验证不得写成已具备**；**未定稿不得写成已冻结**；纯文档维护不虚构业务运行（`agent/workflow = null`）。
6. **数模档位**：未写档位=草稿；「过图」才跑非严格 QA；「交稿」才走九阶段并冻结；禁止用 runner INIT 清空已有项目。（BP-2 追加：档位只管开销，**永不**改变"某功能能不能用"；不得用降档来掩盖能力面缺口。）
7. （2.0 新增）**分面不可相加**：`prompt: advisory` 不可读作 `script: advisory`，`script: kernel` 也不代表全平台内核强制。
8. （2.0 新增）**失败关闭优先于勉强可用**：缺后端、缺契约依赖、能力位与实现不一致时，宁可拒绝整次调用，不得静默降级或误跑。（BP-2/BP-3 划界：失败关闭针对**语义不一致**；针对"平台还没做那项能力"则须走降级阶梯与待补台账，不得当作终局不支持。）

## 5. 契约、描述符与权限口径

- **独立契约包**：`runtime-contracts@1.1.0`（〔09-18 定稿时 `current.json` 仍 1.0.0，选版与指针是两套机制〕**09-19 共享 current 已切 1.1.0**，见清单 §8.9）。自包含、自带 `SHA256SUMS` 自校验；三格篡改负例（增文件 / 改字节 / 目录名不符）在 qoder 面全部捕获。
- **协议**：`ai-run-protocol/v1.1`（五核心操作）与 **`v1.2`（`delegate` 的唯一载体）**；`stop` 必带 `payload.reason`；`status` 不带幂等键与修订号。
- **能力文档**：`ai-platform-capabilities/v1` + 嵌套 `ai-platform-descriptor/v2`。**权限有三处、语义不同，不可混用**：
  1. `permissionAdapters[]` —— 声明式三元组，**逐字相等**才匹配（`project-scoped/deny/allowlisted-only` 与 `shared-read-only-platform-report-write/deny/none`）；
  2. `descriptor.actions.*.enforcement` —— 分面强度（`advisory` / `kernel` / `mediated`）；
  3. 顶层 `permissions` —— **闭合词表且只在委派路径被校验**（`network∈{deny,egress-allowlist}`、`process∈{isolated-python,allowlisted-only}`、`filesystem∈{project-scoped,platform-runtime-write-shared-read-only}`）。它是单一全局三元组、**结构上无法表达分面**，因此**基线口径：平台不填该字段**（缺省 unspecified），分面只走前两处。此规约来自 §8 发现④ 的实测代价。
- **密封预算**：环境清单每次脚本派发前**全量重算**哈希 ⇒ 密封环境大小目前受**成本**约束（不是接口上限）。〔09-18 原文写作"超时 120 s 写死、超时被报成 `HASH_MISMATCH`"，两处均已更正〕超时预算是**平台自声明**的 `verifyTimeoutSeconds`（引擎按 1..3600 校验取值，120 只是缺省），且 0.7.7 起超时与篡改已分成 `ENVIRONMENT_VERIFY_TIMEOUT` 与 `HASH_MISMATCH`；见 §8 缺陷⑥ 与 §7 数模求解器链那行的成本判定。实测数据点：qoder 2401 文件 / 26.3 s（灭失前）与重建后 2545 文件 / 暖 22.6–27.9 s、冷 72.7 s（`2.0-G/baseline/G2-render-stack.json`）；7108 文件 / 157 s 那条是**旧自设预算**下的超时，不是引擎上限。真缺口仍是**全量→增量哈希**（2.1 §9 P4）。

## 6. 平台接入最小接口的 2.0 增量

规范 §9 的八项接口仍是接入判据（`ops/invocation_matrix.py` 的 FAIL 0）。2.0 在此之上要求平台**额外**如实声明四件事：后端（或不声明并让脚本面失败关闭）、契约布局与 `scannerRelease`、写回根、委派器（或不申报 peer）。缺任何一项**不构成接入失败**，只要它被登记为 `declaredAbsent` 而非谎报为具备——这正是 `dsh` / `codex` 等未接平台的正确状态。

## 8. 已知缺陷（共享侧；状态按 wf-runner 0.7.7 之后）

0.7.7（2026-09-18 发布、qoder 同日生产接入）关闭了 ①③④ 与 ⑥ 的语义部分；**契约包零改动**（两个新错误码本就在 v2 信封的枚举里）。证据：`qoder/runtime/maintenance/2.0-D/baseline/W-framework-published-077.json`（38 项全绿，树摘要 `a5f6ea1b…`）、`tool/wf-runner/versions/0.7.7/SOURCE.json`。

| 编号 | 事实 | 影响 | 状态（0.7.7） |
