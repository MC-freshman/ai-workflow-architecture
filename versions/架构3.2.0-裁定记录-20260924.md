## 1. 引擎代际

3.1.0 文档中的 0.10.0 / 1.4.0 / 0.5.1 是 09-23 方案定稿时的一代字节；09-23 晚间修复轮已经发布并抬高共享 current：

    wf-runner          0.10.1
    runtime-contracts  1.4.1
    repo-lint          0.5.2

3.1.0 中“禁止 0.10.1”的语句属于当时的发布边界，不能继续约束已经完成的 current 切换。3.2.0 §0 要求重新读取三仓 current，因此 3.2.0 选择的基线是当前配对代，而不是 3.1.0 的历史候选代。

选择选项②的原因：

- runtime-contracts 1.4.1 修复旧 v1.1/v1.2 锁在 scenario 字段上的兼容问题；3.2.0 会产真锁并回放既有锁。
- wf-runner 0.10.1 修复 process gate 的 at-most-once；3.2.0 的 P4 会真实跑阶段门禁。
- repo-lint 0.5.2 把 --select 的同机成本从 158.6 秒降到 30.1 秒；3.2.0 P8 的验收使用单格 conform。
- 混用三件中的任意一件会触发 VERSION_CONFLICT，不作为 3.2.0 方案选项。

这项裁定批准“3.2.0 必须以 current 配对代为基线”，不等于 Codex 直接修改 Qoder 配置。Qoder 需要在自己的维护目录保存切代前 checkpoint，成套切换、验证和回滚；切换后由 Qoder 自己重出受影响证据。P2 的进入条件是 Qoder 读回三件均已采用且版本一致。

## 2. R2-F4 与 dirsearch 解释器

### 措辞修正

R2-F4 不再声称“3.2.0 规定 dirsearch 必须使用某个解释器”。3.2.0 方案原文只规定连接器使用 Python 3.9-compatible 运行时；P4 的“绑定平台本体与解释器”是待执行工作，解释器选择由软件配方和冻结能力证据决定。

### 实测与选择

dirsearch 1.0.1 的冻结快照记录：

    interpreter = PPython
    pythonVersion = 3.12.4
    dirsearch --version -> exit 0, dirsearch v0.4.3

Qoder config 的 Python 3.9 是脚本阶段/连接器可用的解释器，不是对所有 Python 软件本体的强制绑定。3.9.13 缺少 dirsearch 启动期依赖，PPython 3.12.4 与冻结快照一致，因此 P4 选择按软件解析解释器别名 PPython。实际绝对路径只写 Qoder 平台配置和运行证据，不写进共享 manifest。

不发布 dirsearch 1.0.2；本项属于 P4 适配器的正常职责，不增加共享仓范围。

## 3. MySQL 凭据与服务端

### 凭据落点

选择 Windows 凭据管理器。共享调用只使用逻辑引用，例如：

    {"credentialReferences": ["reference:mysql-local"]}

真实用户名、密码和凭据管理器目标只存在于 Qoder 平台。inbox/backup/qoder/ 只登记目标名、创建/恢复命令和“秘密未导出”状态，不保存秘密副本。其他平台使用各自的原生密钥环，但继续接受同一个 reference:<name> 语义。

### 字段统一

发布 mysql-cli 1.0.2，将 credentialReferences 定为连接器和 input schema 的唯一规范入口。passwordRef 属于旧配方字段，保留在 1.0.1 的历史字节中；3.2.0 新调用不再产生第二个长期字段。连接器不把凭据值写入 request、run-lock、event、response 或 evidence。

### 服务端组合

P4 首轮使用现有 phpStudy MySQL 5.7.26，客户端使用冻结快照中的 mysql-cli 8.0.39。基础查询成功证据必须明确写出：

    serverVersion = 5.7.26
    clientVersion = 8.0.39
    compatibilityScope = basic-query-only

首轮只覆盖连接、SELECT 1、字符集和 information_schema 读取；不把这个组合推广成所有 MySQL 版本的兼容性结论。服务启动/停止命令留在 Qoder 平台 runtime，不写入共享配方。若后续需要声明版本纯净的覆盖面，再单独增加匹配版本服务和 P 表。

## 4. 对 P 表的影响

本裁定只改变 P2/P4 的明确输入，不新增全矩阵：

- P2：加入 credentialReferences 规范、mysql-cli 1.0.2 候选 schema、软件解释器解析字段和 current 代检查。
- P3：连接器自身仍以 Python 3.9-compatible 构建；软件本体解释器按 recipe/snapshot 解析。
- P4：dirsearch 以 PPython 3.12.4 实测；mysql-cli 以 5.7.26/8.0.39 混合组合完成基础查询，并登记限制。
- P8：只做第一批软件的单格 conform --only；不因 MySQL 版本限制扩展全矩阵。

Qoder 完成 current 成套采纳和自己的 P1-readback 后，才可以进入 P2。P2 之前不得派发软件、启动 MySQL 服务或写凭据。
