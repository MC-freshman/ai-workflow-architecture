## 1. 三分类处置原则

- **A 直接删（可重建 / 别处已有副本，无复原价值）**：`.pyc` 与 `__pycache__`、`node_modules`、`architecture-manager/release` 与 `seed`、各类 pip/node 缓存、`*.lock` 空文件、`inbox/backup` 中的 venv 完整副本（BP-7 只要求留「重建配方 + 一条重建命令」，不是留字节）。
- **B 先压后删（有复原价值、别处无副本）**：已完结 run 目录、已完结 workspaces 项目、`*.jsonl` 会话日志、归属存疑目录。
- **C 不合并**：`tool`（23,614 文件）、`tool/skills`（11,011 文件 / 仅 27MB）、`versions/`、三仓资源——**逐资源独立版本 + 逐文件 sha256 + 内容哈希增量**（BP-3）正是靠"碎"才成立；合并会使增量失效、哈希粒度变粗。合并收益 27MB，代价是治理机制失效 ⇒ **明确不合**。

## 2. 关于 sha256 的修正（采纳用户意见）

打包后**只记录压缩包自身的一个 sha256**，不生成逐文件清单——压缩包本身就是复原来源，逐文件清单既冗余又会拖慢流程。
仅当对象属「不可重建且无别处副本」时，才额外保留逐文件清单（本轮无此类对象）。

## 3. 删除执行约束（针对本轮事故）

1. **先压后删**（B 类）：打成一个 zst/7z 包 → 记包 sha256 → 删目录。删除对象从 N 万文件变为 1 个文件。
2. **目录级删除**，不逐文件；单命令不超过 4 个目录（实测多次目录会被中断）。
3. 含 WSL（LX）符号链接的目录：Windows 侧全拒，Git Bash `rm -rf` 可清内容仅剩链接壳 ⇒ 残留在册（D-176）。
4. **Windows 搜索索引排除** `E:\ai\*\runtime` 与 `node_modules`（本轮卡死真因是索引器实时处理十万级删除通知）。
5. 不使用回收站（直接删）。

## 4. P 表

**P1 只读盘点与白名单（~1h）**
- 1a 按 A/B/C 分类产出待处理清单（路径 + 文件数 + 体积 + 处置类别）；在途 run 与活跃 workspaces 项目一律排除；
- 1b 确认 B 类对象无别处副本（GitHub release / inbox/archive / 共享仓）。
- 判据：清单落盘可回读；A/B 边界无争议项。停手点：零写入。

**P2 B 类归档打包（~2h）**
- 2a 逐对象打 zst/7z 单包 → `inbox/archive/<platform>/<日期>/`（或用户指定共享路径）；
- 2b 记每包 sha256（一行一值），写入同名 `.sha256`；
- 2c 抽样解压验证可回读。
- 判据：包数 = B 类对象数；抽样解压后文件数与原目录一致；包 sha256 记录完整。
- 停手点：每对象打完即停。

**P3 A 类直接删（~2h，破坏性，P1/P2 已完成）**
- 3a `__pycache__` 目录（13.3 万文件 / 2.5GB）优先，目录级分批；
- 3b `node_modules`（dsh 2,020 处等）、release/seed、缓存、`*.lock`、备份区 venv 副本。
- 判据：复测文件数与体积；`pyvenv.cfg` 与活跃环境零触碰；残留（EBUSY/LX 链接）逐条登记不清强删。
- 停手点：每批一停。

**P4 与防复发 P 表合并执行**
- 4a 防复发 P1（备份 5 台待重铺文件）+ P2（新增 `scripts/check-runtime-drift.mjs` 并以 warn 挂入 `conform.mjs`）；
- 4b 本表 P3 的删除不触碰 `bridge/` 下任何铺设文件（防复发 P3 重铺才动）。
- 判据：conform 仍 ok（warn 不阻断）；注入坏哈希能抓 FAIL。

**P5 收口（~1h）**
- 5a 更新日志 / 退役配方补记本轮减量与残留清单；
- 5b 四项读数：HEAD sha / 白名单内 `git status` 空 / 远端一致 / **入库早于删除**（本轮 P1 与本文档先入库，满足）。
- 判据：四读数齐全；总减量 ≥ 预估 80%。

## 5. 风险登记

1. EBUSY：release 目录受 WorkBuddy 宿主句柄锁，需重启后清（已知，不强删）。
2. 打包需同盘临时空间与时间，B 类合计约 6.7GB，压缩后预计 <2GB。
3. 会话内 spawnSync 对 `.exe` 存在 EBUSY ⇒ 打包/删除优先用 node/Git Bash 命令。
4. 删除仍会触发索引器：执行前先完成 §3.4 的索引排除，或分批执行。
5. 治理文本改后必跑 `git diff --numstat` 验 EOL 膨胀。

## 6. 完成判定

P1–P5 按上列判据跑完即＝本轮完成；同一轮内不追加验收项。
