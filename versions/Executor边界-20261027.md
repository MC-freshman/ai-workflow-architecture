# Executor 边界（2026-10-27）

本文件是《AgenticWorkflow共享执行器落地-P表-20261027.md》P1-③ 的产物：把「谁执行什么」的边界从代码事实上升为治理文本。依据全部来自对 `tool/wf-runner/versions/0.13.1` 的只读源码核对（`engine.py` / `cli.py` / `sandbox.py` / `sandbox_host.py`），读数快照见 `workbuddy/runtime/maintenance/20261027-executor-adoption/p1-snapshot.json`。

## 1. 执行权划分

| 动作类型 | 执行者 | 依据（源码事实） |
| --- | --- | --- |
| `stage.action = "script"` | **runner 真执行** | `engine._execute_claimed` 取 `stage['script']`（attempt>1 取 `repairScript`）→ `sandbox.start_script` → `subprocess.Popen`（异步，非 spawnSync）→ `wait_script` 收割 |
| `stage.action = "software"`（else 分支） | **runner 真执行** | `self._execute_software(...)`，走软件网关契约 |
| `gateDefinitions.type = "process"` | **runner 真执行** | `gate_exec`，带 `argv` / `expectExit` / `expectArtifacts` / `reasonFrom` |
| `stage.action = "prompt"` | **host（客户端会话）执行** | `engine.next()` 只交付 `task.prompt`（promptRef 渲染 + 上下文文档拼接）并把状态置 `waiting-for-input`，随后由 host 会话完成推理并 `submit` 产物 |

**编排层全部机读**（`ai-workflow-definition/v3`）：`stages` / `dependsOn` / `requiredStages` / `scenarios` / `gates` / `maxIterations` / `onFail: repair` / `outputs` schema。

## 2. 为什么 prompt stage 归 host 是设计边界而非欠账

把 prompt stage 的推理循环也纳入 runner，要求把模型访问（API 凭据、会话状态、token 消耗）放进共享仓的运行态，这直接违背：

- **BP-1 §1.6**：仓内只放可冻结、可跨平台共享的文本；本体、凭据、运行产物不入仓；
- **BP-2**：共享代码/契约/配方中禁止平台专有常量与发行版特例——各平台模型绑定不同，模型访问不可能写成平台无关。

因此：**「agentic workflow 是 prompt-mode」这一表述只对 stage 内循环成立，且该循环永远归 host**。runner 的职责边界是：算对下一步（机读 DAG）、交付任务、收产物、过门禁、记证据。

## 3. script stage 的硬边界（0.13.1 实测代码事实）

1. **入口仅限 `.py`**：`entry.endswith('.py')` 否则 `UNAUTHORIZED`（「Only locked Python entries and structured argv are supported」）；argv 必须是纯字符串列表。
2. **attempt 隔离**：每次派发在 `attempt_root` 下新建 `jail/ scratch/ stdout.log/ stderr.log/ result.json/ process.json/ cancel.flag/ authorize.flag`，`mkdir(exist_ok=False)`。
3. **gated 授权门**：`gated=True` 时写 `authorize.flag`，脚本须持授权才放行。
4. **timeout**：`timeoutSeconds` 默认 30。
5. **不可重放**：对已派发脚本的再次执行被 `UNKNOWN_OUTCOME`（「A dispatched script is never replayed」）拒绝；幂等由 attempt 流与事件前缀保障。
6. **backend 二族**：`kind=host` → `sandbox_host.py`（Windows 密封环境）；否则 `sandbox_linux.py`（Landlock 沙箱）。本机现状：workbuddy/dsh/zcode/doubao 声明 `manager-sealed.json`（host 族），codex/qoder 声明 `wsl2-ubuntu.json`（linux 族）。
7. **纯配置驱动**：执行路径只读平台 config 的 `scriptEnvironmentRungs` / `executionBackend` / `scriptEnvironment`，**无平台专有代码分支**。

## 4. 降级契约（`CAPABILITY_UNAVAILABLE` 触发点，D-27 语义）

无密封环境或通路未装配时，**提示词面照常跑到 `succeeded`，脚本面结构化拒绝、不留半截产物**。已核对到的触发点：

1. `No locked script entry for this prompt`（阶段没有可执行脚本入口）；
2. 平台阶梯不含所需 `execPath`（「which the platform ladder does not currently offer」）；
3. `Script dispatch requires a declared execution backend`（backend 未声明/缺失）；
4. 密封环境根不存在（「The pinned script environment root does not exist」）；
5. `verify_script` 密封校验失败（sealed rung）。

## 5. 平台装配判据（三件齐才可用）

脚本执行通路可用 = ① config 声明 `scriptEnvironmentRungs`（含 `execPath` / `executionBackend`，sealed 档含 `scriptEnvironment`）+ ② backend 文件真实存在 + ③ sealed 目录真实存在并通过校验。缺任一件 ⇒ 脚本面降级（`CAPABILITY_UNAVAILABLE`），属**平台侧装配时间差**，按 BP-2 列待补台账，不得写成「本平台不支持」。

**P1 发现（登记，非阻断）**：`doubao` 声明了 `requiresSealedEnvironment: true` 但 rung **缺 `scriptEnvironment` 键**，且 `executionBackend` 所指 `doubao/bridge/backends/manager-sealed.json` **不存在**——三件中缺两件，预期全部脚本派发落入 `CAPABILITY_UNAVAILABLE`。此形态与 2026-09-16 doubao 升格时的接入范围一致（软件面已登记受限，见 D-124 相邻语境），本轮**只登记不修复**（修法属平台侧补装 backend+sealed，需另批），待 P4 降级用例真机复核其行为后归档。

## 6. 本边界的适用范围

- 适用于 `wf-runner 0.13.1` 及其声明的 `ai-workflow-definition/v3`；引擎大版本升级时须重核本文件第 3/4 节的代码事实。
- 本文件不构成对任何平台的业务运行认证；各平台脚本通路是否真实可用，以各自 runtime 证据为准，结论不互抄（BP-2）。
