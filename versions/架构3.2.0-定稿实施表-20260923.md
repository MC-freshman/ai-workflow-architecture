## 0. 进入条件

1. 读取 `versions/架构基本原则.md`、`versions/架构3.0.0.md`、`versions/架构3.1.0.md`。
2. Codex 先生成 handoff-bundle/v1，Qoder 只读校验通过后才进入 P2。
3. Qoder 必须先成套采纳当前 wf-runner 0.10.1、runtime-contracts 1.4.1、repo-lint 0.5.2，保存 checkpoint 并由 Qoder 自己重出受影响证据；不得以 3.1.0 的历史候选代进入 P2。
4. 目标版本必须重新读取三仓 current.json；不得把 Codex 当前锁直接当成 Qoder 的生产锁。
5. 本表不授权删除或覆盖已发布版本，不授权把软件本体写入共享仓，不授权跨平台直接读取 runtime。

## 1. P 步表

|---|---:|---|---|---|---|

## 2. 每个 P 的工具和实现口径

| 面 | 采用什么 | 怎么做 | 关键点 |
|---|---|---|---|
| 连接器运行时 | 现有 `_gateway` 契约 + 新版 `software/_connector`；Python 3.9 | 复用已验证的 JSON 单行请求/响应、锁和证据布局；MCP-stdio/HTTP 只作为传输层 | 传输层不能改变 `software-call/v1` 语义 |
| 软件本体解释器 | recipe/snapshot 中的逻辑解释器别名 | 连接器解析软件自己的 interpreter；dirsearch 绑定 PPython 3.12.4；绝对路径留在 Qoder config/runtime | 连接器 Python 3.9 与软件本体解释器是两个字段 |
| CLI 调用 | `generic-cli` adapter | recipe 给出逻辑入口、参数模板、工作目录和输出 schema；平台 config 解析真实本体 | 不把平台绝对路径写入共享 manifest |
| 原生 MCP | `mcp-proxy` adapter | 连接原生 MCP stdio/HTTP，保留 tools/list 和结构化结果 | 不为没有该能力的软件伪造 `--tools` |
| GUI/长会话 | `desktop-session` adapter | open/status/close，必要时返回人工交互状态 | 不把人工 GUI 操作伪装成自动化成功 |
| 版本和能力 | `current.json` + manifest/SHA256SUMS + frozen snapshot | health 阶段固定释放版和快照，run-lock 记录摘要 | snapshot 未冻结时 `CAPABILITY_UNAVAILABLE` |
| 权限 | profile + 一次性 consent | 调用前检查文件根、网络、端口、凭据和提权授权 | 不能用永久管理员授权替代逐次授权 |
| MySQL 凭据 | Windows 凭据管理器 + credentialReferences | 连接请求只带 reference:mysql-local；凭据值不进 request、run-lock、event、response 或 evidence | 3.2.0 使用 mysql-cli 1.0.2 的规范字段 |
| 交接 | `handoff-bundle/v1` | Codex 生成，Qoder 校验；只通过共享交接包传递项目状态 | 禁止直读另一平台 runtime |
| 验收 | `conform --only <softwareId>` | 单软件变更只做索引增量和单格冒烟；大版本才跑全矩阵 | 空行集不得亮绿；各平台各自出证 |

## 3. 各软件的 MCP 编写规则

| 软件 | 首选实现 | 是否单独写 MCP 服务 |
|---|---|---|
| `dirsearch` | 通用 CLI adapter | 否，只写 manifest/参数映射 |
| `mysql-cli` | 通用 CLI adapter，默认只允许授权连接 | 否，只写连接参数 schema 和权限 profile |
| `wireshark-cli` | 通用 CLI adapter | 否，只写 capture/input/output 映射 |
| `nmap` | 通用 CLI adapter + 外部网络 consent | 否，复用连接器 |
| `burp-suite` | MCP-HTTP（有端点时）或 desktop-session | 通常否；只有其端点协议独立时写薄 proxy |
| `veracrypt` | desktop-session | 否，复用会话适配器；挂载操作需要逐次授权 |

结论：**一个共享连接器，六份软件声明，少量特殊 adapter；不是六个独立 MCP 服务。**

## 4. 预先登记的缺陷处理

执行期若出现以下非阻断问题，只登记到 `3.2-LEDGER.md`，不在本轮顺手扩展：

- 某软件没有可稳定解析的原生 MCP 端点；
- GUI 软件需要平台专有的窗口控制能力；
- 某平台没有可密封的运行环境；
- 某软件快照或安装本体无法在本次窗口冻结；
- 旧配方字段需要兼容性迁移。

维护方案必须另立 P 表；本表完成判定不因维护项追加门槛。

## 5. 收口报告固定内容

收口报告至少包含：

1. P1–P8 每步的产物路径和判定；
2. Qoder 自己的 connector/软件版本、配置哈希和 `conform` digest；
3. 第一批软件的成功、拒绝、幂等和证据读数；
4. 用户直用命令或 GUI 入口验证；
5. `HEAD` SHA、白名单内 `git status`、远端与本地一致性、入库时间；
6. 未完成软件和平台的 `declaredAbsent`/`unverified` 清单与整数分钟补齐路径。

这张 P 表跑完，3.2.0 的“连接器与 Qoder 首批软件可用”范围才算完成；其他平台和特殊软件按各自 P7 证据逐步补齐。
